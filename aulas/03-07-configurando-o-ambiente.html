03–07 · Configurando o ambiente

JDK, variáveis de ambiente, compilação manual e IDE · playlist

Resumo Flashcards Quiz Material de estudo

Junta as aulas 03 (download da JDK 15), 04 (variáveis de ambiente), 05 (compilação manual), 06 e 07 (IntelliJ). Montado a partir dos temas, sem as transcrições. As aulas usam Windows e JDK 15; aqui os comandos são para Ubuntu/WSL e uma versão LTS atual.

Resumo

Antes de programar, você precisa de três coisas: a JDK instalada, o sistema sabendo onde ela está (variáveis de ambiente) e um lugar para escrever código (IDE). Compilar uma vez na mão, com javac e java, mostra o que a IDE faz por trás quando você aperta "Run".

03 · Instalando a JDK

  • Para programar, instale a JDK, não só o runtime.
  • Prefira uma versão LTS (Long-Term Support), como a 17 ou a 21, que recebem correções por anos. A JDK 15 do curso não é LTS; tudo o que o curso ensina funciona nas versões mais novas.
  • OpenJDK é a implementação aberta. Temurin (Adoptium), Oracle JDK, Amazon Corretto etc. são distribuições dela.
  • Para conferir a instalação: java -version e javac -version.

04 · Variáveis de ambiente

  • PATH: lista de pastas onde o sistema procura comandos. Se a pasta bin da JDK não está no PATH, o terminal responde "javac: command not found".
  • JAVA_HOME: aponta para a pasta raiz da JDK. Ferramentas como Maven, Gradle e IDEs usam essa variável.
  • No Windows, você configura em "Variáveis de ambiente" e reabre o terminal. No Linux, coloca no ~/.bashrc e roda source ~/.bashrc.
  • Instalando pelo apt, o PATH já fica certo. O JAVA_HOME você define na mão.

05 · Compilação manual

  • javac Arquivo.java gera Arquivo.class, e java Arquivo executa (sem extensão).
  • O nome da classe pública tem que ser igual ao nome do arquivo.
  • O ponto de entrada é o método public static void main(String[] args).
  • javac -d out separa os .class em outra pasta, e java -cp out diz onde procurá-los (classpath).

06–07 · IDE

  • O curso usa o IntelliJ IDEA Community, que é gratuito.
  • A IDE compila, executa, depura e completa código sozinha, mas por baixo roda o mesmo javac/java.
  • No IntelliJ: New Project, escolher a JDK (SDK), criar uma classe em src e rodar pelo ▶ ao lado do main.
  • Atalhos úteis: psvm + Tab cria o main, e sout + Tab cria o System.out.println().

Atenção

  • Classe Ola dentro de ola.java (com letra minúscula) dá erro. Java diferencia maiúsculas de minúsculas.
  • java Ola.class dá erro. O comando recebe o nome da classe, não do arquivo.
  • Mudou o PATH e o comando continua sem funcionar? Abra um terminal novo ou rode source ~/.bashrc.
  • O JAVA_HOME aponta para a raiz da JDK, sem o /bin. O PATH recebe o $JAVA_HOME/bin.
  • A JDK instalada no Windows não aparece no WSL, e vice-versa. São sistemas separados.

Paralelo com PHP

É como instalar o PHP CLI e garantir que php esteja no PATH. A diferença é o passo extra de compilar: no PHP você roda php script.php direto. No Java, compila com javac e depois executa. Desde o Java 11 também dá para rodar direto com java Script.java, mas só para programas de um arquivo.

Prática no seu WSL (10 minutos)

# 1. Instalar e conferir
sudo apt update
sudo apt install openjdk-21-jdk
java -version
javac -version

# 2. Descobrir a pasta da JDK e definir o JAVA_HOME
readlink -f $(which javac)      # ex.: /usr/lib/jvm/java-21-openjdk-amd64/bin/javac
echo 'export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64' >> ~/.bashrc
echo 'export PATH="$JAVA_HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
echo $JAVA_HOME
# 3. Compilar na mão, separando fonte e compilado
mkdir -p ~/java-lab/src ~/java-lab/out && cd ~/java-lab
cat > src/Ola.java <<'EOF'
public class Ola {
    public static void main(String[] args) {
        System.out.println("Olá do WSL!");
    }
}
EOF
javac -d out src/Ola.java    # o .class vai para out/
java -cp out Ola             # executa procurando em out/
java src/Ola.java            # atalho: compila e roda na memória

IDE no WSL: como você já usa VS Code com WSL, instalar a extensão Extension Pack for Java na janela conectada ao WSL resolve. Se preferir seguir o curso à risca, o IntelliJ no Windows também abre projetos que estão no WSL.

Glossário

  • LTS: versão com suporte estendido, a indicada para estudo e produção.
  • PATH: pastas onde o shell procura executáveis.
  • JAVA_HOME: caminho da raiz da JDK, lido por ferramentas.
  • Classpath (-cp): onde a JVM procura os .class.
  • IDE: ambiente integrado para editar, compilar, executar e depurar.
  • SDK: no IntelliJ, é a JDK escolhida para o projeto.
