Resumo

Até aqui, cada objeto tinha a sua própria cópia de cada atributo. Estas aulas mostram duas coisas novas. A primeira: onde colocar código de inicialização comum a todos os construtores (o bloco de inicialização). A segunda: como fazer algo pertencer à classe e não a cada objeto (o modificador static). Com isso, o public static void main(String[] args) finalmente faz sentido por inteiro.

60 · Bloco de inicialização de instância

public class Anime {
    private String nome;
    private int[] episodios;

    {   // bloco de inicialização: roda a CADA new, ANTES do construtor
        System.out.println("Dentro do bloco de inicialização");
        episodios = new int[100];
        for (int i = 0; i < episodios.length; i++) {
            episodios[i] = i + 1;          // episódios de 1 a 100
        }
    }

    public Anime() {
    }

    public Anime(String nome) {            // não precisa repetir o laço aqui
        this.nome = nome;
    }
}
  • O problema: preencher os 100 episódios (pense em One Piece) no construtor vazio funciona, mas o construtor Anime(String nome) deixava episodios como null. Seria preciso duplicar o código em todos os construtores.
  • A solução: um par de chaves solto na classe, { ... }, é o bloco de inicialização de instância. Ele roda toda vez que um objeto é criado, antes do construtor, não importa qual construtor foi chamado.
  • Pode ficar em qualquer lugar da classe, mas o costume é depois dos atributos e antes dos construtores.
  • No IntelliJ, Alt+Enter sobre um array oferece "iterate" e gera o foreach.
  • O William recomenda o bloco quando uma inicialização precisa valer para todos os construtores, ou quando ela pode lançar exceção (tema futuro).

A ordem de criação de um objeto (até aqui):

1. Aloca o espaço do objeto na memória
2. Cada atributo recebe o valor padrão (null, 0, false) ou o valor escrito na declaração
3. Executa o bloco de inicialização de instância
4. Executa o construtor

61 · Atributo static: pertence à classe

public class Carro {
    private String nome;
    private double velocidadeMaxima;
    public static double velocidadeLimite = 250;   // UMA cópia, da classe

    public Carro(String nome, double velocidadeMaxima) {
        this.nome = nome;
        this.velocidadeMaxima = velocidadeMaxima;
    }
}

Carro c1 = new Carro("BMW", 280);
Carro c2 = new Carro("Mercedes", 275);
Carro c3 = new Carro("Audi", 290);
Carro.velocidadeLimite = 180;   // vale para os TRÊS (e para os que forem criados depois)
  • O cenário: o "acordo de cavalheiros" das montadoras alemãs limita eletronicamente os carros a 250 km/h. Com velocidadeLimite como atributo comum, cada carro tem sua cópia, e c1.setVelocidadeLimite(180) muda só a BMW. O acordo quebra.
  • Com static, o atributo passa a pertencer à classe, como um metadado dela. Existe um valor só, compartilhado por todos os objetos. Mudar por um aparece em todos.
  • Acesse pelo nome da classe: Carro.velocidadeLimite. Por c1.velocidadeLimite ou this.velocidadeLimite até compila, mas engana quem lê, que pensa estar mexendo só num objeto. O IntelliJ avisa.
  • Não precisa de objeto nenhum: System.out.println(Carro.velocidadeLimite) funciona sem nenhum new Carro.
  • A ordem das palavras: public static. static public compila, mas a convenção é o modificador de acesso primeiro.

62 · Métodos static

private static double velocidadeLimite = 250;

public static void setVelocidadeLimite(double velocidadeLimite) {
    Carro.velocidadeLimite = velocidadeLimite;    // NÃO dá para usar this aqui
}

public static double getVelocidadeLimite() {
    return velocidadeLimite;
}

// CarroTeste01 — antes de criar qualquer carro
Carro.setVelocidadeLimite(180);
  • Com o atributo private, o acesso passa por getter e setter estáticos, chamados pelo nome da classe.
  • Dentro de um método static não existe this. O this é o objeto atual, e um método estático pode ser chamado sem nenhum objeto na memória. Para desempatar o parâmetro do atributo, use o nome da classe: Carro.velocidadeLimite = velocidadeLimite.
  • Métodos estáticos não acessam atributos de instância. Se imprime() fosse static, nome e velocidadeMaxima dariam erro (non-static field cannot be referenced from a static context). De qual carro seria o nome, se talvez nem exista carro?
  • O contrário pode: métodos de instância acessam os membros estáticos, porque a classe sempre existe antes do objeto.
  • Quando tornar um método static: quando ele não usa nenhum atributo de instância. Os métodos da Calculadora (aulas 44–47) poderiam ser todos estáticos.
  • Agora o main faz sentido: public static void main(String[] args) é público, estático (a JVM chama sem criar objeto), não retorna nada, se chama main e recebe um array de String. Por ser estático, um atributo não estático da classe de teste não pode ser usado dentro dele.

63 · Bloco de inicialização static

public class Anime {
    private String nome;
    private static int[] episodios;      // um array só para todos os animes

    static {    // roda UMA VEZ, quando a JVM carrega a classe
        System.out.println("Dentro do bloco de inicialização estático");
        episodios = new int[100];
        for (int i = 0; i < episodios.length; i++) {
            episodios[i] = i + 1;
        }
    }

    {           // de instância: roda a cada new
        System.out.println("Dentro do bloco de inicialização não estático");
    }
}

new Anime(); new Anime(); new Anime();
// estático: 1 vez · não estático: 3 vezes
  • Criar 3 animes rodava o bloco de instância 3 vezes, recriando o mesmo array de 100 episódios. É processamento desperdiçado, já que o valor é igual para todos.
  • Com o atributo static e a palavra static antes das chaves, o bloco roda uma única vez, quando a JVM carrega a classe, antes mesmo de existir qualquer objeto. Dentro dele, os atributos estáticos se acessam pelo nome da classe (Anime.episodios), sem this.
  • Vários blocos estáticos rodam na ordem em que aparecem, uma vez cada. Depois, a cada objeto, rodam os blocos de instância.
  • Como no método estático, o bloco estático não enxerga atributos de instância (nome).
  • Segundo o William, você vai usar pouco o bloco estático, mas muito os métodos estáticos.

A ordem completa:

0. Quando a classe é carregada (1 vez): atributos static + blocos static, na ordem do código
1. Aloca o espaço do objeto                       ┐
2. Atributos de instância: padrão / valor escrito  │ a cada new
3. Blocos de inicialização de instância            │
4. Construtor                                      ┘

Atenção

  • this em contexto estático não compila. Vale para métodos e blocos static, incluindo o main.
  • Atributo de instância em contexto estático não compila. Dentro do main, um int x declarado na classe (sem static) não pode ser usado.
  • Acessar static por uma referência compila e engana: c1.velocidadeLimite = 180 muda para todos os carros, não só para o c1.
  • Extra: o exemplo clássico de static é contar quantos objetos já foram criados: private static int total; e, no construtor, total++. Cada new incrementa o mesmo contador.
  • Extra: você já usa métodos estáticos. Math.max(a, b), Integer.parseInt("10") e Arrays.toString(arr) são todos chamados pelo nome da classe, sem new.
  • Extra: estado estático é estado global. Um static que muda de valor é compartilhado por todo o programa, inclusive entre requisições e threads num servidor. Prefira static para métodos utilitários e constantes (static final, aula 77), e evite para dados que mudam.
  • Extra: ordem entre atributo e bloco. Valores escritos na declaração e blocos de instância rodam na ordem em que aparecem no código, sempre antes do construtor.

Paralelo com PHP

  • A palavra é a mesma, mas a sintaxe de acesso muda: Carro::$velocidadeLimite e self::/static:: no PHP, contra Carro.velocidadeLimite em Java (sem $, com ponto).
  • $this também não existe em métodos estáticos do PHP. A regra é a mesma.
  • Blocos de inicialização não existem no PHP. Nem o de instância (no PHP tudo vai no __construct) nem o estático (você chamaria um init() estático manualmente).
  • A diferença que mais importa, o tempo de vida: no PHP-FPM, cada requisição começa do zero, e um static "morre" no fim dela. Numa aplicação Java (Spring, por exemplo), a JVM fica no ar por dias: um atributo static é compartilhado por todas as requisições de todos os usuários. Guardar dados de usuário num static em Java é bug grave. (O Laravel Octane se aproxima desse modelo, e lá o mesmo cuidado vale.)
  • Facades não são static de verdade: Cache::get() parece método estático, mas é um proxy (__callStatic) para um objeto do container. Em Java, Math.max() é estático de fato.

cd ~/java-lab
F=src/academy/devdojo/maratonajava/javacore/Fmodificadorestatico
mkdir -p $F/dominio $F/test

cat > $F/dominio/Carro.java <<'EOF'
package academy.devdojo.maratonajava.javacore.Fmodificadorestatico.dominio;

public class Carro {
    private String nome;
    private static double velocidadeLimite = 250;
    private static int total;

    static {
        System.out.println("static: classe Carro carregada");
    }

    {
        System.out.println("instância: bloco antes do construtor");
    }

    public Carro(String nome) {
        System.out.println("construtor: " + nome);
        this.nome = nome;
        total++;
    }

    public void imprime() {
        System.out.println(nome + " limite " + velocidadeLimite);
    }

    public static void setVelocidadeLimite(double velocidadeLimite) {
        Carro.velocidadeLimite = velocidadeLimite;
    }

    public static int getTotal() {
        return total;
    }
}
EOF

Glossário

  • Bloco de inicialização de instância: { ... } na classe. Roda a cada criação de objeto, antes do construtor.
  • Bloco de inicialização estático: static { ... }. Roda uma vez, quando a classe é carregada.
  • Atributo de instância: cada objeto tem o seu.
  • Atributo estático (de classe): um só, compartilhado por todos os objetos.
  • Método estático: chamado pela classe. Não tem this nem acessa atributos de instância.
  • Contexto estático: métodos e blocos static, onde não há objeto atual.
  • Carregamento de classe: momento em que a JVM lê a classe, na primeira vez que ela é usada, e executa a parte estática.
