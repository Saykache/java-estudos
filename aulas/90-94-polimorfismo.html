Resumo

Polimorfismo ("múltiplas formas"), para o William "um dos assuntos mais importantes da orientação a objetos", é poder usar uma variável de referência de um tipo mais genérico (superclasse ou interface) apontando para um objeto de um tipo mais específico (subclasse ou implementação). Só funciona dentro da mesma linha de herança. A variável decide quais métodos você pode chamar. O objeto decide qual versão é executada. Com isso, um método só atende qualquer produto, e trocar a implementação vira trocar só o new.

90 · Preparando o terreno

public interface Taxavel {
    public abstract double calcularImposto();
}

public abstract class Produto implements Taxavel {   // abstrata: não precisa implementar calcularImposto
    protected String nome;
    protected double valor;
    public Produto(String nome, double valor) { this.nome = nome; this.valor = valor; }
    public String getNome() { return nome; }
    public double getValor() { return valor; }
}

public class Computador extends Produto {
    public static final double IMPOSTO_POR_CENTO = 0.21;
    public Computador(String nome, double valor) { super(nome, valor); }
    @Override
    public double calcularImposto() {
        System.out.println("Calculando imposto do Computador");
        return this.valor * IMPOSTO_POR_CENTO;
    }
}
// Tomate: igual, com IMPOSTO_POR_CENTO = 0.06 e "Calculando imposto do tomate"

// servico/CalculadoraImposto: calcularImpostoComputador(Computador c) e calcularImpostoTomate(Tomate t)
// → dois métodos quase idênticos (o problema que a aula 92 resolve)
  • Revisão de tudo até aqui: Produto é abstrata (não existe "produto" genérico), implementa a interface Taxavel e deixa calcularImposto para a primeira classe concreta. Computador e Tomate são "irmãos" e cada um implementa o seu.
  • Camadas: dominio (o modelo), servico (a regra de negócio: o relatório de impostos) e test (o que visualizamos). É a ideia do MVC: separar regra de negócio do domínio e da visualização.
  • Os métodos da CalculadoraImposto são static porque não usam nenhum atributo de instância (aulas 60–63). Assim não precisa dar new CalculadoraImposto().
  • Resultado: computador NUC10i7 de 11000 paga 2310.0 e o Tomate Siciliano de 10 paga 0.6.

91 · Como funciona: o controle remoto

Produto produto = new Computador("Ryzen 9", 3000);   // variável genérica, objeto específico
System.out.println(produto.getNome());               // Ryzen 9
System.out.println(produto.getValor());              // 3000.0
System.out.println(produto.calcularImposto());       // Calculando imposto do Computador / 630.0

Produto produto2 = new Tomate("Americano", 20);
System.out.println(produto2.calcularImposto());      // Calculando imposto do tomate / 1.2
// produto2.getDataValidade();                       // NÃO compila: Produto não tem esse "botão"
  • A analogia: a variável de referência é o controle remoto e o objeto é a TV. Quando você aperta o botão, quem executa é sempre a TV.
  • O controle da Samsung 2019 tem os botões Netflix e Prime Video. Ele também funciona na TV Samsung 2020 (a subclasse), que ainda tem YouTube. Netflix e Prime executam na TV 2020, mas não há botão de YouTube no controle, então não dá para acessá-lo.
  • No código: produto.calcularImposto() executa o método do Computador. Mas getDataValidade(), que só o Tomate tem, não pode ser chamado por uma variável Produto.
  • Isso funciona porque a herança garante: tudo que a superclasse tem, a subclasse também tem. O contrário não é garantido.
  • Guardar o objeto específico numa referência genérica é um widening cast (alargamento), também chamado de upcasting. É automático, como long x = umInt; nos primitivos (aulas 10–14).

92 · Parâmetros polimórficos

public class CalculadoraImposto {
    public static void calcularImposto(Produto produto) {   // UM método para qualquer produto
        System.out.println("Relatório de imposto");
        double imposto = produto.calcularImposto();          // quem executa é o objeto
        System.out.println("Produto: " + produto.getNome());
        System.out.println("Preço: " + produto.getValor());
        System.out.println("Imposto a ser pago: " + imposto);
    }
}

Televisao tv = new Televisao("Samsung 50\" ", 5000);   // \" = aspas dentro da String
CalculadoraImposto.calcularImposto(computador);         // 2310.0
CalculadoraImposto.calcularImposto(tomate);             // 0.6
CalculadoraImposto.calcularImposto(tv);                 // 1050.0
  • Os dois métodos da aula 90 repetiam a mesma lógica e só usavam coisas que todo Produto tem (calcularImposto, getNome, getValor). Com um parâmetro do tipo Produto, sobra um método genérico e desacoplado.
  • Para uma nova Televisao extends Produto (21%), não precisa mexer na calculadora: é só passar a TV. Dá para estender "infinitamente" para todos os objetos que passam no teste "é um produto". Com o jeito antigo seriam três métodos iguais.
  • Caractere de escape: para ter aspas duplas dentro de uma String, use \". Sem a barra, o compilador acha que a String terminou ali.

93 · Cast (downcasting) e instanceof

Tomate tomate = new Tomate("Americano", 20);
tomate.setDataValidade("11/12/2021");        // precisa da variável Tomate para chamar o setter

// dentro de calcularImposto(Produto produto):
if (produto instanceof Tomate) {                              // o objeto é um Tomate?
    String dataValidade = ((Tomate) produto).getDataValidade();   // cast explícito
    System.out.println(dataValidade);
}

CalculadoraImposto.calcularImposto(tomate);    // ... imprime 11/12/2021 no fim
CalculadoraImposto.calcularImposto(produto);   // Computador: pula o if
  • Novo requisito: imprimir a data de validade quando o produto for tomate. Mas dentro do método a variável é Produto, que não tem esse botão. É preciso fazer o caminho inverso: narrowing cast (downcasting), do genérico para o específico.
  • Tomate t = produto; não compila: o Java sabe que é um produto, mas não qual. Como no primitivo (int i = (int) umLong;), é preciso o cast explícito (Tomate) produto, que diz "confia em mim".
  • Se o objeto for um Computador, o cast compila mas explode na execução com ClassCastException, porque Computador e Tomate são irmãos. Cast só funciona na mesma linha de herança (pai → filho → neto).
  • instanceof é a palavra reservada que verifica se o objeto referenciado é uma instância daquele tipo. Sempre confira antes de fazer o downcast.
  • Em uma linha só: ((Tomate) produto).getDataValidade(). Os parênteses externos fazem o cast acontecer antes do ..
  • No debug (breakpoint + F9), dá para ver que na segunda chamada o objeto é um Computador e o if é pulado.

94 · Programação orientada a interface

// repositorio/Repositorio.java
public interface Repositorio {
    public abstract void salvar();
}
// servico: RepositorioBancoDeDados, RepositorioArquivo, RepositorioMemoria implementam salvar()

Repositorio repositorio = new RepositorioMemoria();   // troque só o new
repositorio.salvar();                                // Salvando em memória

List<String> list = new LinkedList<>();                // ou new ArrayList<>()
list.add("Goku");
list.add("Vegeta");
list.add("Kuririn");
System.out.println(list);                            // [Goku, Vegeta, Kuririn]
  • No Spring e em outros frameworks, a camada que busca e grava os dados (banco, arquivo...) se chama repositório.
  • Com RepositorioBancoDeDados repositorio = ..., trocar para arquivo obriga a mudar o tipo da variável também, porque as classes não estão na mesma linha de herança. Com o tipo genérico Repositorio, só o objeto muda e o resto do código fica intacto.
  • A API de coleções usa exatamente isso: List é uma interface, e ArrayList e LinkedList são implementações com desempenho diferente para leitura e inserção. Com List<String> list, trocar a implementação não quebra nada. Coleções vêm em detalhe mais à frente.
  • Programar para a interface aumenta a manutenibilidade e facilita expandir. O William pede: "se não entendeu, assista às últimas aulas de novo até fixar", porque o conceito será usado o tempo todo.

Atenção

  • A variável limita, o objeto executa. O compilador olha o tipo da variável para permitir a chamada. Na execução, roda o método do objeto.
  • Upcast é automático, downcast é explícito. Downcast errado compila e dá ClassCastException em tempo de execução.
  • Cast entre irmãos ((Tomate) num Computador) nunca funciona. Entre tipos sem nenhuma relação de herança, nem compila.
  • Extra: instanceof com null dá false, sem exceção.
  • Extra: pattern matching (Java 16+): if (produto instanceof Tomate t) { t.getDataValidade(); } já testa e faz o cast numa tacada.
  • Extra: polimorfismo vale para métodos sobrescritos, não para atributos nem métodos static. IMPOSTO_POR_CENTO e os static são resolvidos pelo tipo da variável ou da classe (como o retrieveMaxDataSize das aulas 87–89).
  • Extra: usar muito instanceof costuma indicar que o comportamento deveria estar num método sobrescrito. Prefira que cada objeto saiba se imprimir.

Paralelo com PHP

  • O parâmetro polimórfico é igual: public static function calcularImposto(Produto $produto) com type hint aceita qualquer subclasse ou implementação.
  • O PHP não tem cast de objeto: como a checagem é em tempo de execução, $produto->getDataValidade() "funciona" se o objeto tiver o método e dá Error: Call to undefined method se não tiver. O Java barra na compilação e exige o cast. No PHP, o instanceof faz o papel de proteção (e de "cast" para o PHPStan/Psalm e para a IDE).
  • instanceof existe igual: if ($produto instanceof Tomate).
  • Repositório no Laravel: interface Repositorio + $this->app->bind(Repositorio::class, RepositorioBancoDeDados::class). Quem recebe Repositorio $repo no construtor não sabe qual implementação veio. Trocar o bind é o "trocar só o new" da aula 94. É o mesmo com Storage (disco local ou S3) e Cache (file, redis).
  • List: no PHP, o array faz tudo. Em Java você escolhe a estrutura (ArrayList, LinkedList) atrás de uma interface. A Collection do Laravel lembra a API, mas é uma classe só.

Glossário

  • Polimorfismo: um tipo genérico (superclasse/interface) referenciando objetos de tipos específicos, e cada objeto executando a sua versão do método.
  • Variável de referência: o "controle remoto"; o tipo dela define os métodos que podem ser chamados.
  • Widening cast / upcasting: subclasse para superclasse; automático.
  • Narrowing cast / downcasting: superclasse para subclasse; explícito, (Tomate) produto.
  • instanceof: operador que testa se um objeto é instância de um tipo.
  • ClassCastException: erro em tempo de execução ao fazer um cast para um tipo que o objeto não é.
  • Parâmetro polimórfico: parâmetro de tipo genérico que aceita qualquer subtipo.
  • Repositório: camada responsável por salvar e buscar dados (banco, arquivo, memória).
  • Caractere de escape: \ antes de um caractere especial dentro da String, como \".
