Resumo

Começa a programação funcional. Uma lambda é uma função anônima: não tem nome e não pertence a nenhuma classe, por isso o professor prefere chamá-la de "função". O objetivo é deixar o código conciso. Toda lambda precisa de um alvo: uma interface funcional, que tem um único método abstrato, e é esse método que define o "contrato" da lambda (quais parâmetros recebe e o que retorna). Depois vêm os method references (Classe::metodo), que encurtam ainda mais uma lambda que só chama um método, e o Optional, uma caixa que pode ter ou não um valor e serve para evitar NullPointerException em retornos.

Predicate<Car>           car -> car.getColor().equals("green")   // T → boolean   (195)
Consumer<String>        s -> System.out.println(s)              // T → nada      (196)
Function<String, Integer> s -> s.length()                       // T → R         (197)
Function<String, Integer> String::length                        // method reference (198–200)
Optional<Manga>         findByTitle("Drifters").orElseGet(...)   // talvez tenha valor (201–202)

195 · Lambdas pt 01: a sintaxe e o Predicate

A CarPredicate da aula 194 ganhou @FunctionalInterface e comentários que resumem a aula:

@FunctionalInterface
public interface CarPredicate {
    // anonimas, funções, conciso
    boolean test(Car car);
    //(parametro) -> <expressão>
    //(Car car) -> car.getColor().equals("green");
}
  • Regra 1: só existe lambda com interface funcional. A interface pode ter métodos default (com corpo), mas só um abstrato. Se você criar um segundo método abstrato numa interface com @FunctionalInterface, o compilador acusa erro. O Predicate do Java tem vários métodos, mas só o test é abstrato.
  • Regra 2: o método abstrato é o contrato (o function descriptor). boolean test(Car car) diz que a lambda recebe um Car e devolve um boolean. Se você devolver outra coisa ou usar um tipo que não bate, o compilador reclama ("incompatible types").
  • Formas da sintaxe, da mais longa para a mais curta:
(Car car) -> { return car.getColor().equals("green"); }  // com chaves: precisa de return e ;
(Car car) -> car.getColor().equals("green")              // expressão: o return é implícito
car -> car.getColor().equals("green")                    // o tipo é inferido; 1 parâmetro dispensa ()
x -> x.getColor().equals("green")                        // o nome não importa, o tipo sim
() -> "sem parâmetros"                                   // nenhum parâmetro: () obrigatório
(car, aviao) -> ...                                      // dois ou mais: () obrigatório

196 · Lambdas pt 02: Consumer

Consumer<T> recebe um T, executa uma operação e não retorna nada (void accept(T t)). O professor escreveu uma versão própria do forEach:

public class LambdaTest01 {
    public static void main(String[] args) {
        List<String> strings = List.of("William", "Suane", "Luffy", "Zoro");
        List<Integer> integers = List.of(1, 2, 3, 4, 5);
        forEach(strings, s -> System.out.println(s));   // o jeito longo seria (String s) -> ...
        forEach(integers, i -> System.out.println(i));  // aqui o parâmetro é Integer
    }

    private static <T> void forEach(List<T> list, Consumer<T> consumer) {
        for (T e : list) {
            consumer.accept(e);
        }
    }
}

O compilador sabe que s é String e que i é Integer pelo tipo da lista, por isso dá para tirar o tipo e os parênteses.

197 · Lambdas pt 03: Function

Function<T, R> recebe um T e devolve um R (R apply(T t)). Os dois tipos podem ser diferentes ou iguais. O método se chama map porque transforma cada elemento em outra coisa:

public class LambdaTest02 {
    public static void main(String[] args) {
        List<String> strings = List.of("Natsu", "Allucard");
        List<Integer> integers = map(strings, (String s) -> s.length()); // String → Integer
        List<String> map = map(strings, s -> s.toUpperCase());           // String → String
        System.out.println(integers); // [5, 8]
        System.out.println(map);      // [NATSU, ALLUCARD]
    }

    private static <T, R> List<R> map(List<T> list, Function<T, R> function) {
        List<R> result = new ArrayList<>();
        for (T e : list) {
            R r = function.apply(e);
            result.add(r);
        }
        return result;
    }
}

Predicate, Consumer e Function são as três interfaces funcionais mais famosas, e todas estão em java.util.function.

198 · Method reference pt 01: método estático

A regrinha: se a lambda só chama um método, dá para trocá-la por um method reference com :: (sem parênteses). No LambdaTest02, s -> s.length() virou String::length, e s -> s.toUpperCase() virou String::toUpperCase. A documentação da Oracle lista quatro tipos, e cada aula mostra um. O primeiro é referência a método estático:

public class AnimeComparators {
    public static int compareByTitle(Anime a1, Anime a2) {
        return a1.getTitle().compareTo(a2.getTitle());
    }
    public static int compareByEpisodes(Anime a1, Anime a2) {
        return Integer.compare(a1.getEpisodes(), a2.getEpisodes());
    }
}

// Reference to a static method
List<Anime> animeList = new ArrayList<>(List.of(new Anime("Berserk", 43),
        new Anime("One piece", 900), new Anime("Naruto", 500)));
animeList.sort((a1, a2) -> a1.getTitle().compareTo(a2.getTitle())); // lambda
animeList.sort(AnimeComparators::compareByTitle);                      // o mesmo, com method reference
animeList.sort(AnimeComparators::compareByEpisodes);
System.out.println(animeList); // Berserk (43), Naruto (500), One piece (900)

Por que funciona? A lambda só se importa com o target type (o contexto em que ela é usada). O Comparator<Anime> pede int compare(Anime, Anime), e compareByTitle tem exatamente essa "forma": recebe dois Anime e retorna int. A classe AnimeComparators não implementa Comparator, e se você passar new AnimeComparators() para o sort, dá erro. Só dá para trocar por method reference quando há uma única chamada: a1.getTitle().compareTo(...) são duas, então essa lambda não vira :: diretamente. O professor usou Collections.sort(lista, ...) e depois trocou por lista.sort(...), que faz o mesmo.

199 · Method reference pt 02: métodos não estáticos

Tipo 2: método de instância de um objeto específico (objeto::metodo). O método não é estático, então precisa de um objeto:

// em AnimeComparators
public int compareByEpisodesNonStatic(Anime a1, Anime a2) {
    return Integer.compare(a1.getEpisodes(), a2.getEpisodes());
}

//Reference to an instance method of a particular object
AnimeComparators animeComparators = new AnimeComparators();
animeList.sort(animeComparators::compareByEpisodesNonStatic);
animeList.sort((a1, a2) -> animeComparators.compareByEpisodesNonStatic(a1, a2)); // equivalente

Tipo 3: método de instância de um objeto arbitrário de um tipo (Classe::metodoNaoEstatico). Parece o tipo 1, mas o método não é estático: o primeiro parâmetro da lambda vira o objeto em que o método é chamado. O professor admite que a definição confunde ("na moral, é melhor você só aceitar, dói menos"):

//Reference to an instance method of an arbitrary object of a particular type
List<String> list = new ArrayList<>(List.of("Rimuru", "Veldora", "Hikimaru"));
list.sort(String::compareTo);           // (s1, s2) -> s1.compareTo(s2)
System.out.println(list);               // [Hikimaru, Rimuru, Veldora]

Function<String, Integer> numStringToInteger = Integer::parseInt; // s -> Integer.parseInt(s)
Integer num = numStringToInteger.apply("10");
System.out.println(num);                // 10

BiPredicate<List<String>, String> checkName = List::contains;     // (l, n) -> l.contains(n)
System.out.println(checkName.test(list, "Rimuru")); // true

BiPredicate<T, U> é o Predicate com dois argumentos (boolean test(T, U)).

200 · Method reference pt 03: construtor

Tipo 4: referência a construtor (Classe::new). Na aula 200 (o professor comenta que o curso anterior inteiro tinha 208 aulas) aparecem mais duas interfaces funcionais:

//Reference to a constructor
Supplier<AnimeComparators> newAnimeComparators = AnimeComparators::new; // () -> new AnimeComparators()
AnimeComparators animeComparators = newAnimeComparators.get();          // o objeto nasce AQUI
animeList.sort(animeComparators::compareByEpisodesNonStatic);

BiFunction<String, Integer, Anime> animeBiFunction = (title, episodes) -> new Anime(title, episodes);
BiFunction<String, Integer, Anime> animeBiFunction2 = Anime::new;
System.out.println(animeBiFunction2.apply("Super campeões", 36));
// Anime{title='Super campeões', episodes=36}
  • Supplier<T>: não recebe nada e retorna um T (T get()). Serve para o construtor sem parâmetros.
  • BiFunction<T, U, R>: recebe T e U e retorna R (R apply(T, U)). Serve para o construtor Anime(String, int). Com Supplier<Anime> = Anime::new não compila, porque Anime não tem construtor sem parâmetros.
  • A linha do ::new não cria o objeto. O objeto só é criado quando você chama get() ou apply(...).

201 · Optional pt 01

Optional<T> (Java 8) é um objeto que encapsula outro objeto, que pode existir ou não. A intenção é evitar NullPointerException (não todos, mas os de retorno). Em vez de um método retornar null, ele retorna um Optional, e quem chama é "forçado" a pensar no caso negativo: e se não encontrar?

Optional<String> o1 = Optional.of("Aha uhu o DevDojo é foda."); // valor obrigatório (null → NPE)
Optional<String> o2 = Optional.ofNullable(null);               // pode ser null → vazio
Optional<String> o3 = Optional.empty();                        // vazio de propósito
System.out.println(o1); // Optional[Aha uhu o DevDojo é foda.]
System.out.println(o2); // Optional.empty
System.out.println(o3); // Optional.empty

Optional<String> nameOptional = findName("William");
String empty = nameOptional.orElse("EMPTY");              // o valor, ou "EMPTY" se vazio
System.out.println(empty);                                // William
nameOptional.ifPresent(s -> System.out.println(s.toUpperCase())); // WILLIAM (Consumer)

private static Optional<String> findName(String name) {
    List<String> list = List.of("William", "DevDojo");
    int i = list.indexOf(name);
    if (i != -1) {                  // no repositório está "i != 1" (veja o Atenção)
        return Optional.of(list.get(i));
    }
    return Optional.empty();
}

O professor primeiro mostra o problema: um findName que devolve null e, lá na frente, alguém faz name.toUpperCase(), estourando NullPointerException. Depois ele passa pela versão intermediária, que embrulha o resultado com Optional.ofNullable(...), e chega à ideal: Optional.of quando encontra e Optional.empty() quando não encontra. O orElse é "um if/else em uma linha". O ifPresent recebe um Consumer, que não retorna nada, por isso o println fica dentro da lambda.

202 · Optional pt 02: um repositório de mangás

Optional é para retorno de método. O IntelliJ avisa quando você usa em parâmetro, e também não é boa ideia como atributo de classe (private Optional<String> name): Optional não é Serializable, e frameworks como o Hibernate/JPA esperam atributos serializáveis.

O repositório simula um banco de dados. Em vez de escrever um findByTitle e um findById com o mesmo for, o professor aplica o que aprendeu nas aulas 193–194 e passa a condição como Predicate:

public class MangaRepository {
    private static List<Manga> mangas = List.of(new Manga(1, "Boku no Hero", 50), new Manga(2, "Overlord", 25));

    public static Optional<Manga> findById(Integer id) {
        return findBy(m -> m.getId().equals(id));
    }

    public static Optional<Manga> findByTitle(String title) {
        return findBy(m -> m.getTitle().equals(title));
    }

    private static Optional<Manga> findBy(Predicate<Manga> predicate) {
        Manga found = null;
        for (Manga manga : mangas) {
            if (predicate.test(manga)) {
                found = manga;
            }
        }
        return Optional.ofNullable(found);
    }
}

E os três requisitos, cada um resolvido em uma linha de Optional:

// 1. Procure por título; se existir, atualize o título
Optional<Manga> mangaByTitle = MangaRepository.findByTitle("Boku no Hero");
mangaByTitle.ifPresent(m -> m.setTitle("Boku no Hero 2"));
System.out.println(mangaByTitle);
// Optional[Manga{id=1, title='Boku no Hero 2', chapters=50}]

// 2. Procure por id; se não existir, lance IllegalArgumentException
Manga mangaById = MangaRepository.findById(2).orElseThrow(IllegalArgumentException::new);
System.out.println(mangaById);
// Manga{id=2, title='Overlord', chapters=25}

// 3. Procure por título; se não existir, crie um novo
Manga newManga = MangaRepository.findByTitle("Drifters")
        .orElseGet(() -> new Manga(3, "Drifters", 20));
System.out.println(newManga);
// Manga{id=3, title='Drifters', chapters=20}
  • orElseThrow(Supplier) extrai o objeto do Optional (o tipo passa a ser Manga, não Optional<Manga>) ou lança a exceção criada pelo Supplier. Com findById(3), sai IllegalArgumentException.
  • orElse(valor) × orElseGet(Supplier): os dois extraem o valor ou devolvem uma alternativa. O professor diz que "tanto faz" para esse exemplo.
  • A vantagem, segundo o professor, é a leitura: "encontra por título, se estiver presente, faz isso"; até quem não é desenvolvedor entende. Com if/else e null ficaria bem mais difícil de ler.

Atenção

  • Lambda só com interface funcional: exatamente um método abstrato (os default e static não contam).
  • Com chaves, return e ; são obrigatórios (se o método retorna algo): car -> { return car.getYear() < 2015; }. Sem chaves, é uma expressão e não tem return.
  • Method reference só quando a lambda faz uma única chamada com os mesmos argumentos, na mesma ordem. s -> s.length() + 1 ou a1.getTitle().compareTo(a2.getTitle()) não viram :: diretamente.
  • Classe::metodo pode ser o tipo 1 ou o tipo 3: depende de o método ser estático (tipo 1) ou de instância (tipo 3, o primeiro parâmetro vira o objeto). Correção: no repositório, Integer::parseInt está no arquivo do tipo 3 (objeto arbitrário), mas parseInt é estático, então é uma referência do tipo 1. String::compareTo e List::contains são tipo 3 de verdade.
  • ::new e ::metodo não executam nada: só criam a "função". A execução acontece em get(), apply(), test(), accept().
  • Optional.of(null) lança NullPointerException. Se o valor pode ser null, use ofNullable.
  • Correção: no repositório, o findName da aula 201 tem if (i != 1). O certo é i != -1 (o indexOf devolve −1 quando não acha); no vídeo o professor chega a falar em "menos um". Com != 1, findName("DevDojo") (índice 1) volta vazio e um nome inexistente estoura IndexOutOfBoundsException em list.get(-1).
  • Extra: orElse × orElseGet não é "tanto faz" sempre. O argumento do orElse é avaliado sempre, mesmo quando o Optional tem valor. Se for caro (orElse(repository.save(...))), use orElseGet(() -> ...), que só roda quando está vazio.
  • Extra: evite optional.get() sem checar: com Optional vazio ele lança NoSuchElementException, que é o NPE com outro nome. Prefira orElse, orElseThrow e ifPresent.
  • Extra: findBy não para no primeiro que encontra (não tem break), então devolve o último que casar. Com ids e títulos únicos não faz diferença.

Paralelo com PHP

  • Lambda = closure/arrow function: fn($s) => strlen($s) ≈ s -> s.length(). A diferença é que no PHP qualquer callable serve, e no Java a lambda precisa "caber" numa interface funcional (Function<String, Integer>), que é conferida na compilação.
  • As interfaces nas funções de array/Collection: Predicate ≈ array_filter / collect()->filter(); Consumer ≈ array_walk / ->each(); Function ≈ array_map / ->map(); Supplier ≈ um fn() => ... sem parâmetros (como o default de $request->input('x', fn() => ...) ou o Cache::remember).
  • Method reference ≈ first-class callable (PHP 8.1): strlen(...), Str::upper(...) (estático), $comparators->compareByEpisodes(...) (objeto específico). Antes do 8.1: 'strlen', [Classe::class, 'metodo'], [$obj, 'metodo']. Não há um Classe::new: o equivalente é fn(...$a) => new Anime(...$a).
  • Optional ≈ o que o PHP faz com ?: tipo de retorno ?Manga, operador ?? (≈ orElse), nullsafe $manga?->title e o helper optional($manga)->title do Laravel. No Eloquent: Manga::findOrFail($id) ≈ findById(id).orElseThrow(...), e Manga::firstOrNew(['title' => 'Drifters'], [...]) ≈ o orElseGet(() -> new Manga(...)) do requisito 3.

package academy.devdojo.maratonajava.javacore.ZZClambdas.test;

import java.util.*;
import java.util.function.*;

public class FuncionalTest01 {
    static class Anime {
        private final String title;
        private final int episodes;
        Anime(String title, int episodes) { this.title = title; this.episodes = episodes; }
        String getTitle() { return title; }
        int getEpisodes() { return episodes; }
        @Override public String toString() { return title + "(" + episodes + ")"; }
    }

    static int compareByEpisodes(Anime a1, Anime a2) {
        return Integer.compare(a1.getEpisodes(), a2.getEpisodes());
    }

    static <T> List<T> filter(List<T> list, Predicate<T> predicate) {
        List<T> result = new ArrayList<>();
        for (T e : list) if (predicate.test(e)) result.add(e);
        return result;
    }

    static <T> void forEach(List<T> list, Consumer<T> consumer) {
        for (T e : list) consumer.accept(e);
    }

    static <T, R> List<R> map(List<T> list, Function<T, R> function) {
        List<R> result = new ArrayList<>();
        for (T e : list) result.add(function.apply(e));
        return result;
    }

    static Optional<String> findName(String name) {
        List<String> list = List.of("William", "DevDojo");
        int i = list.indexOf(name);
        return i != -1 ? Optional.of(list.get(i)) : Optional.empty();
    }

    public static void main(String[] args) {
        List<String> nomes = List.of("Natsu", "Allucard", "Rimuru");

        // Predicate, Consumer, Function
        System.out.println(filter(nomes, s -> s.length() > 5));        // ?
        forEach(nomes, s -> System.out.print(s.charAt(0)));             // ?
        System.out.println();
        System.out.println(map(nomes, String::length));                 // ?
        System.out.println(map(nomes, String::toUpperCase));            // ?

        // 1. método estático
        List<Anime> animes = new ArrayList<>(List.of(new Anime("Berserk", 43),
                new Anime("One piece", 900), new Anime("Naruto", 500)));
        animes.sort(FuncionalTest01::compareByEpisodes);
        System.out.println(animes);                                     // ?

        // 2. objeto específico
        String prefixo = "Anime: ";
        Function<String, String> comPrefixo = prefixo::concat;         // s -> prefixo.concat(s)
        System.out.println(comPrefixo.apply("Berserk"));                // ?

        // 3. objeto arbitrário de um tipo
        List<String> ordenados = new ArrayList<>(List.of("Rimuru", "Veldora", "Hikimaru"));
        ordenados.sort(String::compareTo);
        System.out.println(ordenados);                                  // ?
        BiPredicate<List<String>, String> contem = List::contains;
        System.out.println(contem.test(ordenados, "Zoro"));             // ?

        // 4. construtor
        Supplier<List<String>> novaLista = ArrayList::new;
        List<String> lista = novaLista.get();
        lista.add("criada pelo Supplier");
        System.out.println(lista);                                      // ?
        BiFunction<String, Integer, Anime> criar = Anime::new;
        System.out.println(criar.apply("Super campeões", 36));          // ?

        // Optional
        System.out.println(Optional.of("DevDojo"));                     // ?
        System.out.println(Optional.ofNullable(null));                  // ?
        System.out.println(findName("William").orElse("EMPTY"));        // ?
        System.out.println(findName("Luffy").orElse("EMPTY"));          // ?
        findName("DevDojo").ifPresent(s -> System.out.println(s.toUpperCase())); // ?
        findName("Zoro").ifPresent(s -> System.out.println("nunca imprime"));
        System.out.println(findName("Zoro").orElseGet(() -> "gerado pelo Supplier")); // ?
        try {
            findName("Zoro").orElseThrow(IllegalArgumentException::new);
        } catch (IllegalArgumentException e) {
            System.out.println("Exceção: " + e.getClass().getSimpleName()); // ?
        }
    }
}

Glossário

  • Programação funcional: estilo em que funções são passadas como valores (parâmetros, retornos).
  • Lambda: função anônima, (parâmetros) -> corpo, que implementa uma interface funcional.
  • Interface funcional: interface com exatamente um método abstrato; @FunctionalInterface faz o compilador garantir isso.
  • Function descriptor: a assinatura do método abstrato, que define parâmetros e retorno da lambda.
  • Target type: o tipo esperado no contexto em que a lambda aparece (ex.: Comparator<Anime> no sort).
  • Predicate<T> / BiPredicate<T,U>: recebem um ou dois valores e retornam boolean.
  • Consumer<T>: recebe um valor e não retorna nada.
  • Function<T,R> / BiFunction<T,U,R>: recebem um ou dois valores e retornam um R.
  • Supplier<T>: não recebe nada e retorna um T.
  • Method reference: atalho Classe::metodo, objeto::metodo ou Classe::new para uma lambda que só chama um método.
  • Optional<T>: contêiner que tem um valor ou está vazio; usado em retornos para evitar null.
