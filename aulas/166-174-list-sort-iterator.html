Resumo

A List é a coleção mais usada: ordenada (guarda a ordem de inserção e tem índice) e aceita repetidos. A implementação mais comum é o ArrayList, um array que cresce sozinho. Aqui você vê como criar, percorrer, buscar (com equals, aulas 161–164), ordenar (Comparable para a ordem natural e Comparator para ordens alternativas), fazer busca binária, converter entre lista e array e remover com segurança durante a iteração.

166 · ArrayList e generics

// Antes do Java 5: lista "crua", aceitava qualquer Object
List nomesAntigos = new ArrayList();
nomesAntigos.add("William");
nomesAntigos.add(123);                     // compilava!

// Com generics (Java 5+) e diamond <> (Java 7+)
List<String> nomes = new ArrayList<>(16);   // 16 = capacidade inicial
nomes.add("William");
nomes.add("DevDojo Academy");
// nomes.add(123);                         // NÃO compila

for (String nome : nomes) {                // foreach
    System.out.println(nome);
}
nomes.add("Suane");                        // cresce sozinho
for (int i = 0; i < nomes.size(); i++) {   // size() em vez de length
    System.out.println(nomes.get(i));      // get(índice) em vez de [i]
}
  • List é uma interface. ArrayList é a implementação: "um array que pode ser incrementado dinamicamente". Você declara pelo tipo genérico (List) e escolhe a implementação no new, pensando no desempenho (aula 165).
  • Generics (<String>) forçam o tipo em tempo de compilação. Sem eles, tudo era Object, e você precisava de cast sem garantia nenhuma. Em bytecode o tipo "some" (compatibilidade com versões antigas), mas o compilador já validou.
  • O diamond new ArrayList<>() (Java 7) evita repetir o tipo. O tipo do new precisa bater com o da variável: List<String> x = new ArrayList<Integer>() não compila.
  • Capacidade inicial: se você já sabe que vão ser uns 300 itens, passe new ArrayList<>(300) e evite redimensionamentos. (O William fala em dobrar o tamanho. No ArrayList atual o crescimento é de 50%, extra.)

167 · Cuidados, remove e addAll

// for (String nome : nomes) { nomes.add("Suane"); }   → ConcurrentModificationException
// for (int i = 0; i < nomes.size(); i++) { nomes.add("Suane"); }   → laço infinito!
int size = nomes.size();                     // congela o tamanho antes de alterar
for (int i = 0; i < size; i++) {
    nomes.add("Suane");
}

List<Integer> numeros = new ArrayList<>();   // List<int> não existe: usa o wrapper (aulas 106–107)
numeros.add(1);                                // autoboxing

nomes.remove(0);                // remove pelo ÍNDICE e devolve o elemento removido
nomes.remove("William");        // remove pelo OBJETO (usa equals) e devolve boolean
nomes.addAll(nomes2);           // adiciona todos os elementos de outra coleção
// William · DevDojo · Suane · Academy
  • Não altere o tamanho da lista dentro de um foreach: dá ConcurrentModificationException. Com o for indexado e size() na condição, cada add aumenta o limite e o laço nunca termina. Guardar o tamanho numa variável resolve, mas mexer no tamanho durante a iteração é má ideia. O jeito certo vem na aula 174.
  • Coleções só guardam objetos, porque elas chamam equals/hashCode e primitivos não têm métodos. Por isso List<Integer>, com autoboxing no add(1).
  • remove é sobrecarregado: remove(int indice) × remove(Object o), que procura com equals.
  • addAll(outraColecao) junta as listas numa linha. "Em entrevista pedem para fazer na mão; no trabalho, você usa o que o Java já resolveu."
  • System.out.println(lista) já imprime [a, b, c] (a lista tem toString).

168 · List de objetos: contains, indexOf e add(índice)

Smartphone s1 = new Smartphone("1ABC1", "iPhone");
Smartphone s2 = new Smartphone("22222", "Pixel");
Smartphone s3 = new Smartphone("33333", "Samsung");
List<Smartphone> smartphones = new ArrayList<>(6);
smartphones.add(s1);
smartphones.add(s2);
smartphones.add(0, s3);                        // insere NA POSIÇÃO 0 e empurra os outros
// Samsung · iPhone · Pixel

Smartphone s4 = new Smartphone("22222", "Pixel");   // outro objeto, mesmo serial
System.out.println(smartphones.contains(s4));        // true: contains usa EQUALS
int indexSmartphone4 = smartphones.indexOf(s4);      // 2 (ou -1 se não existir)
System.out.println(smartphones.get(indexSmartphone4));
// smartphones.clear();                              // esvazia a lista
  • O cenário: os dados vêm do banco e viram objetos, e você trabalha com a coleção deles.
  • add(indice, elemento) insere numa posição específica, porque a lista mantém a ordem do índice.
  • contains e indexOf chamam o equals de cada elemento (dá para ver no debug, com breakpoint no equals). Por isso implementar equals/hashCode em toda classe de domínio é importante. É também o custo O(n) da aula 165: 10 mil celulares, até 10 mil equals.
  • indexOf devolve -1 quando não encontra, e get(-1) lança IndexOutOfBoundsException. Confira antes (if (indice != -1)).

169 · Collections.sort e a classe Manga

List<String> mangas = new ArrayList<>(6);
mangas.add("Hellsing Ultimate");
mangas.add("Berserk");
mangas.add("Pokemon");

Collections.sort(mangas);        // Attack on titan · Berserk · Dragon ball Z · Hellsing Ultimate · Pokemon

List<Double> dinheiros = new ArrayList<>(List.of(100.21, 23.98, 21.21, 98.10));
Collections.sort(dinheiros);     // [21.21, 23.98, 98.1, 100.21]

// Collections.sort(smartphones);   → NÃO compila: ordenar Smartphone por quê?

public Manga(Long id, String nome, double preco) {
    Objects.requireNonNull(id, "Id não pode ser null");     // falha cedo, com mensagem clara
    Objects.requireNonNull(nome, "Nome não pode ser null");

// equals/hashCode gerados pela IDE com id, nome e preco (Objects.hash(id, nome, preco))
  • Collections (com s) é a classe utilitária de métodos estáticos. Collections.sort(lista) ordena a própria lista: Strings em ordem alfabética, números do menor para o maior.

170 · Comparable: a ordem natural

public class Manga implements Comparable<Manga> {
    ...
    @Override
    public int compareTo(Manga outroManga) {
        // negativo se this < outroManga · 0 se iguais · positivo se this > outroManga
        // if (this.id < outroManga.getId()) return -1;
        // else if (this.id.equals(outroManga.getId())) return 0;
        // else return 1;
        return this.nome.compareTo(outroManga.getNome());        // delega para a String
        // return this.id.compareTo(outroManga.getId());          // Long já é Comparable
        // return Double.compare(preco, outroManga.getPreco());   // primitivo: usa o wrapper
    }
}

Collections.sort(mangas);   // agora compila e chama o compareTo por dentro
// Manga{id=3, nome='Attack on titan'...} · Berserk · Dragon ball Z · Hellsing Ultimate · Pokemon
  • A String se ordena porque implementa Comparable. Faça o mesmo: implements Comparable<Manga> e o método compareTo.
  • A regra do retorno: negativo se this vem antes, 0 se empata e positivo se this vem depois. Não precisa ser -1/1, qualquer negativo ou positivo vale.
  • Delegue sempre que puder: Long, String e Double já são Comparable. Um if/else de 6 linhas vira return this.id.compareTo(outro.getId()). Para primitivo (double preco): Double.compare(a, b) (ou Double.valueOf(preco).compareTo(...)).
  • Quem chama o compareTo é o algoritmo de ordenação do Java. Com um breakpoint dá para ver this e o outro sendo comparados par a par.

171 · Comparator: ordens alternativas

class MangaByIdComparator implements Comparator<Manga> {   // classe separada, fora do Manga
    @Override
    public int compare(Manga manga1, Manga manga2) {
        return manga1.getId().compareTo(manga2.getId());
    }
}

Collections.sort(mangas);                              // ordem natural (compareTo): por nome
Collections.sort(mangas, new MangaByIdComparator());   // ordem alternativa: por id
mangas.sort(new MangaByIdComparator());                // o mesmo, pelo método da própria List
// 1 Berserk · 2 Dragon ball Z · 3 Attack on titan · 4 Pokemon · 5 Hellsing Ultimate
  • O problema: o compareTo por nome é usado no sistema inteiro há um ano. Trocar para id "solta o inferno na terra". Uma ordem diferente num lugar específico vem de um Comparator, sem tocar no Manga.
  • Comparable: dentro da classe, 1 argumento (compareTo(outro)), é a ordem natural (única). Comparator: classe à parte, 2 argumentos (compare(a, b)), quantas ordens quiser. A regra do retorno é a mesma.
  • Collections.sort(lista, comparator) ou lista.sort(comparator). No list.sort o comparator é obrigatório. Com null, ele usa a ordem natural.
  • Com classes anônimas (aula 191) e lambdas (aulas 195+) isso fica em uma linha: mangas.sort(Comparator.comparing(Manga::getId)) (extra).

172 · Busca binária

List<Integer> numeros = new ArrayList<>(List.of(2, 0, 4, 3));
Collections.sort(numeros);                             // OBRIGATÓRIO antes: [0, 2, 3, 4]
// índice: 0 1 2 3  ·  valor: 0 2 3 4
System.out.println(Collections.binarySearch(numeros, 2));    // 1  (achou no índice 1)
System.out.println(Collections.binarySearch(numeros, 0));    // 0
System.out.println(Collections.binarySearch(numeros, 1));    // -2 → -(ponto de inserção) - 1 = -(1) - 1
System.out.println(Collections.binarySearch(numeros, -1));   // -1 → -(0) - 1

// Com objetos e ordem customizada: ordene E busque com o MESMO comparator
MangaByIdComparator mangaByIdComparator = new MangaByIdComparator();
mangas.sort(mangaByIdComparator);
Manga mangaToSearch = new Manga(2L, "Dragon ball Z", 2.99);
System.out.println(Collections.binarySearch(mangas, mangaToSearch, mangaByIdComparator));   // 1
// id 6 → -6 (entraria no fim, posição 5)
  • A busca binária divide a lista ao meio a cada passo, então é O(log n), bem mais rápida que o indexOf (O(n)). Em troca, exige a lista ordenada pelo mesmo critério. Senão, "o resultado não é confiável".
  • Encontrou: devolve o índice (≥ 0). Não encontrou: devolve -(ponto de inserção) - 1, onde o ponto de inserção é onde o elemento deveria entrar para manter a ordem.
  • Por que o "−1"? Sem ele, "não achei, mas entraria na posição 0" daria 0, igual a "achei na posição 0". Com o −1, o resultado só é ≥ 0 se o elemento existe.
  • Com objetos ordenados por um Comparator, passe o mesmo comparator para o binarySearch. Ele compara pelo critério do comparator (o id), não pelo equals.
  • Existe também para arrays: Arrays.binarySearch(array, chave), com as mesmas regras.

173 · List ↔ array

// Lista → array
List<Integer> numeros = new ArrayList<>(List.of(1, 2, 3));
Integer[] listToArray = numeros.toArray(new Integer[0]);   // o array de 0 posições só informa o TIPO
System.out.println(Arrays.toString(listToArray));          // [1, 2, 3]

// Array → lista: Arrays.asList cria uma lista LIGADA ao array e de tamanho FIXO
Integer[] numerosArray = {1, 2, 3};
List<Integer> arrayToList = Arrays.asList(numerosArray);
arrayToList.set(0, 12);
System.out.println(Arrays.toString(numerosArray));   // [12, 2, 3] ← o array mudou junto!
System.out.println(arrayToList);                     // [12, 2, 3]
// arrayToList.add(19);                              → UnsupportedOperationException

// Cópia independente e mutável
List<Integer> numerosList = new ArrayList<>(Arrays.asList(numerosArray));
numerosList.add(15);                                  // [12, 2, 3, 15]

List<String> strings = Arrays.asList("1", "2");       // lista direto dos valores (varargs)
List<String> imutavel = List.of("1", "2");            // Java 9+: imutável de verdade
  • toArray(new Integer[0]) devolve um array do tipo certo. O toArray() sem argumento devolve Object[], o que "geralmente não é bom". Passar new Integer[0] é o recomendado (a IDE sugere, e é tão rápido quanto passar o tamanho).
  • Arrays.asList(array) tem duas pegadinhas: a lista fica ligada ao array (alterar um altera o outro) e tem tamanho fixo (add/remove lançam UnsupportedOperationException). O set funciona.
  • Para uma lista independente e mutável: new ArrayList<>(Arrays.asList(...)), porque o ArrayList tem um construtor que recebe outra coleção.
  • Para criar numa linha: Arrays.asList(1, 2, 3) ou, no Java 9+, List.of(1, 2, 3). Por isso o projeto passou para o language level 11.

174 · Iterator e removeIf

// public Manga(Long id, String nome, double preco, int quantidade) { this(id, nome, preco); ... }
mangas.add(new Manga(5L, "Hellsing Ultimate", 19.9, 0));
mangas.add(new Manga(1L, "Berserk", 9.5, 5));
mangas.add(new Manga(4L, "Pokemon", 3.2, 0));
mangas.add(new Manga(3L, "Attack on titan", 11.20, 2));
mangas.add(new Manga(2L, "Dragon ball Z", 2.99, 0));

// for (Manga manga : mangas) { if (manga.getQuantidade() == 0) mangas.remove(manga); }
//   → ConcurrentModificationException

Iterator<Manga> mangaIterator = mangas.iterator();
while (mangaIterator.hasNext()) {                     // tem alguém na fila?
    if (mangaIterator.next().getQuantidade() == 0) {  // chama o próximo
        mangaIterator.remove();                       // remove PELO ITERATOR (seguro)
    }
}

mangas.removeIf(manga -> manga.getQuantidade() == 0);  // Java 8: o mesmo, em uma linha
// [Manga{id=1, nome='Berserk'...quantidade=5}, Manga{id=3, nome='Attack on titan'...quantidade=2}]
  • O construtor novo reaproveita o antigo com this(...) (aulas 58–59), e o código que usava o de 3 argumentos continua funcionando.
  • Remover dentro do foreach dá ConcurrentModificationException.
  • Iterator é a "fila do banco": hasNext() olha se tem alguém, next() chama o próximo e iterator.remove() tira da lista quem acabou de ser chamado, sem bagunçar a iteração.
  • removeIf(condição) (Java 8) faz o mesmo com uma lambda: manga -> manga.getQuantidade() == 0. O nome antes da seta é só uma variável, como a do foreach. Por baixo, usa o mesmo Iterator. Programação funcional é assunto das aulas 195+.

Atenção

  • Declare pela interface: List<X> l = new ArrayList<>().
  • Nunca altere o tamanho da lista num foreach. Use Iterator.remove() ou removeIf.
  • contains, indexOf e remove(Object) dependem do equals. binarySearch depende da ordem (compareTo/compare).
  • Comparable = ordem natural, dentro da classe, compareTo(1). Comparator = outras ordens, fora, compare(2).
  • Arrays.asList: ligado ao array e tamanho fixo. List.of: totalmente imutável (nem set funciona, nem aceita null).
  • Extra: armadilha com List<Integer>: numeros.remove(1) remove o índice 1, não o valor 1. Para remover o valor: numeros.remove(Integer.valueOf(1)).
  • Extra: compareTo coerente com equals: o recomendado é compareTo == 0 quando equals é true. Coleções ordenadas (TreeSet, aula 176) usam o compareTo para decidir o que é "repetido".

Paralelo com PHP

  • Array do PHP × List: o array do PHP é lista e dicionário ao mesmo tempo, sem tipo. List<String> garante o tipo na compilação. No PHP isso vem com PHPDoc (@var list<string>) e PHPStan. A Collection do Laravel é o parente mais próximo da List.
  • Equivalências:
    • add ≈ $a[] = /push, size ≈ count, get(i) ≈ $a[$i].
    • contains ≈ in_array/contains, indexOf ≈ array_search (que devolve false, não −1).
    • addAll ≈ array_merge/merge, clear ≈ $a = [].
  • Ordenação: Collections.sort ≈ sort(), e o Comparator ≈ usort($a, fn($x, $y) => $x->id <=> $y->id). O spaceship <=> do PHP devolve −1/0/1, a mesma regra do compareTo. No Laravel: $c->sortBy('id'). O PHP não tem um "Comparable" que o sort use sozinho.
  • Remover durante a iteração: no PHP, um foreach com unset($a[$k]) funciona (o foreach itera sobre uma cópia). No Java, dá exceção. O removeIf equivale a array_filter/$c->reject(fn($m) => $m->quantidade == 0), com a diferença de que o Java altera a própria lista e o PHP devolve uma nova.
  • Busca binária: o PHP não tem nativa. array_search é sempre linear.

package academy.devdojo.maratonajava.javacore.Ycolecoes.dominio;

import java.util.Objects;

public class Manga implements Comparable<Manga> {
    private Long id;
    private String nome;
    private double preco;
    private int quantidade;

    public Manga(Long id, String nome, double preco) {
        Objects.requireNonNull(id, "Id não pode ser null");
        Objects.requireNonNull(nome, "Nome não pode ser null");
        this.id = id;
        this.nome = nome;
        this.preco = preco;
    }

    public Manga(Long id, String nome, double preco, int quantidade) {
        this(id, nome, preco);
        this.quantidade = quantidade;
    }

    @Override
    public int compareTo(Manga outroManga) {
        return this.nome.compareTo(outroManga.getNome());
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Manga manga = (Manga) o;
        return Double.compare(manga.preco, preco) == 0 && id.equals(manga.id) && nome.equals(manga.nome);
    }

    @Override
    public int hashCode() { return Objects.hash(id, nome, preco); }

    @Override
    public String toString() { return id + " " + nome + " (" + preco + ", qtd " + quantidade + ")"; }

    public Long getId() { return id; }
    public String getNome() { return nome; }
    public double getPreco() { return preco; }
    public int getQuantidade() { return quantidade; }
}
EOF

Glossário

  • List: coleção ordenada por índice que aceita repetidos.
  • ArrayList: implementação de List sobre um array redimensionável.
  • Generics: parâmetro de tipo (<String>) checado em compilação.
  • Diamond (<>): deixa o compilador inferir o tipo no new.
  • Comparable: interface da ordem natural (compareTo), implementada pela própria classe.
  • Comparator: objeto externo que define uma ordem (compare).
  • Busca binária: busca O(log n) que divide a lista ordenada ao meio a cada passo.
  • Ponto de inserção: onde o elemento entraria para manter a lista ordenada.
  • Iterator: objeto que percorre a coleção (hasNext, next) e remove com segurança.
  • ConcurrentModificationException: exceção ao alterar a estrutura da coleção enquanto um foreach a percorre.
