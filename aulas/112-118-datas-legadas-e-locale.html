Resumo

Datas em Java têm história: primeiro veio a Date, que não bastou. Depois veio a Calendar, "tentando consertar", que também não bastou. No Java 8 chegou um pacote inteiro, o java.time (aulas 119+). As classes legadas continuam importantes porque você vai encontrá-las em sistemas antigos. O bloco também mostra a internacionalização (i18n) com Locale: o mesmo dado formatado como cada país espera.

java.util:  Date (1.0) · Calendar (abstrata) · Locale
java.text:  DateFormat (abstrata) · SimpleDateFormat · NumberFormat (abstrata)
java.time:  LocalDate, LocalDateTime... (Java 8, aulas 119+) ← use em sistemas novos

112 · Date

import java.util.Date;              // NÃO confundir com java.sql.Date (banco de dados)

Date date = new Date(1613061109953L);          // milissegundos desde 01/01/1970
date.setTime(date.getTime() + 3_600_000);      // + 1 hora (3.600.000 ms)
System.out.println(date);                      // Thu Feb 11 14:31:49 BRT 2021 (fuso de São Paulo)
  • Existe desde o Java 1.0. Tome cuidado com o import: é java.util.Date. A java.sql.Date é para o banco.
  • Por dentro é só um long com os milissegundos desde 1º de janeiro de 1970 (a epoch). new Date() é "agora", e getTime() devolve esse long.
  • Quase todos os métodos são deprecated (riscados na IDE). Deprecated quer dizer que pode sumir numa versão futura e que existe coisa melhor.
  • Somar uma hora exige conta de milissegundos à mão (3_600_000), e ela não tem suporte a internacionalização, uma das bandeiras do Java. Por isso ficou obsoleta.
  • println(date) chama o toString(), que sai sempre no mesmo formato em inglês, no fuso da JVM.

113 · Calendar

Calendar c = Calendar.getInstance();     // abstrata: new Calendar() não compila
if (c.getFirstDayOfWeek() == Calendar.SUNDAY) {
    System.out.println("Domingão é o primeiro dia da semana");
}
System.out.println(c.get(Calendar.DAY_OF_WEEK));          // 5 = quinta
System.out.println(c.get(Calendar.DAY_OF_MONTH));         // 11
System.out.println(c.get(Calendar.DAY_OF_YEAR));          // 42
System.out.println(c.get(Calendar.DAY_OF_WEEK_IN_MONTH)); // 2 (2ª quinta do mês)

c.add(Calendar.DAY_OF_MONTH, 2);   // soma e "vira" o que precisar (mês, ano)
c.roll(Calendar.HOUR, 12);         // soma sem virar o campo de cima
Date date = c.getTime();           // Calendar → Date (para imprimir legível)
  • É abstrata. Calendar.getInstance() devolve a implementação certa para o Locale (budista, imperial japonês, gregoriano no Brasil e na Europa).
  • O toString() dela é ilegível. O truque da aula é c.getTime(), que devolve um Date para imprimir.
  • Use as constantes, não números mágicos: Calendar.SUNDAY, Calendar.DAY_OF_MONTH... O primeiro dia da semana depende do país: domingo no Brasil e nos EUA, segunda na França e na Holanda.
  • get(campo) lê um campo: dia da semana, do mês, do ano, ou a ocorrência do dia da semana no mês.
  • add × roll: add soma e vira o campo maior (12 horas depois das 18h dá 6h do dia seguinte). roll não vira o campo de cima: dá a volta dentro do próprio campo e deixa dia/mês/ano como estavam.
  • Sistema legado em Java 7? Com Date e Calendar você já sabe se virar. Em Java 8+, prefira converter para o java.time.

114 · DateFormat: formatos prontos

Calendar calendar = Calendar.getInstance();
DateFormat[] df = new DateFormat[7];                 // abstrata, mas pode ser tipo de array
df[0] = DateFormat.getInstance();                    // data e hora curtas
df[1] = DateFormat.getDateInstance();                // só data (MEDIUM)
df[2] = DateFormat.getDateTimeInstance();            // data e hora
df[3] = DateFormat.getDateInstance(DateFormat.SHORT);   // 11/02/2021
df[4] = DateFormat.getDateInstance(DateFormat.MEDIUM);  // 11 de fev. de 2021
df[5] = DateFormat.getDateInstance(DateFormat.LONG);    // 11 de fevereiro de 2021
df[6] = DateFormat.getDateInstance(DateFormat.FULL);    // quinta-feira, 11 de fevereiro de 2021

for (DateFormat dateFormat : df) {
    System.out.println(dateFormat.format(calendar.getTime()));   // format recebe Date, não Calendar
}
  • java.text.DateFormat é abstrata: os objetos vêm de getInstance, getDateInstance e getDateTimeInstance.
  • Quatro estilos: SHORT, MEDIUM, LONG, FULL (o FULL inclui o dia da semana). O resultado segue o Locale do sistema operacional (as saídas acima são de uma JVM em pt-BR).
  • format recebe um Date. Passar o Calendar direto não funciona, por isso o calendar.getTime().
  • O William diz que esses formatos prontos resolvem uns 90% dos casos. Para formatos sob medida existe o SimpleDateFormat (aula 118).

115 · Locale: datas no formato de cada país

Locale localeItaly = new Locale("it", "IT");    // língua (ISO 639) + país (ISO 3166)
Locale localeCH = new Locale("it", "CH");       // italiano falado na Suíça
Locale localeIndia = new Locale("hi", "IN");
Locale localeJapao = new Locale("ja", "JP");
Locale localeHolanda = new Locale("nl", "NL");

Calendar calendar = Calendar.getInstance();
DateFormat df1 = DateFormat.getDateInstance(DateFormat.FULL, localeItaly);
System.out.println("Italia " + df1.format(calendar.getTime()));   // Italia giovedì 11 febbraio 2021
// Suíça: "giovedì, 11 febbraio 2021" (com vírgula) · Japão: "2021年2月11日木曜日"

System.out.println(localeItaly.getDisplayCountry(localeJapao));    // "Itália" escrito em japonês
System.out.println(localeCH.getDisplayCountry(localeHolanda));     // "Suíça" em holandês (Zwitserland)
System.out.println(localeItaly.getDisplayLanguage(localeJapao));   // "italiano" em japonês
  • java.util.Locale existe para a internacionalização: formatar datas, números e moedas conforme a preferência do usuário ou a configuração da JVM.
  • É criado com dois códigos ISO: a língua em minúsculas (ISO 639: pt, it, ja) e o país em maiúsculas (ISO 3166: BR, IT, CH). O mesmo idioma muda de país para país: it_IT × it_CH.
  • DateFormat.getDateInstance(estilo, locale) formata "como se estivesse lá". Diferenças pequenas, como a vírgula na Suíça, importam. Nos números, uma vírgula trocada muda o valor.
  • getDisplayCountry(locale) e getDisplayLanguage(locale) dão o nome do país e da língua traduzidos para outro Locale. Sem argumento, usam o Locale padrão.
  • De onde vem o Locale do usuário? Do cabeçalho Accept-Language que o navegador envia, ou de uma preferência que o usuário escolhe. Exemplo: a Amazon da Holanda permite escolher o inglês e traduz o site todo, inclusive a formatação.

116 · Números com NumberFormat

System.out.println(Locale.getDefault());          // en_US na máquina do William
String[] isoCountries = Locale.getISOCountries(); // todos os países suportados
String[] isoLanguages = Locale.getISOLanguages(); // todas as línguas (há menos línguas que países)

Locale localeBR = new Locale("pt", "BR");         // não existe Locale.BRAZIL
Locale localeJP = Locale.JAPAN;                   // constantes prontas: JAPAN, ITALY, FRANCE, GERMANY...
Locale localeIT = Locale.ITALY;
NumberFormat[] nfa = new NumberFormat[4];         // abstrata, como DateFormat
nfa[0] = NumberFormat.getInstance();              // Locale padrão
nfa[1] = NumberFormat.getInstance(localeJP);
nfa[2] = NumberFormat.getInstance(localeBR);
nfa[3] = NumberFormat.getInstance(localeIT);
double valor = 100_000_000.2130;                  // no código o separador decimal é SEMPRE o ponto
for (NumberFormat numberFormat : nfa) {
    System.out.println(numberFormat.format(valor));
}
// en_US e ja_JP: 100,000,000.213   ·   pt_BR e it_IT: 100.000.000,213
  • O pacote Rdatas ganhou um irmão, o Sformatacao, para a parte de internacionalização.
  • Locale.getDefault() mostra como o sistema operacional está configurado. getISOCountries() e getISOLanguages() listam o que é suportado. Há mais países que línguas, porque o português, por exemplo, é falado em vários países.
  • EUA e Japão usam vírgula no milhar e ponto no decimal. Brasil e Itália, o contrário.
  • No IntelliJ, getCompactNumberInstance aparece em vermelho no projeto da aula. Ele é do Java 12, e o language level do projeto está em 8. O que se vê no Java 8 cobre "uns 85%" dos casos.

117 · Moeda, casas decimais e parse

// NumberFormatTest01 (números)
double valor = 1_000.2130;
for (NumberFormat numberFormat : nfa) {
    numberFormat.setMaximumFractionDigits(2);          // padrão é 3 para números
    System.out.println(numberFormat.format(valor));    // 1,000.21 · 1,000.21 · 1.000,21 · 1.000,21
}
String valorString = "1000.2130";
try {
    System.out.println(nfa[0].parse(valorString));     // 1000.213 (String → Number)
} catch (ParseException e) {                           // checked!
    e.printStackTrace();
}

// NumberFormatTest02 (moeda)
nfa[0] = NumberFormat.getCurrencyInstance();           // $1,000.21 no en_US
nfa[1] = NumberFormat.getCurrencyInstance(localeJP);   // iene: 0 casas decimais
nfa[2] = NumberFormat.getCurrencyInstance(localeBR);   // R$ 1.000,21
nfa[3] = NumberFormat.getCurrencyInstance(localeIT);   // 1.000,21 €
for (NumberFormat numberFormat : nfa) {
    System.out.println(numberFormat.getMaximumFractionDigits());   // 2 · 0 · 2 · 2
    System.out.println(numberFormat.format(valor));
}
nfa[1].parse("1,000");   // ParseException: moeda precisa do símbolo (¥1,000)
  • getCurrencyInstance(locale) formata como dinheiro: símbolo, separadores e casas decimais do país.
  • Casas decimais: getMaximumFractionDigits() é 3 no número comum e 2 na moeda (dólar, real, euro). O iene tem 0. setMaximumFractionDigits(2) muda isso.
  • parse(String) faz o caminho inverso (texto → Number) e lança ParseException (checked, aulas 95–105). Ele lê do início e para no primeiro caractere inválido, ignorando o resto. Se o inválido estiver logo no começo, lança exceção.
  • O parse de moeda exige o formato de moeda, com o símbolo: "$1,000.21" no en_US, "￥1,000" no Japão. Sem o símbolo: Unparseable number.
  • O _ em 1_000.2130 só vale no código. Numa String para parse ele é um caractere inválido.
  • No banco, guarde o número, nunca o texto formatado ("R$ 1.000,21"). A formatação com o Locale acontece só na hora de exibir.

118 · SimpleDateFormat: formato sob medida

String pattern = "'Amsterdam' dd 'de' MMMM 'de' yyyy";   // texto fixo entre aspas simples
SimpleDateFormat sdf = new SimpleDateFormat(pattern);    // concreta: aqui tem new
System.out.println(sdf.format(new Date()));              // Amsterdam 15 de February de 2021 (Windows em inglês)
try {
    System.out.println(sdf.parse("Amsterdam 15 de February de 2021"));   // String → Date
} catch (ParseException e) {
    e.printStackTrace();
}
  • java.text.SimpleDateFormat (Java 1.1) é concreta e bem mais flexível que DateFormat. Ela recebe um padrão de letras (tabela na documentação).
  • Letras principais: G era (AD, "anno Domini"), y ano, M mês, d dia, E dia da semana, H hora 0–23, h hora 1–12, m minuto, s segundo, a AM/PM, z fuso.
  • Quantidade de letras: MM = 02, MMM = fev (abreviado), MMMM = fevereiro (por extenso). yyyy = 2021.
  • Texto fixo vai entre aspas simples ('Amsterdam', 'de'), porque senão letras como a e m seriam interpretadas.
  • parse segue o mesmo padrão e lança ParseException se o texto não bater (por exemplo, sem o "Amsterdam"). Útil para relatórios com formato customizado.

Atenção

  • MM é mês, mm é minuto. "dd/mm/yyyy" é um bug clássico. O certo é "dd/MM/yyyy". Também: HH (0–23) × hh (1–12, precisa do a).
  • Extra: no Calendar o mês começa em 0. c.get(Calendar.MONTH) em fevereiro dá 1. Use Calendar.FEBRUARY, nunca o número.
  • DateFormat e NumberFormat são abstratas (use getXxxInstance). SimpleDateFormat é concreta.
  • Os parses (NumberFormat, SimpleDateFormat) lançam ParseException, que é checked. Por isso o try/catch.
  • Extra: SimpleDateFormat não é thread-safe. Não guarde um em atributo static compartilhado. O DateTimeFormatter do java.time (aula 129) é.
  • Extra: new Locale("pt", "BR") é deprecated no Java 19+. Use Locale.of("pt", "BR") ou Locale.forLanguageTag("pt-BR").
  • Extra: para forçar o Locale e o fuso ao rodar: java -Duser.language=pt -Duser.country=BR e a variável TZ=America/Sao_Paulo.

Paralelo com PHP

  • Epoch: time() no PHP devolve segundos. Em Java, new Date().getTime() e System.currentTimeMillis() devolvem milissegundos. Ao trocar timestamps com uma API PHP, multiplique ou divida por 1000.
  • Letras de formato diferentes: PHP date('d/m/Y H:i') ≈ Java "dd/MM/yyyy HH:mm". No PHP, m é mês e i é minuto. No Java, M é mês e m é minuto. Cuidado ao traduzir de cabeça.
  • Calendar.add ≈ $dt->modify('+2 days') ou o addDays(2) do Carbon. DateTime do PHP também é mutável. DateTimeImmutable/CarbonImmutable são o espírito do java.time.
  • Locale: a extensão intl tem NumberFormatter (≈ NumberFormat, com CURRENCY) e IntlDateFormatter (≈ DateFormat com estilos FULL/LONG...). number_format($v, 2, ',', '.') é a versão "na mão".
  • Laravel: App::setLocale('pt_BR'), a middleware que lê o Accept-Language, Carbon::setLocale + translatedFormat() e Number::currency(1000.21, 'BRL', 'pt_BR') (Laravel 11). E a mesma regra: guarde o número no banco e formate na view.

package academy.devdojo.maratonajava.javacore.Sformatacao.test;

import java.text.DateFormat;
import java.text.NumberFormat;
import java.text.ParseException;
import java.text.SimpleDateFormat;
import java.util.Calendar;
import java.util.Date;
import java.util.Locale;

public class DatasLegadasTest01 {
    public static void main(String[] args) throws ParseException {
        Locale ptBR = new Locale("pt", "BR");
        SimpleDateFormat br = new SimpleDateFormat("dd/MM/yyyy HH:mm", ptBR);

        // 112 · Date
        Date date = new Date(1613061109953L);
        date.setTime(date.getTime() + 3_600_000);
        System.out.println(date);                                        // ?

        // 113 · Calendar
        Calendar c = Calendar.getInstance(ptBR);
        c.setTime(new Date(1613061109953L));
        System.out.println(c.get(Calendar.DAY_OF_WEEK));                 // ?
        System.out.println(c.get(Calendar.DAY_OF_YEAR));                 // ?
        System.out.println(c.get(Calendar.MONTH));                       // ? (pegadinha)
        c.add(Calendar.DAY_OF_MONTH, 20);
        System.out.println(br.format(c.getTime()));                      // ?
        c.setTime(new Date(1613061109953L));
        c.roll(Calendar.DAY_OF_MONTH, 20);
        System.out.println(br.format(c.getTime()));                      // ?

        // 114/115 · DateFormat + Locale
        Date d = new Date(1613061109953L);
        System.out.println(DateFormat.getDateInstance(DateFormat.SHORT, ptBR).format(d)); // ?
        System.out.println(DateFormat.getDateInstance(DateFormat.FULL, ptBR).format(d));  // ?
        System.out.println(DateFormat.getDateInstance(DateFormat.FULL, Locale.ITALY).format(d));
        System.out.println(Locale.ITALY.getDisplayCountry(ptBR));        // ?

        // 116/117 · NumberFormat
        double valor = 1_000.2130;
        NumberFormat nf = NumberFormat.getInstance(ptBR);
        System.out.println(nf.getMaximumFractionDigits());               // ?
        System.out.println(nf.format(valor));                            // ?
        nf.setMaximumFractionDigits(2);
        System.out.println(nf.format(valor));                            // ?
        System.out.println(NumberFormat.getInstance(Locale.JAPAN).format(valor));
        System.out.println(NumberFormat.getCurrencyInstance(ptBR).format(valor));
        System.out.println(NumberFormat.getCurrencyInstance(Locale.JAPAN).getMaximumFractionDigits()); // ?
        System.out.println(NumberFormat.getInstance(Locale.US).parse("1000.2130abc"));                // ?

        // 118 · SimpleDateFormat
        SimpleDateFormat sdf = new SimpleDateFormat("'Amsterdam' dd 'de' MMMM 'de' yyyy", ptBR);
        System.out.println(sdf.format(d));                               // ?
        System.out.println(sdf.parse("Amsterdam 15 de fevereiro de 2021"));  // ?
    }
}

Glossário

  • Epoch: 1º de janeiro de 1970, 00:00 UTC; o ponto zero do Date.
  • Legado: sistema ou API antiga que continua em uso e precisa ser mantida.
  • Internacionalização (i18n): preparar o sistema para vários idiomas e formatos regionais.
  • Locale: combinação língua + país (pt_BR, it_CH) que define formatos.
  • ISO 639 / ISO 3166: padrões dos códigos de língua (pt) e de país (BR).
  • add × roll: somar virando o campo de cima × somar dando a volta só no campo.
  • Padrão (pattern): a String de letras que define o formato no SimpleDateFormat.
  • Parse: converter texto em objeto (Number, Date); lança ParseException.
  • Accept-Language: cabeçalho HTTP em que o navegador informa os idiomas preferidos.
