Resumo

Começa o banco de dados. O foco do curso é o JDBC, e não o MySQL em si (o professor recomenda uma pesquisa rápida sobre o que é e como funciona um banco). Estas cinco aulas montam o ambiente: o MySQL roda num container Docker, o banco e as tabelas são criados no MySQL Workbench, o projeto passa a usar Maven para baixar o driver do MySQL, e no fim o Java abre a primeira conexão.

docker-compose up                      // 253 · sobe o MySQL num container
CREATE SCHEMA anime_store;             // 254 · banco + tabelas producer e anime
pom.xml → mysql-connector-java         // 255–256 · Maven baixa o driver
DriverManager.getConnection("jdbc:mysql://localhost:3306/anime_store", "root", "root"); // 256

252 · Instalando Docker

  • Dá para instalar o MySQL nativamente (instalador em dev.mysql.com/downloads/installer), e quem tiver problemas com Docker pode fazer isso. Lembre do usuário e da senha que definir na instalação.
  • O curso usa Docker porque "uma vez que você aprende, não instala mais nada no seu computador": banco, Grafana e outras ferramentas viram containers (o curso de Spring Boot da DevDojo usa bastante). E para parar é só Ctrl+C no terminal, sem caçar processo no gerenciador de tarefas.
  • Container × máquina virtual: numa VM (VirtualBox, VMware), o hypervisor roda um sistema operacional completo para cada máquina, e três VMs são três sistemas operacionais dividindo os recursos do seu computador. No Docker, o Docker Engine reaproveita bibliotecas e funcionalidades do sistema existente, e cada container é como "uma máquina virtual bem pequena", só com o necessário para rodar a aplicação.
  • Instalação no Windows: Docker Desktop (a versão gratuita). Pode pedir para reiniciar e para ativar a virtualização na BIOS (hardware-assisted virtualization); o professor precisou fazer isso. Quando o ícone da baleia para de se mexer, o Docker está pronto.
  • O Docker Desktop é um pouco pesado: com menos de 6 GB de RAM, o professor aconselha instalar o MySQL nativo.

253 · Criando o container MySQL

Na raiz do projeto, um arquivo docker-compose.yml (o nome importa). YAML é um formato em que a indentação é a sintaxe: um espaço a mais e o arquivo não funciona. Na dúvida, copie o arquivo do repositório.

version: '2.4'
services:
  db:                                  # nome do serviço (qualquer um)
    image: mysql                       # imagem do Docker Hub; sem tag = a mais recente
    container_name: mysql
    environment:
      MYSQL_ROOT_PASSWORD: root        # senha do usuário root
    ports:
      - "3306:3306"                    # porta do SEU PC : porta do container
    volumes:
      - devdojo_maratona_data:/var/lib/mysql   # os dados ficam fora do container

volumes:
  devdojo_maratona_data:
  • version: '2.4': as versões 3.x foram pensadas para orquestradores (Docker Swarm, Kubernetes); para rodar imagens direto, a 2.4 é a indicada.
  • image: mysql: vem do Docker Hub (hub.docker.com), onde há imagem de praticamente tudo (Postgres, MariaDB...). Sem versão, pega a última; com versão, mysql:8.0.25.
  • environment: variáveis que a imagem lê ao iniciar. A documentação da imagem lista quais existem, como MYSQL_ROOT_PASSWORD. O professor não usou o restart: always do exemplo da documentação: quando ele parar o container, quer que pare mesmo.
  • ports: "3306:3306": o primeiro número é a porta no seu computador, o segundo é a porta dentro do container. Se a 3306 do seu PC já estiver ocupada (um MySQL instalado, por exemplo), use "3307:3306" e conecte na 3307. (Extra: a legenda deixa confuso qual lado é qual; a regra é HOST:CONTAINER.)
  • volumes: o container é descartável, e matar o container apagaria os dados. O volume nomeado guarda /var/lib/mysql fora dele, e o nome identifica o volume de cada projeto.
docker ps                    # containers rodando (vazio no começo)
docker-compose up            # baixa a imagem (em camadas) e sobe o container
docker ps                    # agora aparece o mysql, com a porta 3306
# Ctrl+C                     # para o container
docker ps -a                 # lista também os parados
docker-compose down          # remove o container (os dados continuam no volume)
docker volume ls             # o volume aparece com o prefixo do projeto: maratona-java_devdojo_maratona_data

254 · Workbench, schema e tabelas

O container é o servidor de banco, onde os dados ficam. Para criar tabelas e mexer nos dados de forma visual, é preciso um cliente. O professor usa o MySQL Workbench (existem outros).

  • Nova conexão: host 127.0.0.1 (localhost), porta 3306, usuário root, senha root (guardada no vault), e depois Test Connection.
  • A tela mostra o status do servidor. Parando o container (Ctrl+C) e atualizando, o status vira "parado"; com docker-compose up de novo, volta a rodar. É fácil liberar os recursos quando você não está estudando.
  • Criar o banco: no Workbench um schema é um banco de dados. O nome é anime_store, em minúsculas e com underscore, um padrão comum em banco.
  • Duas tabelas: producer (produtor) e anime. Um produtor produz um ou vários animes; um anime tem um produtor (um-para-muitos). Na vida real um anime pode ter vários produtores, mas o exemplo fica simples.
CREATE SCHEMA anime_store;

CREATE TABLE anime_store.producer (
  id   INT          NOT NULL AUTO_INCREMENT,   -- PK: identifica o registro
  name VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);

CREATE TABLE anime_store.anime (
  id          INT          NOT NULL AUTO_INCREMENT,
  name        VARCHAR(300) NOT NULL,           -- "nome de anime ultimamente está complicado"
  episodes    INT          NOT NULL,
  producer_id INT          NOT NULL,           -- mesmo tipo da coluna referenciada
  PRIMARY KEY (id),
  CONSTRAINT fk_anime_producer
    FOREIGN KEY (producer_id) REFERENCES anime_store.producer (id)
);

SELECT * FROM anime;          -- erro: "No database selected"
USE anime_store;              -- no Workbench: botão direito no schema → Set as Default Schema
SELECT * FROM anime;          -- agora funciona
  • PK (primary key), NN (not null) e AI (auto increment, o próprio MySQL numera) são as caixinhas do Workbench. Ao aplicar, ele mostra o SQL gerado.
  • Chave estrangeira (aba Foreign Keys): a coluna producer_id de anime referencia producer.id. Assim nenhum anime pode apontar para um produtor que não existe.
  • Num trecho regravado, o professor avisa que nesse ponto "deu capim na palheta", um erro que ele só percebeu na aula 279: a coluna producer_id da tabela anime tem que referenciar a coluna id da tabela producer. O SQL acima já está do jeito certo.
  • Extra: o script SQL acima é o equivalente do que foi feito clicando no Workbench (o nome da constraint é livre). Na prática abaixo ele é executado sem Workbench.

255 · Maven

JDBC (Java Database Connectivity) é a API que o Java criou para padronizar a conexão com qualquer banco (Oracle, MySQL, PostgreSQL, SQL Server, MariaDB, H2, Cassandra...). O pacote java.sql define interfaces (Connection, Statement, ResultSet, existentes desde o Java 1.1) e a classe DriverManager. Cada fabricante (vendor) escreve a implementação, o driver, distribuído como um .jar. Seu código usa só as interfaces, e trocar de banco é trocar o driver (desde que você não use recursos exclusivos de um banco). É a interface da aula 87 aplicada em grande escala.

O driver do MySQL (Connector/J) poderia ser baixado à mão no site, mas "fazer download manual de bibliotecas hoje em dia é coisa de louco": a cada versão nova seria preciso baixar, colocar numa pasta e reconfigurar. Por isso entra um gerenciador de dependências, o Maven. Dependência é uma biblioteca sem a qual o projeto não funciona.

  • Instalar: baixar o binary zip em maven.apache.org (na gravação, 3.8.1), extrair numa pasta e criar variáveis de ambiente: M2_HOME (a pasta do Maven, sem a barra no fim), M2 = %M2_HOME%\bin, e adicionar %M2% ao Path. Teste com mvn --version, que mostra também o Java encontrado (15, no curso).
  • No IntelliJ: botão direito no projeto, Add Framework Support, Maven. A estrutura muda para o padrão do Maven: src/main/java (código), src/main/resources (arquivos de configuração) e src/test/java (testes). O professor diz que tudo continua funcionando normalmente.
  • Pegadinha: os arquivos messages*.properties do ResourceBundle (aula 130) param de ser encontrados. É preciso movê-los para src/main/resources.
  • Surge o pom.xml (Project Object Model), o arquivo de configuração do Maven, em XML (linguagem de marcação):
<project ...>
    <modelVersion>4.0.0</modelVersion>
    <groupId>academy.devdojo</groupId>           <!-- geralmente o pacote base -->
    <artifactId>maratona-java</artifactId>       <!-- nome do projeto -->
    <version>1.0-SNAPSHOT</version>              <!-- SNAPSHOT = em desenvolvimento -->
    <properties>
        <maven.compiler.source>15</maven.compiler.source>
        <maven.compiler.target>15</maven.compiler.target>
    </properties>
</project>

256 · Dependência e conexão com o banco

<dependencies>
    <dependency>
        <groupId>mysql</groupId>
        <artifactId>mysql-connector-java</artifactId>
        <version>8.0.25</version>
    </dependency>
</dependencies>
  • O trecho vem do Maven Repository (mvnrepository.com): procure "mysql connector java", escolha a versão e copie o XML. O professor tenta usar a mesma versão do servidor (o docker-compose up mostrou 8.0.25).
  • Fica vermelho até o IntelliJ "carregar as mudanças do Maven" (botão de recarregar ou Ctrl+Shift+O). Aí aparecem em External Libraries o conector e também o protobuf do Google, uma dependência transitiva que o conector usa, e o Maven baixa sozinho.
  • Tudo vai para o repositório local ~/.m2/repository (no Windows, C:\Users\você\.m2). Se outra versão já estiver lá, não baixa de novo.
public class ConnectionFactory {
    //java.sql = Connection, Statement, ResultSet, DriverManager
    public static Connection getConnection() {
        String url = "jdbc:mysql://localhost:3306/anime_store";
        String username = "root";
        String password = "root";
        try {
            Connection connection = DriverManager.getConnection(url, username, password);
            System.out.println(connection);   // com.mysql.cj.jdbc.ConnectionImpl@...
        } catch (SQLException e) {
            e.printStackTrace();
        }
        return null;
    }
}

public class ConnectionFactoryTest {
    public static void main(String[] args) {
        ConnectionFactory.getConnection();
    }
}
  • A URL JDBC: jdbc: + vendor (mysql) + ://host:porta/banco. Cada banco tem seu formato (veja a documentação do fabricante): jdbc:postgresql://localhost:5432/banco, por exemplo. Se você mapeou a 3307, a URL usa 3307.
  • DriverManager.getConnection(url, usuario, senha) procura, entre os drivers no classpath, um que aceite aquela URL, e devolve uma Connection. Imprimir mostra a classe do MySQL (ConnectionImpl) por trás da interface.
  • SQLException é checked. O container precisa estar rodando, senão vem Communications link failure.
  • O nome ConnectionFactory é o padrão Factory da aula 247.

Atenção

  • Neste primeiro teste, getConnection() imprime a conexão e devolve null, e a conexão nunca é fechada. O professor corrige na aula 257: o método passa a throws SQLException e faz return DriverManager.getConnection(...). Toda conexão deve ser fechada, com try-with-resources (aula 103), porque Connection é AutoCloseable.
  • YAML: indentação é sintaxe. Use espaços, nunca tabs.
  • ports é HOST:CONTAINER. A URL do Java usa a porta do host.
  • docker-compose down não apaga os dados (estão no volume); docker-compose down -v apaga o volume junto.
  • Extra: fixe a versão da imagem (image: mysql:8.0). Sem tag, cada docker pull pode trazer uma versão nova e diferente do driver.
  • Extra: o artefato mudou de nome. Desde a versão 8.0.31 o conector é com.mysql:mysql-connector-j; o mysql:mysql-connector-java da aula foi descontinuado (redireciona para o novo). Em projeto novo, use o novo.
  • Extra: docker-compose × docker compose. O comando com hífen é o antigo (Compose v1, um programa separado); hoje ele vem embutido no Docker como docker compose, e o campo version: do arquivo é ignorado.
  • Extra: senha no código (root/root) só serve para estudo. Em projeto real ela vem de variável de ambiente ou arquivo de configuração fora do Git, como o .env do Laravel.

Paralelo com PHP

  • Docker: o Laravel Sail é exatamente isso, um docker-compose.yml com MySQL, Redis etc. (./vendor/bin/sail up). O ports, o environment e os volumes são os mesmos conceitos.
  • Maven ≈ Composer: pom.xml ≈ composer.json; <dependency> ≈ uma linha em require; mvnrepository.com/Maven Central ≈ packagist.org; ~/.m2/repository ≈ o cache do Composer + a pasta vendor; dependência transitiva (o protobuf) ≈ as dependências das dependências que aparecem no composer.lock. groupId:artifactId ≈ vendor/pacote. O Maven também compila e empacota (é uma build tool), algo que o PHP não precisa.
  • JDBC ≈ PDO: o PDO também é uma API única com um driver por banco (pdo_mysql, pdo_pgsql). A URL JDBC é o DSN do PDO: new PDO('mysql:host=127.0.0.1;port=3306;dbname=anime_store', 'root', 'root') ≈ DriverManager.getConnection("jdbc:mysql://localhost:3306/anime_store", "root", "root"). No Laravel, isso fica no .env (DB_CONNECTION, DB_HOST, DB_PORT, DB_DATABASE...).
  • Tabelas: no Laravel você não clicaria no Workbench, escreveria uma migration ($table->id(); $table->string('name', 300); $table->foreignId('producer_id')->constrained();). No mundo Java, o equivalente de migrations são ferramentas como Flyway e Liquibase.

Glossário

  • Docker: plataforma que roda aplicações em containers.
  • Container: processo isolado com só o necessário para a aplicação; mais leve que uma VM.
  • Imagem: o "molde" do container (ex.: mysql:8.0), baixado do Docker Hub em camadas.
  • docker-compose.yml: arquivo que descreve serviços, portas, variáveis e volumes.
  • Volume: armazenamento fora do container, que sobrevive à remoção dele.
  • Schema: no MySQL, sinônimo de banco de dados.
  • Chave primária (PK): coluna que identifica cada registro.
  • Chave estrangeira (FK): coluna que referencia a PK de outra tabela.
  • JDBC: API Java (java.sql) para conectar a bancos de forma padronizada.
  • Driver: implementação do JDBC feita pelo fabricante do banco (.jar).
  • Maven: ferramenta de build e gerenciador de dependências; configurado pelo pom.xml.
  • Dependência transitiva: dependência de uma dependência, baixada automaticamente.
  • URL JDBC: endereço de conexão, jdbc:vendor://host:porta/banco.
