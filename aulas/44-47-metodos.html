Resumo

Até aqui as classes só tinham atributos (características). Métodos são o comportamento: o que o objeto sabe fazer. O exemplo das quatro aulas é uma Calculadora, no pacote novo javacore.Bintroducaometodos (com dominio e test, como antes). A analogia que o William repete: "corte esta maçã". Para cortar, eu preciso te dar a maçã (parâmetro). Depois, você pode me devolver os pedaços (retorno) ou ficar com eles (void).

44 · Anatomia e chamada

public class Calculadora {
//  acesso  retorno  nome              (parâmetros)
    public  void     somaDoisNumeros() {
        System.out.println(10 + 10);   // corpo
    }

    public void subtraiDoisNumeros() {
        System.out.println(21 - 2);
    }
}

// CalculadoraTest01
Calculadora calculadora = new Calculadora();
calculadora.somaDoisNumeros();       // 20
System.out.println("Finalizando CalculadoraTest01");
calculadora.subtraiDoisNumeros();    // 19
  • As partes de um método: modificador de acesso (public), tipo de retorno, nome, parênteses com os parâmetros e o corpo entre chaves.
  • void significa "vazio": o método executa, mas não devolve nada para quem chamou.
  • Retorno não é saída. Imprimir no console é uma saída. Devolver um valor para quem chamou é retorno. Um método void pode imprimir e ainda assim não retornar nada.
  • O nome segue a convenção das variáveis: camelCase, começando com minúscula.
  • Para chamar, use a variável de referência, o ponto, o nome e os parênteses: calculadora.somaDoisNumeros();. Atributo não tem parênteses e recebe valor com =. Método tem parênteses.
  • O fluxo: ao chegar na chamada, a execução entra no método, roda o corpo e volta para a linha seguinte de quem chamou. O debug (Shift+F9, F8) mostra esse vai e volta.
  • O método roda no objeto para o qual a variável aponta. Ctrl+B (ou Ctrl+clique) no nome abre o método na classe.

45 · Parâmetros e argumentos

public void multiplicaDoisNumeros(int num1, int num2) {
    System.out.println(num1 * num2);
}

calculadora.multiplicaDoisNumeros(10, 20);   // 200
  • Parâmetros são variáveis locais do método, que só existem enquanto ele executa. A sintaxe é igual à de declarar variável: tipo nome. Pode ser qualquer primitivo, referência ou array.
  • Cada parâmetro precisa do seu tipo: (int num1, num2) não compila. O certo é (int num1, int num2).
  • Parâmetro × argumento: na declaração (int num1) é parâmetro. Na chamada (10) é argumento. No IntelliJ, Ctrl+P mostra o que o método espera.
  • Passar um argumento é como uma atribuição (num1 = 10), e as mesmas regras de tipo valem: um double num parâmetro int não compila (com cast compila, mas "é muito feio"). Um int num parâmetro float entra sem problema. Já 20.5 precisa de F.
  • A assinatura é um contrato: "para eu funcionar, me passe dois ints". Quem chama não precisa saber como o método faz, e ele pode até chamar outro sistema. Se o contrato mudar (por exemplo, um terceiro parâmetro), todas as chamadas antigas param de compilar.
  • O método não sabe que valores vão chegar. Pense no que pode vir errado, como uma divisão por zero.
  • Boa prática: mais de três parâmetros costuma indicar um método fazendo coisa demais. Divida em métodos menores.

46 · Retorno

public double divideDoisNumeros(double num1, double num2) {
    if (num2 == 0) {
        return 0;          // sai do método aqui e devolve 0
    }
    return num1 / num2;
}

double resultado = calculadora.divideDoisNumeros(20, 2);   // 10.0
System.out.println(resultado);
System.out.println(calculadora.divideDoisNumeros(20, 2));  // direto no println
  • No lugar de void, qualquer tipo (primitivo ou referência) diz o que o método devolve.
  • Com tipo de retorno, o return é obrigatório. Sem ele, não compila. return 0; já basta para compilar.
  • Chamar o método e ignorar o retorno é permitido (calculadora.divideDoisNumeros(20, 2);), mas não acontece nada visível: o valor volta e é descartado.
  • O retorno é tratado como um valor comum: dá para guardar numa variável ou usar direto. As regras de cast valem: um double devolvido não cabe num int sem (int). Se o método declarar int, o return num1 / num2 com doubles precisa de cast.
  • Com double, dividir por zero dá Infinity e não gera erro. Por isso a validação if (num2 == 0) return 0;.
  • O return funciona como um break do método: ao executá-lo, o método termina na hora e volta para quem chamou. As linhas seguintes não rodam.

47 · Mais sobre retorno e o return em void

// Três jeitos de fazer a mesma coisa:
if (num2 == 0) { return 0; } return num1 / num2;              // aula 46
if (num2 == 0) { return 0; } else { return num1 / num2; }     // com else
if (num2 != 0) { return num1 / num2; } return 0;              // lógica invertida

public void imprimeDivisaoDeDoisNumeros(double num1, double num2) {
    if (num2 == 0) {
        System.out.println("Não existe divisão por zero");
        return;            // em void: só "sai do método", sem valor
    }
    System.out.println(num1 / num2);
}
  • As três versões dão o mesmo resultado. Lógica de programação é individual, e com experiência você cria seu próprio estilo.
  • return; sem valor também funciona em métodos void, para encerrar mais cedo. Sem ele (e sem else), a execução continuaria e imprimiria Infinity.
  • break dentro de um if que não está em laço nem switch não compila. Para sair de método, use return.
  • Um método void não pode ir dentro de um println: System.out.println(calculadora.imprimeDivisaoDeDoisNumeros(86, 5)); não compila, porque não há valor para imprimir.
  • O estilo do William: validações no começo do método, parando a execução logo se algo estiver errado, e a lógica de negócio depois. É o que se chama de guard clause.

Atenção

  • calculadora.somaDoisNumeros sem parênteses não compila. Com parênteses é chamada de método, sem é acesso a atributo.
  • Extra: "missing return statement". Se o return estiver só dentro de um if, o compilador reclama, porque existe um caminho sem retorno. Todo caminho precisa de um return.
  • Extra: código depois de return no mesmo bloco não compila (unreachable statement).
  • Extra: divisão por zero depende do tipo. Com double dá Infinity (ou NaN em 0/0), sem erro. Com int lança ArithmeticException. O método da aula recebe double.
  • Extra: o tipo de retorno não faz parte da assinatura. A assinatura é o nome mais os tipos dos parâmetros. Isso vai importar na sobrecarga (aula 57).
  • Extra: o parâmetro recebe uma cópia do valor. Mudar num1 dentro do método não altera a variável de quem chamou. Com referências a história tem nuances (aulas 48–50).

Paralelo com PHP

  • Sintaxe: public function divide(float $a, float $b): float vira public double divide(double a, double b). Em Java não existe a palavra function, e o tipo de retorno vem antes do nome.
  • void existe nas duas. Em PHP, sem return o método devolve null. Em Java, método com tipo de retorno e sem return não compila.
  • Tipos dos argumentos: sem strict_types, o PHP converte "10" em 10 sozinho. O Java só aceita tipos compatíveis e verifica na compilação.
  • Sem parâmetros opcionais nem nomeados: function x($a, $b = 0) e x(b: 2, a: 1) não existem em Java. O equivalente é a sobrecarga (aula 57), com vários métodos de mesmo nome e parâmetros diferentes.
  • Divisão por zero: no PHP 8, 1 / 0 lança DivisionByZeroError. Em Java, com double dá Infinity em silêncio.
  • Guard clauses (if (!$user) return; no começo) são as mesmas nas duas linguagens.

Glossário

  • Método: bloco de código de uma classe que define um comportamento.
  • Tipo de retorno: o tipo do valor que o método devolve, ou void.
  • void: "vazio", o método não devolve nada.
  • Parâmetro: variável declarada nos parênteses do método.
  • Argumento: valor passado na chamada.
  • Assinatura: nome mais os tipos dos parâmetros, o "contrato" do método.
  • return: encerra o método e, se houver tipo de retorno, devolve o valor.
  • Guard clause: validação no começo que sai do método cedo com return.
