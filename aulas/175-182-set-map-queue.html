Resumo

Além da List, o Java tem três famílias. Set é uma coleção sem elementos repetidos. Map associa chave → valor, e tecnicamente não é uma Collection. Queue é uma fila. Em cada família, o nome da implementação diz como ela organiza os dados:

Hash...        → usa hashCode/equals · SEM ordem garantida · O(1)
LinkedHash...  → usa hash, mas LEMBRA a ordem de inserção
Tree...        → árvore ORDENADA pelo compareTo/Comparator · O(log n) · navegável (lower, floor, higher, ceiling)

Set:   HashSet · LinkedHashSet · TreeSet (NavigableSet)
Map:   HashMap · LinkedHashMap · TreeMap (NavigableMap)
Queue: PriorityQueue (sai pela prioridade do Comparable/Comparator)

175 · LinkedList, Set e HashSet

List<Manga> mangas = new LinkedList<>();   // troca de implementação: o resto do código não muda

Set<Manga> mangas = new HashSet<>();       // sem repetidos, sem índice, sem ordem garantida
mangas.add(new Manga(5L, "Hellsing Ultimate", 19.9, 0));
mangas.add(new Manga(1L, "Berserk", 9.5, 5));
mangas.add(new Manga(2L, "Dragon ball Z", 2.99, 0));
mangas.add(new Manga(2L, "Dragon ball Z", 2.99, 0));   // repetido: IGNORADO (equals/hashCode)
for (Manga manga : mangas) {               // não existe get(i): só percorrer
    System.out.println(manga);
}

Set<Manga> ordemInsercao = new LinkedHashSet<>();   // hash + mantém a ordem de inserção

// equals/hashCode do Manga regerados só com id e nome (o preço pode mudar sem virar outro produto):
return Objects.equals(id, manga.id) && Objects.equals(nome, manga.nome);
return Objects.hash(id, nome);
  • A vantagem de programar para a interface: trocar ArrayList por LinkedList é mudar só o new. A LinkedList é uma lista em que cada elemento conhece o anterior e o próximo, então remover é mais barato que no ArrayList (Big-O, aula 165).
  • Set não aceita duplicados. Antes de inserir, ele verifica com equals/hashCode, e se já existir, ignora. Útil para eliminar repetidos que vieram, por exemplo, do banco.
  • Não é indexado: não há get(i). Você percorre com foreach.
  • HashSet: a ordem depende do hash e pode mudar conforme você insere. LinkedHashSet: mesmo esquema, mas mantém a ordem de inserção (5, 1, 4, 3, 2).
  • O que é "repetido" é decisão sua, no equals. Com o preço no equals, o mesmo mangá com preço novo viraria outro produto. Por isso o William regerou usando só id e nome.

176 · TreeSet e NavigableSet

// Smartphone não é Comparable:
// NavigableSet<Smartphone> set = new TreeSet<>();  set.add(smartphone);   → ClassCastException

class SmartphoneMarcaComparator implements Comparator<Smartphone> {
    @Override
    public int compare(Smartphone o1, Smartphone o2) {
        return o1.getMarca().compareTo(o2.getMarca());
    }
}
NavigableSet<Smartphone> set = new TreeSet<>(new SmartphoneMarcaComparator());   // agora funciona
set.add(new Smartphone("123", "Nokia"));

NavigableSet<Manga> mangas = new TreeSet<>();       // Manga é Comparable (compareTo por nome)
mangas.add(new Manga(5L, "Hellsing Ultimate", 19.9, 0));
... (Berserk, Pokemon, Attack on titan, Dragon ball Z)
mangas.add(new Manga(10L, "Aaragon", 2.99, 0));      // inserido por último...
mangas.add(new Manga(10L, "Aaragon", 10.0, 0));      // mesmo nome → ignorado
// Aaragon · Attack on titan · Berserk · Dragon ball Z · Hellsing Ultimate · Pokemon  ← sempre ordenado
  • SortedSet → NavigableSet → TreeSet. Continua sendo um Set (sem repetidos), mas reordena a cada inserção.
  • Classes com "Tree" no nome precisam saber comparar: o elemento é Comparable ou você passa um Comparator no construtor. Sem isso: ClassCastException.
  • O "Aaragon" entrou por último e saiu primeiro na impressão, porque a ordem é a do compareTo (nome).
  • Desempenho: O(log n) para inserir e buscar. Não é constante como o hash, mas continua bom.

177 · O contrato quebrado e a navegação

class MangaPrecoComparator implements Comparator<Manga> {
    @Override
    public int compare(Manga o1, Manga o2) {
        return Double.compare(o1.getPreco(), o2.getPreco());
    }
}
NavigableSet<Manga> mangas = new TreeSet<>(new MangaPrecoComparator());
// Hellsing 19.9 · Berserk 9.5 · Pokemon 3.2 · Attack 11.2 · Dragon ball Z 2.99 · Aaragon 2.99
// Aaragon NÃO entra: mesmo PREÇO que o Dragon ball Z → compare == 0 → "repetido"
// 2.99 Dragon ball Z · 3.2 Pokemon · 9.5 Berserk · 11.2 Attack on titan · 19.9 Hellsing Ultimate

Manga yuyu = new Manga(21L, "Yuyu Hakusho", 3.2, 5);
// lower <   floor <=   higher >   ceiling >=
System.out.println(mangas.lower(yuyu));     // Dragon ball Z (2.99)  estritamente menor
System.out.println(mangas.floor(yuyu));     // Pokemon (3.2)         menor ou igual
System.out.println(mangas.higher(yuyu));    // Berserk (9.5)         estritamente maior
System.out.println(mangas.ceiling(yuyu));   // Pokemon (3.2)         maior ou igual
System.out.println(mangas.size());          // 5
System.out.println(mangas.pollLast());      // Hellsing Ultimate: devolve E REMOVE o último
System.out.println(mangas.size());          // 4
// mangas.descendingSet() → a ordem invertida · pollFirst() → devolve e remove o primeiro
  • A pegadinha: o TreeSet não usa o equals para decidir se é repetido. Ele usa o compareTo/compare. Se o critério de ordem dá 0, o elemento é descartado, mesmo com equals falso. A documentação diz que ele "falha em obedecer o contrato do Set". Escolha o critério pensando nisso.
  • Métodos de navegação (pelo critério de ordem, aqui o preço): lower (<), floor (≤), higher (>) e ceiling (≥). Devolvem null se não houver.
  • pollFirst/pollLast devolvem e removem o primeiro ou o último. descendingSet() inverte a ordem.

178 · Map, HashMap e LinkedHashMap

Map<String, String> map = new LinkedHashMap<>();   // <TipoDaChave, TipoDoValor>
map.put("teklado", "teclado");                     // "corretor ortográfico"
map.put("mouze", "mouse");
map.put("vc", "você");
map.put("vc", "você!");                            // chave repetida: SOBRESCREVE o valor
map.putIfAbsent("vc2", "você");                    // só insere se a chave não existir (Java 8)
System.out.println(map);                           // {teklado=teclado, mouze=mouse, vc=você!, vc2=você}

for (String key : map.keySet()) {                  // keySet(): Set das chaves (únicas)
    System.out.println(key + " : " + map.get(key));
}
for (String value : map.values()) {                // values(): Collection dos valores (podem repetir)
    System.out.println(value);
}
for (Map.Entry<String, String> entry : map.entrySet()) {   // chave E valor juntos
    System.out.println(entry.getKey() + " - " + entry.getValue());
}
  • Map<K, V> guarda pares chave → valor. Não é uma Collection: não aparece na hierarquia dela, mesmo sendo "uma coleção de dados".
  • Chaves únicas (via equals/hashCode da chave). Diferente do Set, que ignora o repetido, o Map sobrescreve o valor. Para não sobrescrever: putIfAbsent.
  • Três formas de percorrer: keySet() devolve um Set (chaves não repetem) e você pega o valor com get. values() devolve uma Collection (valores podem repetir). entrySet() devolve os pares Map.Entry, com getKey()/getValue(). É o melhor quando você precisa dos dois.
  • Ir do valor para a chave não é algo natural no Map. O fluxo é sempre chave → valor.
  • HashMap não garante ordem. LinkedHashMap mantém a ordem de inserção.

179–180 · Map com objetos e Map de List

public class Consumidor {
    private Long id;
    private String nome;
    public Consumidor(String nome) {
        this.id = ThreadLocalRandom.current().nextLong(0, 100_000);   // id aleatório de 0 a 99.999
        this.nome = nome;
    }
    // equals/hashCode só pelo id
}

// 179: cada consumidor comprou UM mangá
Map<Consumidor, Manga> consumidorManga = new HashMap<>();
consumidorManga.put(consumidor1, manga1);     // William Suane - Hellsing Ultimate
consumidorManga.put(consumidor2, manga4);     // DevDojo Academy - Attack on titan
for (Map.Entry<Consumidor, Manga> entry : consumidorManga.entrySet()) {
    System.out.println(entry.getKey().getNome() + " - " + entry.getValue().getNome());
}

// 180: cada consumidor comprou VÁRIOS → o valor é uma lista
Map<Consumidor, List<Manga>> consumidorMangaMap = new HashMap<>();
consumidorMangaMap.put(consumidor1, List.of(manga1, manga2, manga3));
consumidorMangaMap.put(consumidor2, List.of(manga3, manga4));
for (Map.Entry<Consumidor, List<Manga>> entry : consumidorMangaMap.entrySet()) {
    System.out.println("----" + entry.getKey().getNome());
    for (Manga manga : entry.getValue()) {          // for dentro do for
        System.out.println("-------" + manga.getNome());
    }
}
  • Chave e valor podem ser objetos seus. Para chave, a classe precisa de equals/hashCode coerentes (aqui, pelo id).
  • ThreadLocalRandom.current().nextLong(0, 100_000) gera um número aleatório num intervalo. O William usa para simular um id gerado. Sem o intervalo, saem números gigantes e até negativos.
  • "Um para muitos": quando uma chave tem vários valores, o valor vira uma coleção, Map<Consumidor, List<Manga>>, "como um array multidimensional". Para imprimir, um for nas entradas e outro for na lista de cada uma.
  • Imprimir entry.getKey() usa o toString. Para uma saída limpa, use os getters (getNome()).

181 · TreeMap e NavigableMap

NavigableMap<String, String> map = new TreeMap<>();   // ordenado pela CHAVE
map.put("A", "Letra A");
map.put("D", "Letra D");
map.put("B", "Letra B");
map.put("C", "Letra C");
map.put("E", "Letra E");
// A-Letra A · B-Letra B · C-Letra C · D-Letra D · E-Letra E

System.out.println(map.headMap("C", true));   // {A=Letra A, B=Letra B, C=Letra C} (true = inclui o C)
System.out.println(map.ceilingKey("C"));      // C  (≥)
System.out.println(map.higherKey("C"));       // D  (>)
System.out.println(map.lowerKey("C"));        // B  (<)
System.out.println(map.floorKey("C"));        // C  (≤)
// com Consumidor como chave (não Comparable, sem Comparator) → ClassCastException
  • É o TreeSet do mundo dos Maps: ordenado pela chave, com as mesmas regras (a chave é Comparable ou você passa um Comparator). O valor pode ser qualquer coisa.
  • headMap(chave) devolve tudo antes da chave, e com true inclui a própria chave. Também existe tailMap (depois). A visão fica ligada ao mapa original: remover da headMap remove do original, como no Arrays.asList.
  • Navegação: lowerKey/floorKey/higherKey/ceilingKey devolvem só a chave. As versões ...Entry (ceilingEntry...) devolvem chave e valor.

182 · Queue e PriorityQueue

Queue<String> fila = new PriorityQueue<>();   // a ordem de saída é a do Comparable
fila.add("C");
fila.add("A");
fila.add("B");
System.out.println(fila);            // [A, C, B] ← por dentro NÃO está ordenado
while (!fila.isEmpty()) {
    System.out.println(fila.remove());   // A · B · C ← mas SAI em ordem
}

// Prioridade customizada: os MAIS CAROS primeiro
Queue<Manga> mangas = new PriorityQueue<>(new MangaPrecoComparator().reversed());
... (os mesmos mangás)
while (!mangas.isEmpty()) {
    System.out.println(mangas.poll());   // 19.9 · 11.2 · 9.5 · 3.2 · 2.99 · 2.99
}
  • Uma fila costuma ser FIFO (o primeiro que entra é o primeiro que sai, como a fila do banco). A PriorityQueue muda isso: sai primeiro quem tem maior prioridade, pelo Comparable ou pelo Comparator do construtor.
  • A ordem só aparece ao retirar. Imprimir a fila ou percorrê-la com foreach mostra a ordem interna (um heap), que não é a ordenada.
  • Métodos:
    • peek() espia o primeiro sem remover. Num laço, fica mostrando o mesmo para sempre.
    • poll() retira o primeiro (null se vazia). remove() faz o mesmo, mas lança exceção se vazia.
    • offer/add inserem. Em fila com capacidade limitada, offer devolve false e add lança exceção.
  • Elemento sem Comparable e sem Comparator (o Consumidor) → ClassCastException já na inserção.
  • Para que serve: regra de negócio com prioridade, como atender primeiro os carrinhos de maior valor. comparator.reversed() inverte a ordem.

Atenção

  • Hash = sem ordem · LinkedHash = ordem de inserção · Tree = ordenado.
  • HashSet/HashMap dependem de equals/hashCode. TreeSet/TreeMap dependem de compareTo/compare, e é esse critério que decide o que é "repetido".
  • Set ignora o repetido, e Map sobrescreve o valor da chave repetida (a não ser com putIfAbsent).
  • Extra: não altere um objeto que já é chave de HashMap/elemento de HashSet nos campos usados pelo hashCode. Ele fica "perdido" no balde errado.
  • Extra: map.getOrDefault(chave, padrao), map.containsKey(chave), map.computeIfAbsent(chave, k -> new ArrayList<>()).add(x) (o jeito moderno de montar o Map<K, List<V>>) e Map.of(...) (imutável, Java 9+).
  • Extra: fila e pilha "de verdade": para FIFO simples, ArrayDeque (offer/poll). Para pilha, o mesmo ArrayDeque com push/pop.

Paralelo com PHP

  • O array associativo do PHP é o LinkedHashMap: chave → valor, mantendo a ordem de inserção. $m['vc'] = 'você' ≈ put (também sobrescreve). $m['vc'] ??= 'você' ≈ putIfAbsent. array_keys ≈ keySet, array_values ≈ values, foreach ($m as $k => $v) ≈ entrySet.
  • Diferença grande: no PHP a chave é só int ou string. Em Java, qualquer objeto pode ser chave (Map<Consumidor, ...>), desde que tenha equals/hashCode. No PHP isso exige SplObjectStorage ou usar o id como chave.
  • Set: o PHP não tem. Faz-se com array_unique ou usando os valores como chave ($set[$v] = true). No Laravel: $c->unique('id').
  • TreeMap/TreeSet: no PHP, é um array + ksort/sort depois de inserir. Não existe estrutura que se mantenha ordenada sozinha, nem floor/ceiling.
  • Map de List (aula 180): no PHP, $compras[$idConsumidor][] = $manga faz isso direto, e o groupBy('consumidor_id') da Collection do Laravel faz o mesmo. Em Java, computeIfAbsent (ou, mais adiante, Collectors.groupingBy, aulas 214+).
  • PriorityQueue: o PHP tem SplPriorityQueue (insert($valor, $prioridade), extract()), e SplQueue para FIFO.

│   ├── HashMap · LinkedHashMap · chave-objeto precisa de equals/hashCode
│   ├── Map<K, List<V>>: um para muitos (for dentro do for)
│   └── TreeMap / NavigableMap: ordenado pela chave · headMap/tailMap · lowerKey...
└── Queue (182)
    ├── PriorityQueue: sai pela prioridade (Comparable/Comparator; .reversed())
    ├── por dentro não fica ordenada; a ordem aparece ao retirar

Glossário

  • Set: coleção sem elementos repetidos e sem índice.
  • Map: estrutura de pares chave → valor, com chaves únicas; não é Collection.
  • Map.Entry: um par chave/valor do mapa (getKey, getValue).
  • LinkedList: lista em que cada nó conhece o anterior e o próximo; boa para inserir e remover.
  • Hash / LinkedHash / Tree: sem ordem / ordem de inserção / ordenado por comparação.
  • NavigableSet/NavigableMap: coleções ordenadas com navegação (lower, floor, higher, ceiling).
  • FIFO: first in, first out, o primeiro a entrar é o primeiro a sair.
  • PriorityQueue: fila em que sai primeiro o de maior prioridade (pela comparação).
  • peek / poll: espia o primeiro sem remover / retira o primeiro.
