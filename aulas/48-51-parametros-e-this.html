Resumo

Quando você passa algo para um método, o que chega lá é sempre uma cópia. A diferença está no que é copiado. Com um primitivo, copia-se o valor, e o original nunca muda. Com um objeto, copia-se a referência: o método recebe outro "controle remoto" que aponta para o mesmo objeto, e tudo o que ele alterar no objeto aparece para quem chamou. O this fecha o bloco: dentro do próprio objeto, ele é a referência para "este objeto aqui". As aulas continuam no pacote javacore.Bintroducaometodos.

48 · Primitivos: chega uma cópia do valor

// Calculadora
public void alteraDoisNumeros(int num1, int num2) {
    num1 = 99;
    num2 = 33;
    System.out.println("Dentro do alteraDoisNumeros: " + num1 + " " + num2);
}

// CalculadoraTeste04
int num1 = 1;
int num2 = 2;
calculadora.alteraDoisNumeros(num1, num2);                     // 99 33
System.out.println("Dentro do CalculadoraTeste04: " + num1 + " " + num2);   // 1 2
  • O Java copia os bits do valor para a variável local do método. São espaços de memória diferentes, mesmo com o mesmo nome. O William usa nomes iguais de propósito, para mostrar que isso não liga nada.
  • Renomear os parâmetros para a e b não muda o resultado: continuam sendo variáveis independentes.
  • A regra: com tipo primitivo, a variável original nunca é alterada, não importa o que aconteça dentro do método.
  • O IntelliJ chega a avisar que o parâmetro "pode virar variável local", porque o valor recebido nem é usado antes de ser sobrescrito.

49 · Objetos: chega uma cópia da referência

// dominio/ImpressoraEstudante.java — uma classe só para imprimir (coesão)
public class ImpressoraEstudante {
    public void imprime(Estudante estudante) {
        System.out.println(estudante.nome);
        System.out.println(estudante.idade);
        System.out.println(estudante.sexo);
    }
}

// test/EstudanteTeste01.java
ImpressoraEstudante impressora = new ImpressoraEstudante();
impressora.imprime(estudante01);   // "estudante" aponta para o MESMO objeto de estudante01
impressora.imprime(estudante02);   // agora aponta para o de estudante02
estudante01 ─────┐
                 ├──▶ [Midoriya | 15 | M]     (durante impressora.imprime(estudante01))
estudante (param)┘
estudante02 ────────▶ [Sakura | 16 | F]
  • O ponto de partida é código repetido: imprimir estudante01 e estudante02 com as mesmas 3 linhas, mudando só a variável. A solução é uma classe com um método que recebe o objeto como parâmetro.
  • O parâmetro Estudante estudante é uma variável de referência sem objeto próprio: o objeto vem como argumento na chamada.
  • Na chamada, o parâmetro passa a apontar para o mesmo objeto que o argumento. No debug, os dois mostram o mesmo identificador (por exemplo Estudante@81).
  • Quando o método termina, a variável local morre, mas o objeto continua existindo, porque estudante01 ainda aponta para ele. Não há limite de variáveis apontando para o mesmo objeto.
  • Cuidado com o import: agora existem duas classes Estudante, uma em Aintroducaoclasses.dominio e outra em Bintroducaometodos.dominio. Para o Java elas são tão diferentes quanto "laranja e alface". Importar a errada gera erro de compilação ao passá-la para o método.
  • Classes do mesmo pacote não precisam de import entre si: ImpressoraEstudante enxerga Estudante direto.

50 · O perigo: alterar o objeto recebido

public void imprime(Estudante estudante) {
    System.out.println(estudante.nome + " " + estudante.idade + " " + estudante.sexo);
    estudante.nome = "Gohan";   // altera o OBJETO, não uma cópia
}

impressora.imprime(estudante01);   // Midoriya 15 M
impressora.imprime(estudante02);   // Sakura 16 F
impressora.imprime(estudante01);   // Gohan 15 M   ← o objeto original mudou!
impressora.imprime(estudante02);   // Gohan 16 F
  • Como o método tem uma referência para o mesmo objeto, qualquer alteração no estado dele continua valendo depois que o método acaba, para todas as variáveis que apontam para aquele objeto.
  • É o que torna a passagem de referência perigosa: um método chamado "imprime" mudou os dados sem ninguém esperar.
  • Boa prática citada na aula: não altere o objeto recebido. Se precisar de uma versão modificada, crie e retorne um objeto novo com o estado alterado.

51 · A referência this

// dominio/Estudante.java
public class Estudante {
    public String nome;
    public int idade;
    public char sexo;

    public void imprime() {
        System.out.println(this.nome);   // "o nome DESTE objeto"
        System.out.println(this.idade);
        System.out.println(this.sexo);
    }
}

// test/EstudanteTeste02.java
estudante01.imprime();   // executa no objeto de estudante01
estudante02.imprime();   // executa no objeto de estudante02
  • Um método da própria classe roda dentro do objeto, então enxerga todos os atributos dele. Não precisa receber o estudante por parâmetro.
  • this ("este", em inglês) é a palavra reservada que referencia o objeto atual, aquele em que o método está executando.
  • A analogia do controle remoto: a variável de referência tem "botões" (nome, idade, sexo, imprime). Ela só manda o sinal. Quem executa é sempre o objeto. Em estudante01.imprime(), o this é o objeto de estudante01, e em estudante02.imprime() é o de estudante02.
  • Nesse caso o this é opcional: sem nenhuma variável local de mesmo nome, nome já significa o atributo. Mas é bom usar, para deixar claro que é o atributo. Ele passa a ser obrigatório quando um parâmetro tem o mesmo nome (veja "Atenção").
  • Coesão: o próprio William pondera que colocar a impressão dentro de Estudante "baixa um pouco a coesão", já que a classe passa a representar e imprimir. A linha entre alta e baixa coesão é tênue. Um método que mostra os dados do objeto é comum e útil, e é a ideia do toString (aula 76).

Atenção

  • Extra: Java é sempre passagem por valor. Para objetos, o "valor" copiado é a referência. Por isso alterar o objeto aparece fora do método, mas trocar para onde o parâmetro aponta não aparece: 
    public void troca(Estudante estudante) {
    estudante = new Estudante();   // só o parâmetro passa a apontar para outro objeto
    estudante.nome = "Novo";       // o objeto de quem chamou NÃO muda
}
  • Extra: this para desempatar nomes. Se o parâmetro tem o mesmo nome do atributo, o nome sozinho é o parâmetro. nome = nome; não faz nada útil. O certo é this.nome = nome;, padrão que aparece nos setters (aulas 54–56) e nos construtores (58–59).
  • Extra: this não existe em métodos static, como o main, porque não há objeto atual. Isso volta nas aulas 61–62.
  • Extra: String parece primitivo aqui. Passar uma String e fazer texto = "outro" dentro do método não altera a original. É o caso da reatribuição acima, e além disso String é imutável.
  • O mesmo vale para arrays, que também são objetos: alterar array[0] dentro do método altera o array de quem chamou.

Paralelo com PHP

  • Objetos: comportamento idêntico. Em PHP, passar um objeto para uma função também passa o "handle", e alterar $estudante->nome lá dentro altera o original. Trocar o parâmetro ($estudante = new Estudante()) também não afeta quem chamou.
  • Escalares e arrays: em PHP também vão por valor. A diferença é que o PHP tem &$var (passagem por referência de verdade), que não existe em Java. Não há como um método Java trocar o int de quem chamou.
  • $this × this: no PHP, $this->nome é obrigatório para acessar o atributo ($nome sozinho é variável local). Em Java, this.nome é opcional quando não há conflito de nomes.
  • A aula 50 no Laravel: é o problema clássico do Carbon mutável. $fim = $inicio->addDays(7); também altera $inicio, porque é o mesmo objeto. A solução do Laravel (CarbonImmutable, que devolve um objeto novo) é exatamente a boa prática que o William cita.

Glossário

  • Passagem por valor: o método recebe uma cópia do que foi passado. Em Java é sempre assim.
  • Cópia da referência: o que é copiado quando se passa um objeto. Aponta para o mesmo objeto.
  • Estado do objeto: os valores atuais dos seus atributos.
  • Efeito colateral: mudança de estado fora do método, como alterar o objeto recebido.
  • this: referência para o objeto atual, em cujo contexto o método executa.
  • Sombreamento (shadowing): variável local ou parâmetro com o mesmo nome de um atributo, que "esconde" o atributo. Resolve-se com this.
  • Imutável: objeto cujo estado não muda depois de criado (como String).
