77–79 · Modificador final

Constantes, referências finais, classes que não podem ser estendidas e métodos que não podem ser sobrescritos · playlist

Resumo

final quer dizer "definitivo", e muda de sentido conforme onde é aplicado. Numa variável, o valor não pode ser trocado depois de atribuído (constante). Numa referência, ela não pode apontar para outro objeto, embora o objeto possa mudar por dentro. Numa classe, ninguém pode estendê-la. Num método, ninguém pode sobrescrevê-lo. Os dois últimos casos são sobre herança.

De passagem, a aula 77 tira o extends Object que a aula 76 tinha escrito: ele é implícito e não precisa aparecer.

77 · Constantes (final em primitivo)

package academy.devdojo.maratonajava.javacore.Jmodificadorfinal.dominio;

public class Carro {
    private String nome;
    public static final double VELOCIDADE_LIMITE = 250;   // constante
}

// CarroTest01
System.out.println(Carro.VELOCIDADE_LIMITE);   // 250.0
// Carro.VELOCIDADE_LIMITE = 180;              // NÃO compila: é final
  • A velocidade limite da aula 61 era static, e por isso ainda podia ser trocada (para 180). Com final ela vira uma constante: depois do valor atribuído, só mudando o código e compilando de novo.
  • final não aceita o valor padrão. Um atributo final sem valor não compila. O Java obriga você a dizer qual é o valor.
  • Convenção de nome: constantes em MAIÚSCULAS, com palavras separadas por underline: VELOCIDADE_LIMITE. Batendo o olho, em qualquer lugar do código, você sabe que é uma constante.
  • O combo mais comum é public static final: pertence à classe, é visível para todos e não muda. Acesse pelo nome da classe (Carro.VELOCIDADE_LIMITE). Por uma referência "funciona", mas não é o certo, e o IntelliJ nem sugere.
  • Onde inicializar:
    • num static final, na declaração ou num bloco static, porque ele sempre roda quando a classe é carregada;
    • num final de instância (sem static), na declaração, num bloco de instância ou no construtor.
    A regra é que ele tenha valor antes de ser usado.

78 · final em referência: não troca o objeto, mas o objeto muda

public class Carro {
    private String nome;
    public static final double VELOCIDADE_LIMITE = 250;
    public final Comprador COMPRADOR = new Comprador();   // referência final
}

// CarroTest01
Carro carro = new Carro();
System.out.println(carro.COMPRADOR);        // Comprador{nome='null'}
carro.COMPRADOR.setNome("Kuririn");         // pode: altera o OBJETO
System.out.println(carro.COMPRADOR);        // Comprador{nome='Kuririn'}

Comprador comprador2 = new Comprador();
// carro.COMPRADOR = comprador2;            // NÃO compila: a REFERÊNCIA é final
carro ──▶ [nome | COMPRADOR ═══▶ [ nome: null → "Kuririn" ]]
                  (seta fixa)      (o conteúdo pode mudar)
  • Numa variável de referência, final trava a seta: ela sempre apontará para aquele mesmo objeto.
  • Os dados do objeto continuam alteráveis: setNome("Kuririn") funciona. final não torna o objeto imutável.
  • Sem o = new Comprador(), o compilador exige a inicialização, pelo mesmo motivo da aula 77.
  • Para que serve: casos em que você quer um único objeto, sempre o mesmo. Por exemplo, um gerenciador de conexões com o banco: com mil usuários, você não quer mil gerenciadores. O William indica pesquisar o padrão de projeto Singleton, que usa isso.

79 · final em classes e métodos

public final class Carro { ... }
// public class Ferrari extends Carro { }   // NÃO compila: Carro é final

public class Carro {
    public final void imprime() {           // método final
        System.out.println(this.nome);
    }
}

public class Ferrari extends Carro {
    // public void imprime() { ... }        // NÃO compila: não se sobrescreve método final
}

Ferrari ferrari = new Ferrari();
ferrari.setNome("Enzo");
ferrari.imprime();                          // Enzo — herdado e usado normalmente
  • Classe final não pode ser estendida. A OO incentiva a herança, mas há casos em que você quer impedi-la.
  • O grande exemplo é String, que é final. Permitir herança é permitir que alguém mude o comportamento dos métodos (como fizemos com o toString). Com bilhões de JVMs no mundo dependendo de String, o comportamento dela tem que ser garantido.
  • Método final não pode ser sobrescrito, mas é herdado e usado normalmente. Ele diz: "este é o comportamento para todo mundo".
  • Ordem das palavras: public final void e final public void compilam. O tipo de retorno fica sempre logo antes do nome, então public void final imprime() não compila. "Na dúvida, teste e veja se compila."
  • Numa classe final, marcar métodos como final é redundante: se ninguém estende a classe, ninguém sobrescreve nada. Por isso os métodos de String não são final.

Atenção

  • final ≠ imutável. Uma referência final pode ter o objeto alterado por dentro. Um array final também: final int[] a = {1, 2}; a[0] = 9; compila.
  • final sem valor não compila (a menos que o construtor, ou um bloco, atribua). E cada construtor precisa garantir a atribuição.
  • Extra: nomes. O professor escreve COMPRADOR em maiúsculas, mas a convenção mais aceita reserva o UPPER_SNAKE_CASE para static final (constantes de verdade). Um final de instância normalmente segue camelCase: private final Comprador comprador;.
  • Extra: final em variáveis locais e parâmetros. final int x = 10; dentro de um método e void m(final String nome) impedem a reatribuição. Isso vai importar com lambdas ("effectively final").
  • Extra: receita de classe imutável. Classe final, atributos private final, preenchidos no construtor e sem setters. É o que String faz, e o que os record (Java 16+) geram sozinhos.
  • Acesse constantes pela classe, não pela referência: Carro.VELOCIDADE_LIMITE.

Paralelo com PHP

  • Constantes: const VELOCIDADE_LIMITE = 250; numa classe PHP, com acesso Carro::VELOCIDADE_LIMITE, equivale a public static final, com acesso Carro.VELOCIDADE_LIMITE. A convenção em maiúsculas é a mesma.
  • readonly ≈ final de instância: a propriedade readonly do PHP 8.1 só pode ser atribuída uma vez. E, igual à aula 78, se ela guarda um objeto, o objeto continua mutável por dentro: $carro->comprador->nome = 'Kuririn' funciona.
  • final class e final function existem no PHP com o mesmo significado. Muitos pacotes modernos (Symfony, PHPStan) marcam classes como final por padrão, exatamente para evitar herança não planejada. O PHP 8.1 também tem constantes de classe final.
  • Classe imutável: o readonly class do PHP 8.2 é o equivalente de uma classe com todos os atributos final, ou de um record.

Glossário

  • final: modificador que impede reatribuição (variável), herança (classe) ou sobrescrita (método).
  • Constante: valor que não muda. Em Java, normalmente public static final em MAIÚSCULAS.
  • UPPER_SNAKE_CASE: maiúsculas com _ entre as palavras.
  • Referência final: variável que sempre aponta para o mesmo objeto (o objeto pode mudar).
  • Imutável: objeto cujo estado não muda depois de criado (ex.: String).
  • Singleton: padrão de projeto que garante uma única instância de uma classe.
