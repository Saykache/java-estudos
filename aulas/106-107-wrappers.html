Resumo

Aqui o curso sai da introdução à OO e entra no Java intermediário, começando pelas classes utilitárias: classes prontas do Java que melhoram a qualidade do código. As primeiras são as wrappers ("embrulhos"): classes que encapsulam os tipos primitivos e os transformam em objetos, com métodos.

106 · Os 8 wrappers

byte byteP = 1;           Byte byteW = 127;
short shortP = 1;         Short shortW = 1;
int intP = 1;             Integer intW = 1;       // autoboxing
long longP = 10;          Long longW = 10L;       // Long longW = 10; NÃO compila
float floatP = 10F;       Float floatW = 10F;
double doubleP = 10D;     Double doubleW = 10D;
char charP = 'W';         Character charW = 'W';
boolean booleanP = false; Boolean booleanW = false;

// List<int> lista;      // NÃO compila: coleções só guardam objetos
List<Integer> lista;      // OK
  • A regra do nome: é o nome do primitivo com a primeira letra maiúscula, com duas exceções: int → Integer e char → Character.
  • Os seis numéricos (Byte, Short, Integer, Long, Float, Double) estendem Number. Todos são filhos de Object.
  • Cuidado, agora vale o polimorfismo, não o tamanho: long x = 10; compila (o int cabe no long). Long x = 10; não compila: o literal 10 é int, viraria Integer, e Integer não é um Long na herança. Precisa de 10L. O mesmo vale para Float e Double (Double d = 10; não compila).
  • Por que os wrappers existem:
    • Coleções (ArrayList...) guardam referências, não primitivos: List<Integer>, nunca List<int>.
    • Ter um objeto com métodos (de Boolean, Comparable, Object...).
    • Concorrência: a sincronização trabalha com objetos.
    • O William também cita a passagem "por referência" de números para alterar dentro do método. Veja o Atenção: na prática isso não funciona, porque wrappers são imutáveis.
  • Boa prática: quando der, prefira o primitivo, como nas classes de domínio feitas até aqui. Use o wrapper quando for necessário.
  • Dica do IntelliJ: Ctrl+R (substituir) com "em seleção" renomeia as variáveis de ...P para ...W de uma vez.

107 · Autoboxing, unboxing, parse e Character

Integer intW = 1;                     // autoboxing: primitivo → wrapper (o Java "encaixota")
int i = intW;                         // unboxing:   wrapper → primitivo
intW.byteValue(); intW.longValue();   // xxxValue(): o primitivo no tipo pedido

Integer intW2 = Integer.parseInt("1");        // String → número
// new Integer("1")                           // deprecated (Java 9): "muito feio, não use"
boolean verdadeiro = Boolean.parseBoolean(null);
System.out.println(verdadeiro);               // false

System.out.println(Character.isDigit('A'));          // false
System.out.println(Character.isDigit('9'));          // true
System.out.println(Character.isLetterOrDigit('!'));  // false
System.out.println(Character.isUpperCase('A'));      // true
System.out.println(Character.isLowerCase('a'));      // true
System.out.println(Character.toUpperCase('a'));      // A
System.out.println(Character.toLowerCase('A'));      // a
  • Autoboxing ("colocar na caixa"): você atribui um primitivo e o Java cria o wrapper. Unboxing: o contrário, automático.
  • Por serem objetos, os wrappers têm métodos: byteValue(), intValue(), longValue(), floatValue()... O William diz que já não são tão usados, por causa do unboxing.
  • parseXxx(String) converte texto: Integer.parseInt, Byte.parseByte, Float.parseFloat, Boolean.parseBoolean... Todos têm, menos Character.
  • new Integer("1") funciona, mas está deprecated desde o Java 9. Use o parseInt.
  • Boolean.parseBoolean ignora maiúsculas e minúsculas: "true", "TRUE" e "tRuE" dão true. Qualquer outra coisa dá false, inclusive "sim", "" e null, sem exceção.
  • Character é "a mais legal": isDigit, isLetter, isLetterOrDigit, isUpperCase, isLowerCase, toUpperCase, toLowerCase, todos static (chamados pela classe).
  • toUpperCase/toLowerCase num caractere que não é letra ('!', '9') devolvem o próprio caractere. isUpperCase('9') dá false.
  • Conselho do William: explore essas classes sozinho (Ctrl+clique para ver o código, Ctrl+Q para a documentação). Os nomes dos métodos já dizem o que fazem, e ler o código do JDK ensina muito.

Atenção

  • Wrappers são imutáveis (correção à aula 106). Passar um Integer para um método e fazer numero = numero + 1 lá dentro não altera a variável de quem chamou: é criado outro objeto, como com String. Para alterar um valor dentro do método, devolva o resultado ou use um objeto mutável (um atributo de classe, AtomicInteger...).
  • Extra: unboxing de null dá NullPointerException. Integer x = null; int y = x; compila e explode. Wrapper aceita null, primitivo não. Atributo wrapper começa como null, primitivo começa como 0/false.
  • Extra: não compare wrappers com ==. Integer a = 127, b = 127; dá a == b true (há cache de -128 a 127), mas com 128 dá false: são objetos diferentes. Use a.equals(b).
  • Extra: parseInt × valueOf. Integer.parseInt("1") devolve int (no código da aula, o autoboxing o transforma em Integer). Integer.valueOf("1") já devolve Integer, e usa o cache.
  • Extra: Integer.parseInt("abc") lança NumberFormatException (uma RuntimeException, aulas 95–99). parseBoolean nunca lança.
  • Extra: cada wrapper tem constantes úteis: Integer.MAX_VALUE, Integer.MIN_VALUE, Long.MAX_VALUE...

Paralelo com PHP

  • O PHP não tem essa divisão. int, float, bool e string são escalares, e um array guarda qualquer coisa. Não existe List<int> proibido nem autoboxing.
  • Aceitar null: o ?int do PHP ≈ usar Integer em vez de int em Java. Uma coluna nullable no banco costuma virar wrapper na entidade.
  • parse: (int) "1" ou intval("1"). Mas (int) "abc" vira 0 em silêncio, enquanto o parseInt do Java lança exceção. Para validar de verdade no PHP: filter_var($v, FILTER_VALIDATE_INT).
  • Boolean: filter_var($v, FILTER_VALIDATE_BOOLEAN) aceita "1", "yes", "on"... O parseBoolean do Java só aceita "true".
  • Character: ctype_digit, ctype_alpha, ctype_alnum, ctype_upper, ctype_lower, strtoupper/strtolower (ou mb_* para acentos).
  • No Laravel, $casts = ['ativo' => 'boolean', 'idade' => 'integer'] faz o papel do parse na fronteira com o banco.

Glossário

  • Wrapper: classe que embrulha um tipo primitivo num objeto (Integer, Double...).
  • Autoboxing: conversão automática de primitivo para wrapper.
  • Unboxing: conversão automática de wrapper para primitivo.
  • Number: superclasse abstrata dos wrappers numéricos.
  • Parse: converter texto (String) para outro tipo.
  • Deprecated: ainda existe, mas não deve mais ser usado (pode sumir em versões futuras).
  • Imutável: objeto cujo valor não muda depois de criado; "alterar" cria outro objeto.
  • Classe utilitária: classe pronta com métodos de apoio, geralmente estáticos.
