Resumo

Entender como a String funciona importa porque "a performance do seu sistema pode ser diretamente impactada". A ideia central: Strings em Java são imutáveis. Toda "alteração" cria outra String. Os literais moram na String Constant Pool e são reaproveitados. Para montar texto em grande quantidade existem as classes mutáveis StringBuilder e StringBuffer.

108 · Imutabilidade e String Constant Pool

String nome = "William";              // String constant pool
String nome2 = "William";             // reaproveita o MESMO objeto do pool
nome.concat(" Suane");                // cria "William Suane"... e ninguém guarda
nome = nome.concat(" Suane");         // agora sim: nome aponta para a nova String (= nome += " Suane")
System.out.println(nome);             // William Suane
System.out.println(nome == nome2);    // false (antes do concat seria true)

String nome3 = new String("William"); // 1 variável de referência, 2 objeto String no heap, 3 "William" no pool
System.out.println(nome2 == nome3);            // false: objetos diferentes
System.out.println(nome2 == nome3.intern());   // true: intern() devolve a referência do pool
  • O heap é onde moram os objetos. Dentro dele o Java reserva a String Constant Pool (piscina de Strings), com base no conceito de string interning: uma String literal é criada uma vez só, e o segundo "William" recebe a mesma referência.
  • == compara referências (é o mesmo objeto?). equals compara o conteúdo. nome == nome2 dá true aqui só porque os dois apontam para o mesmo literal do pool.
  • Imutável: nome.concat(" Suane") não muda nome. Cria " Suane" e "William Suane" no pool, e, sem atribuir a uma variável, o resultado se perde. É preciso nome = nome.concat(...).
  • new String("William") cria um objeto fora do pool, que encapsula o valor do pool. O intern() devolve a representação canônica (a do pool). O William diz que nunca viu new String em produção: é "feio".
  • Por que isso pesa: um documento de 5 mil palavras numa String. Mudar um caractere cria outra String quase do mesmo tamanho.

109 · Métodos principais

String nome = "Luffy";
String numeros = "012345";
System.out.println(nome.charAt(0));                          // L
System.out.println(nome.length());                           // 5
System.out.println(nome.replace("f", "l"));                  // Lully
System.out.println(nome.toLowerCase());                      // luffy
System.out.println(nome.toUpperCase());                      // LUFFY
System.out.println(numeros.length());                        // 6
System.out.println(numeros.substring(0, 2));                 // 01  (o fim é exclusivo)
System.out.println(numeros.substring(3, numeros.length()));  // 345 (= numeros.substring(3))
System.out.println("  Luffy  ".trim());                      // "Luffy"
  • charAt(i): o char na posição i (começa em 0). Índice inexistente lança StringIndexOutOfBoundsException.
  • length() é método na String. No array, length é atributo (sem parênteses). Tamanho 5, índices de 0 a 4.
  • replace(a, b) troca todas as ocorrências.
  • toLowerCase()/toUpperCase(): útil quando o sistema padroniza como grava (tudo maiúsculo, por exemplo).
  • substring(inicio, fim): o início é inclusivo e o fim é exclusivo (pega até fim - 1). Com um parâmetro só (sobrecarga), vai até o final. substring(0, length() + 1) lança exceção.
  • trim() remove espaços do começo e do fim. É útil no login: o usuário pode digitar " Luffy ". Aplique antes de salvar e antes de comparar.
  • Todos esses métodos retornam uma String nova. nome continua "Luffy".

110 · Desempenho: String × StringBuilder × StringBuffer

long inicio = System.currentTimeMillis();
concatString(30_000);                         // _ separa milhares (sintaxe válida)
long fim = System.currentTimeMillis();
System.out.println("Tempo gasto para String " + (fim - inicio) + "ms");

private static void concatString(int tamanho) {
    String texto = "Ola meu nome é william";
    for (int i = 0; i < tamanho; i++) {
        texto += i;                           // uma String NOVA a cada volta
    }
}

private static void concatStringBuilder(int tamanho) {
    StringBuilder sb = new StringBuilder(tamanho);   // já reserva a capacidade
    for (int i = 0; i < tamanho; i++) {
        sb.append(i);                         // altera o MESMO objeto
    }
}
// concatStringBuffer: igual, com StringBuffer
  • Com += no laço, cada volta cria uma String nova (cada vez maior). Na máquina do William: 1 mil → 3 ms, 10 mil → 186 ms, 100 mil → quase 10 segundos.
  • Com StringBuilder, 100 mil levou 4 ms, e 1 milhão ficou na casa das dezenas de ms.
  • Pense em sistemas grandes (governo, Amazon): segundos a mais por ação, multiplicados por milhões de usuários, é inaceitável ("esperar 15 segundos para saber se a compra foi aprovada").
  • StringBuffer tem os mesmos métodos do StringBuilder, mas eles são synchronized: só uma thread por vez. É para ambientes com várias threads acessando o mesmo objeto. Isso custa um pouco (quase o dobro no teste), mas ainda é muito mais rápido que String.
  • Quando usar cada um: para modelar o mundo real (atributo nome de Pessoa) use String, que é mais simples e legível. Use o StringBuilder quando sentir o impacto de muita concatenação. Evite a micro-otimização precoce: ela só adiciona complexidade.
  • System.currentTimeMillis() devolve o horário atual em milissegundos. Datas vêm nas próximas aulas.

111 · StringBuilder

String nome = "William Suane";
nome.concat(" DevDojo");          // resultado perdido
nome.substring(0, 3);             // resultado perdido
System.out.println(nome);         // William Suane

StringBuffer sb = new StringBuffer("William Suane");   // (StringBuilder funciona igual)
sb.append(" DevDojo").append(" Academy");   // encadeia: append retorna o próprio objeto
sb.reverse();                               // ymedacA ojoDveD enauS mailliW
sb.reverse();                               // volta ao normal
sb.delete(0, 3);                            // apaga as posições 0 a 2 (fim exclusivo)
System.out.println(sb);                     // liam Suane DevDojo Academy
  • StringBuilder não é uma String (StringBuilder sb = "William"; não compila). É uma classe que manipula uma sequência de caracteres mutável, e quem muda é o próprio objeto.
  • Construtores: vazio (capacidade 16), com uma capacidade (new StringBuilder(30_000)) ou com uma String/CharSequence inicial. Quando a capacidade estoura, ela cresce para o dobro + 2 (16 → 34 → 70...). Passar o tamanho já evita realocações.
  • append é o concat dele, sobrecarregado (aceita int, boolean, Object...). System.out.println(sb) chama o toString(), que devolve a String.
  • Legibilidade: dezenas de append encadeados ficam difíceis de ler. O próprio IntelliJ sugere "trocar append por +" quando há concatenação simples.
  • A pegadinha: olhe o tipo de retorno. append, reverse, delete, insert e replace retornam StringBuilder e alteram o objeto. substring retorna uma String nova e não altera o builder.
  • delete(inicio, fim) segue a mesma regra do substring: o fim é exclusivo.

Atenção

  • Compare Strings com equals (ou equalsIgnoreCase), nunca com ==. O == só "funciona" com literais do pool, por coincidência.
  • Método de String que "altera" precisa de atribuição: nome.toUpperCase(); sozinho não faz nada. Escreva nome = nome.toUpperCase();.
  • substring(3, 5) pega os índices 3 e 4. O fim é exclusivo, e o tamanho do resultado é fim - inicio.
  • Extra: outros métodos do dia a dia: contains, startsWith/endsWith, indexOf, split, isEmpty, isBlank (Java 11), strip (Java 11, entende espaços Unicode), String.join, String.format, equalsIgnoreCase.
  • Extra: "Wil" + "liam" == "William" dá true, porque o compilador junta literais constantes em tempo de compilação. Com uma variável no meio, dá false.
  • Extra: + fora de laço é tranquilo. O compilador já otimiza a + b + c numa linha. O problema é o += dentro de laço.

Paralelo com PHP

  • No PHP, strings são valores (copy-on-write), e $s .= $i num laço é rápido: o motor altera no lugar quando pode. Por isso não existe "StringBuilder" no PHP. Em Java, o += em laço é o vilão.
  • Equivalências: strlen ≈ length(), $s[0] ≈ charAt(0), str_replace ≈ replace, strtolower/strtoupper ≈ toLowerCase/toUpperCase, trim ≈ trim, strrev ≈ reverse, implode ≈ String.join.
  • Cuidado com o substr: no PHP é substr($s, inicio, TAMANHO). No Java é substring(inicio, FIM) (índice final exclusivo). substr("012345", 3, 2) dá "34", e "012345".substring(3, 2) lança exceção.
  • Comparação: no PHP, === compara o conteúdo da string. Em Java, == compara referências. Hábito do PHP é armadilha aqui: use equals.
  • Laravel: Str::of(' luffy ')->trim()->upper()->append('!') encadeia como o StringBuilder, mas cada passo devolve um novo Stringable (imutável, como a String do Java).

Glossário

  • Imutável: objeto que não muda depois de criado; operações devolvem um objeto novo.
  • Heap: área de memória onde ficam os objetos.
  • String Constant Pool: área do heap onde o Java guarda e reaproveita os literais de String.
  • Interning / intern(): usar uma única cópia canônica de cada String (a do pool).
  • Índice exclusivo: o limite final não entra no resultado (substring, delete).
  • StringBuilder: sequência de caracteres mutável, rápida, sem sincronização.
  • StringBuffer: igual ao StringBuilder, mas com métodos synchronized (seguro entre threads).
  • Capacidade: espaço reservado no builder; padrão 16, cresce para o dobro + 2.
  • Micro-otimização: otimizar cedo demais algo que não é gargalo, trocando legibilidade por ganho irrelevante.
