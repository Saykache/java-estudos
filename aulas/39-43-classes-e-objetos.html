Resumo

A parte introdutória acabou, e agora entra "o que realmente importa": orientação a objetos (OO). Até aqui, String nome, int idade e char sexo eram variáveis soltas, sem nada que dissesse que pertencem à mesma pessoa. A OO foi criada para mapear o mundo real para o computacional: dados relacionados ficam agrupados num único objeto, criado a partir de um molde, a classe.

39 · Classe, objeto e variável de referência

// dominio/Estudante.java
public class Estudante {
    public String nome;   // atributos: as características
    public int idade;
    public char sexo;
}

// test/EstudanteTest01.java
import academy.devdojo.maratonajava.javacore.Aintroducaoclasses.dominio.Estudante;

public class EstudanteTest01 {
    public static void main(String[] args) {
        Estudante estudante = new Estudante();
        estudante.nome = "Luffy";
        estudante.idade = 21;
        estudante.sexo = 'M';
        System.out.println(estudante.nome + " " + estudante.idade + " " + estudante.sexo);
        System.out.println(estudante); // algo como ...dominio.Estudante@1b6d3586
    }
}
  • Classe é o template, a "forma" que dá origem aos objetos. Ela define atributos (características, como nome, idade e sexo) e comportamentos (métodos, nas próximas aulas).
  • Objeto é uma instância criada a partir da classe, com new. Cada new cria um espaço novo na memória com os atributos da classe dentro.
  • Estudante estudante = new Estudante(); se lê assim: uma variável de referência do tipo Estudante aponta para um objeto do tipo Estudante. Com polimorfismo, mais à frente, os dois tipos podem ser diferentes.
  • A variável de referência é como um controle remoto: com ela e o ponto (estudante.nome) você acessa os "espacinhos" do objeto.
  • Imprimir a variável sozinha mostra a referência, não os dados. Isso vale até a aula 76 (toString).
  • Classe de outro pacote precisa de import. A alternativa é escrever o nome completo (academy...dominio.Estudante), que funciona mas é "muito verboso". O IntelliJ importa sozinho com Alt+Enter.
  • O public na frente dos atributos é um modificador de acesso. Ele fica sem explicação por enquanto e volta nas aulas 54–56.
  • Renomear a classe Pessoa para Estudante foi feito com Shift+F6, que troca todas as referências.

40 · Valores padrão e dois objetos

  • new Estudante(); sem guardar em variável cria o objeto, mas não há como acessá-lo. É para isso que existe a variável de referência.
  • Atributos têm valor padrão, diferente das variáveis locais: int → 0, char → '\u0000', String → null. É a mesma tabela dos arrays (aula 33). Dá para imprimir sem inicializar.
  • Dá para dar um valor inicial na própria classe (public String nome = "Zoro";), mas cuidado: todos os objetos criados nascem com esse nome.
  • Cada objeto tem os seus valores. Com estudante e estudante2, fazer estudante.nome = "Sanji" muda só o primeiro, e o segundo continua "Zoro".
  • Preste atenção em qual variável você está usando. Escrever estudante onde era estudante2 compila e roda, só que altera o objeto errado.

41 · Coesão

  • Coesão é o propósito de uma classe. Alta coesão é bom: cada classe tem um propósito, de preferência um só.
  • Jeito errado: colocar nomeProfessor, idadeProfessor e sexoProfessor dentro de Estudante. Compila, mas mistura dois conceitos do mundo real. Toda mudança em professor passa a mexer em estudante, e com 300 classes "você mexe aqui e quebra tudo".
  • Jeito certo: uma classe Professor própria. Estudante e professor podem se relacionar (associação, aulas 64–67), mas não são a mesma coisa.
  • Outro exemplo de baixa coesão: pôr um main dentro de Estudante. A classe de domínio passaria a representar o estudante e executar o teste. Mantenha domínio e teste separados.
  • O desafio da aula é imprimir todos os dados do professor numa linha, concatenando com + e espaços: professor.nome + " " + professor.idade + " " + professor.sexo.

42 · Exercício: classe Carro

Criar a classe Carro (em dominio) com nome, modelo e ano, criar dois objetos diferentes e imprimir os valores (em CarroTest01, dentro de test).

Carro carro1 = new Carro();
Carro carro2 = new Carro();
carro1.nome = "Fusca Bala";
carro1.modelo = "Sport";
carro1.ano = 1969;
carro2.nome = "Mustang";
carro2.modelo = "GT 500";
carro2.ano = 1968;
System.out.println("Carro 1\n" + carro1.nome + " " + carro1.modelo + " " + carro1.ano);
  • O enunciado escreve "Modelo" com M maiúsculo de propósito: o atributo tem que seguir a convenção, modelo.
  • O costume do William: primeiro criar os objetos, depois preencher um, depois o outro. A ordem não importa para o Java, mas organiza o código.
  • "\n" dentro da String pula uma linha.
  • São dois espaços diferentes na memória: um com o Fusca, outro com o Mustang, cada um apontado pela sua variável.

43 · Trocando referências

carro1 = carro2;   // carro1 passa a apontar para o MESMO objeto de carro2

carro1 ─┐
        ├──▶ [Mustang | GT 500 | 1968]
carro2 ─┘
             [Fusca Bala | Sport | 1969]      ← sem referência: perdido, vai para o GC
  • A variável de referência pode passar a apontar para outro objeto do mesmo tipo. carro1 = carro2 não copia os dados: faz as duas variáveis apontarem para o mesmo objeto.
  • O Fusca ficou sem nenhuma referência: não há como voltar a ele, e o garbage collector recolhe a memória. Só daria para salvá-lo se uma terceira variável ainda apontasse para ele.
  • Invertendo (carro2 = carro1, antes de perder o Fusca), os dois passam a imprimir o Fusca e é o Mustang que se perde.
  • Só dá para atribuir entre tipos compatíveis: carro1 = professor; não compila. As regras exatas ("mesma linha de herança") vêm com polimorfismo.
  • Ctrl+Alt+O remove os import que não estão sendo usados.

Atenção

  • Extra: depois de carro1 = carro2, alterar por um altera "os dois". carro1.nome = "Opala"; faz carro2.nome também virar "Opala", porque é um objeto só. É a mesma armadilha do int[] b = a da aula 34.
  • Extra: == em objetos compara referências, não conteúdo. Dois carros com os mesmos dados, criados com dois new, dão carro1 == carro2 → false. Depois de carro1 = carro2 dá true. Comparar conteúdo é com equals, mais à frente, e é por isso que String não se compara com ==.
  • Extra: variável de referência pode valer null. Carro c = null; c.nome = "x"; compila e lança NullPointerException ao rodar.
  • Atributo tem valor padrão e variável local não. Estudante e; e.nome = "x"; dentro do main não compila (variável não inicializada).
  • Atributos public acessados direto de fora funcionam para aprender, mas não são a prática profissional. O certo (private + get/set) vem nas aulas 54–56.
  • O nome do arquivo precisa bater com a classe pública: Estudante.java para public class Estudante.

Paralelo com PHP

  • Sintaxe: class Estudante { public string $nome; } vira public class Estudante { public String nome; }. O new é igual. Para acessar, $e->nome vira e.nome.
  • use × import: use App\Models\Estudante; equivale a import academy...dominio.Estudante;. O FQCN funciona nos dois.
  • Objetos são compartilhados nos dois: em PHP, $b = $a com objeto também faz as duas variáveis apontarem para o mesmo objeto. O comportamento da aula 43 é idêntico. Para copiar, o PHP tem clone $a. A diferença é que arrays PHP são copiados e arrays Java não (aula 34).
  • Valor padrão: no PHP, uma propriedade tipada sem valor fica "não inicializada", e ler dá Error. Uma sem tipo vale null. Em Java, todo atributo nasce com o padrão do tipo (0, false, null).
  • Eloquent × Java: no Laravel, os atributos de um Model aparecem "por mágica" a partir das colunas do banco. Em Java, cada atributo é declarado explicitamente na classe. As classes de dominio fazem o papel dos Models.
  • Coesão = SRP: é o mesmo princípio que você aplica ao tirar lógica de um Controller gordo para um Service ou Action.

Glossário

  • Orientação a objetos: paradigma que modela o sistema como objetos que agrupam dados e comportamentos.
  • Classe: molde (template) que define atributos e métodos.
  • Objeto / instância: algo concreto criado a partir de uma classe com new.
  • Atributo: característica declarada na classe (variável fora dos métodos).
  • Variável de referência: variável que aponta para um objeto, o "controle remoto".
  • Classe de domínio (model): representa algo do negócio ou do mundo real.
  • Coesão: o quanto uma classe se mantém num propósito só. Alta coesão é bom.
  • import: declara onde está uma classe de outro pacote.
