Resumo

Expressão regular (regex) é uma pequena linguagem de metacaracteres para encontrar padrões num texto: extrair todos os e-mails de um arquivo, achar links, validar se um e-mail está sintaticamente correto (se o domínio existe é outra história). O William avisa: "você vai voltar nessa aula mais vezes na vida". Ninguém decora tudo e todo mundo consulta. Em Java o trabalho é feito por duas classes de java.util.regex: Pattern (o padrão compilado) e Matcher (quem procura o padrão no texto).

131 · Pattern e Matcher

String regex = "aba";
String texto2 = "abababa";
Pattern pattern = Pattern.compile(regex);   // compila (valida) a expressão
Matcher matcher = pattern.matcher(texto2);  // aplica ao texto
System.out.println("texto:  " + texto2);
System.out.println("indice: 0123456789");
System.out.println("regex " + regex);
System.out.println("Posicoes encontradas");
while (matcher.find()) {                    // enquanto encontrar a próxima ocorrência
    System.out.print(matcher.start() + " ");   // índice onde começa
}
// "abaaba"  → 0 3
// "abababa" → 0 4   (e não 0 2 4!)
  • Pattern.compile(regex) cria o padrão. Uma regex inválida (por exemplo, um [ sem fechar) lança exceção. pattern.matcher(texto) devolve o Matcher.
  • find() procura a próxima ocorrência e devolve true/false, por isso o while. start() é o índice onde a ocorrência começa.
  • Sem metacaracteres, a regex procura o texto literal.
  • Ocorrências não se sobrepõem: em "abababa", depois de achar aba em 0–2, a busca continua do índice 3. O a do índice 2 já foi "consumido". Por isso a saída é 0 4, e não 0 2 4.
  • A linha indice: 0123456789 embaixo do texto é só um truque visual para conferir as posições.

132 · Metacaracteres

// \d = todos os dígitos
// \D = tudo o que não for dígito
// \s = espaços em branco: espaço, \t \n \f \r
// \S = todos os caracteres, excluindo os brancos
// \w = a-z, A-Z, dígitos e _
// \W = tudo o que não estiver incluso no \w
String regex = "\\w";                    // no código Java a barra precisa de escape: \\
String texto2 = "@#hh_j2 12gvh21";
while (matcher.find()) {
    System.out.print(matcher.start() + " " + matcher.group() + "\n");   // group() = o trecho encontrado
}
// \\d → 6 2 · 8 1 · 9 2 · 13 2 · 14 1
// \\s → 7 (o espaço)
// \\W → 0 @ · 1 # · 7 (espaço)
// \\w → todas as letras, dígitos e o _ (índices 2 a 6 e 8 a 14)
  • Metacaracteres são atalhos para grupos de caracteres. O maiúsculo é sempre o contrário do minúsculo.
  • Dupla barra: a regex é \d, mas numa String Java a \ é caractere de escape (aula 92), então se escreve "\\d".
  • matcher.group() devolve o texto que casou. Com start() você sabe onde, com group() sabe o quê.
  • Há muitos outros metacaracteres, mas esses seis resolvem a maioria dos casos.

133 · Range: [ ]

"[abc]"      // UM caractere: a OU b OU c        ("abc" sem colchetes = a sequência abc)
"[abcABC]"   // também maiúsculas
"[a-cA-C]"   // intervalo: de a até c, de A até C  → em "cafeBABE": c a B A B

int numeroHex = 0x59F86A;     // 0x ou 0X = literal hexadecimal no Java
System.out.println(numeroHex); // 5896298

String regex = "0[xX][0-9a-fA-F]";
String texto2 = "12 0x 0X 0xFFABC 0x109 0x1";
// → 9 0xF · 17 0x1 · 23 0x1   (só o 1º caractere depois do x: faltam os quantificadores)
  • Colchetes = um caractere dentre os listados. [abc] casa com a, b ou c, um de cada vez. É case sensitive.
  • Hífen = intervalo: [a-z], [A-Z], [0-9], [a-fA-F]. Dá para juntar vários no mesmo colchete.
  • Exercício dos hexadecimais: um número hexa em Java começa com 0x/0X e só usa dígitos de 0 a 9 e letras de A a F (0x10G não compila). A regex 0[xX][0-9a-fA-F] acha o começo certo, mas pega um caractere só depois do x. A aula 134 resolve.

134 · Quantificadores, grupos, | e $

// ?  zero ou uma          *  zero ou mais          +  uma ou mais
// {n,m} de n até m        ( ) agrupamento           |  ou             $  fim da linha
String regex = "0[xX]([0-9a-fA-F])+(\\s|$)";
String texto = "12 0x 0X 0xFFABC 0x10G 0x1";
// → 9 "0xFFABC " · 23 "0x1"
  • O quantificador vale para o que vem logo antes. Por isso o range foi agrupado com parênteses: ([0-9a-fA-F])+.
  • * não serve: "zero ou mais" aceita 0x sem nada depois. Precisa de + (pelo menos um).
  • Mesmo com +, 0x10G ainda casava como 0x10. Faltava um delimitador: depois dos dígitos tem que vir um espaço (\\s)...
  • ...ou o fim da linha ($), senão o último 0x1 some, porque não há espaço depois dele. Daí (\\s|$): grupo com OU. Exemplo de |: (ovo|coco).
  • Resultado: só os hexadecimais válidos, 0xFFABC e 0x1. "Olha o tamanho da expressão para algo simples."

135 · O ponto e o exercício do e-mail

// .  qualquer caractere (curinga): "1.3" casa com 123, 133, 1@3, 1A3
String regex = "([a-zA-Z0-9\\._-])+@([a-zA-Z])+(\\.([a-zA-Z])+)+";
String texto = "luffy@hotmail.com, 123jotaro@gmail.com, #@!zoro@mail.br, teste@gmail.com.br, sakura@mail";
// find():  0 luffy@hotmail.com · 19 123jotaro@gmail.com · 43 zoro@mail.br · 57 teste@gmail.com.br

System.out.println("#@!zoro@mail.br".matches(regex));      // false: matches exige a String INTEIRA
System.out.println(texto.split(",")[1].trim());            // 123jotaro@gmail.com
System.out.println(Arrays.toString(texto.split(",")));     // o array legível
  • O ponto é curinga: casa com qualquer caractere. Para um ponto de verdade, escape-o: \. na regex, "\\." na String Java.
  • A regex do e-mail, por partes:
    • ([a-zA-Z0-9\\._-])+: o usuário, com letras, dígitos, ponto, _ e -, uma ou mais vezes.
    • @, literal.
    • ([a-zA-Z])+: o provedor, só letras.
    • (\\.([a-zA-Z])+)+: .com, .br... uma ou mais vezes, para aceitar .com.br. Sem esse + externo, teste@gmail.com.br virava só teste@gmail.com.
  • sakura@mail não casa (falta o .algo). De #@!zoro@mail.br o find pega só o pedaço válido zoro@mail.br: encontrar um padrão dentro do texto não é validar o texto.
  • Para validar uma String inteira: String.matches(regex), que só dá true se a String toda casar.
  • split(regex) quebra a String num array (o separador também é uma regex). Depois, trim() em cada parte. Arrays.toString(array) imprime o array legível.

136 · Âncora ^ e negação [^ ]

// No site de testes (ex.: regexr.com): passe o mouse na regex e ele explica cada parte.
"^\\w+"      // ^ fora do colchete = COMEÇO da linha: a primeira palavra
             // com a flag multiline, a primeira palavra de CADA linha
"[^abc]"     // ^ DENTRO do colchete = NEGAÇÃO: qualquer caractere que não seja a, b ou c

// Em Java (exemplo desta página, não está no repositório):
Pattern.compile("^\\w+", Pattern.MULTILINE).matcher("Levi soldado\nEren titan\nMikasa")
// → Levi · Eren · Mikasa
  • O William recomenda treinar num site de regex: você digita a expressão e o texto, vê o que casa na hora, e passar o mouse sobre cada parte mostra a explicação. É bem mais rápido que testar no Java.
  • ^ fora dos colchetes é âncora de começo, par do $ (fim). Por padrão vale para o começo do texto. Com a flag multiline (Pattern.MULTILINE em Java), vale para o começo de cada linha.
  • ^ logo depois de [ é negação: [^abc] = "tudo menos a, b e c". Case sensitive: A maiúsculo casa com [^abc].

Atenção

  • Barras em dobro no Java: a regex \d vira "\\d", e o ponto literal \. vira "\\.". Esquecer dá erro de compilação ("\d" é escape inválido) ou uma regex diferente da pretendida.
  • find() × matches(): find procura pedaços dentro do texto. matcher.matches() e String.matches exigem que o texto inteiro case.
  • O mesmo símbolo muda de sentido com o lugar: ^ (começo × negação dentro de [ ]), . (qualquer caractere × ponto literal dentro de [ ], onde não precisa de escape), - (intervalo × literal quando é o último do colchete, como em [._-]).
  • Extra: split usa regex. "a.b.c".split(".") devolve um array vazio (o ponto casa com tudo). Use split("\\."). O mesmo vale para |: split("\\|").
  • Extra: Pattern é imutável e thread-safe. Compile uma vez numa constante private static final Pattern EMAIL = Pattern.compile(...). String.matches recompila a cada chamada.
  • Extra: replaceAll(regex, troca): "(11) 98765-4321".replaceAll("\\D", "") dá "11987654321" (só os dígitos).
  • Extra: Pattern.CASE_INSENSITIVE (ou (?i) no começo da regex) ignora maiúsculas e minúsculas.

Paralelo com PHP

  • A mesma sintaxe (PCRE): o PHP usa preg_*, com a regex entre delimitadores: '/0[xX][0-9a-fA-F]+/'. A mesma regex funciona nos dois, mudando só as aspas e barras.
  • Barras: em PHP, com aspas simples, '/\d+/' já funciona. Em Java é "\\d+". A partir do Java 15, text blocks não ajudam aqui: a barra continua precisando de escape.
  • Equivalências:
    • while (matcher.find()) ≈ preg_match_all($re, $txt, $m, PREG_OFFSET_CAPTURE) (o offset é o start()).
    • String.matches(re) ≈ preg_match('/^...$/', $s) (no PHP você coloca as âncoras).
    • split(re) ≈ preg_split. Para separador fixo, explode(',', $s).
    • replaceAll ≈ preg_replace.
  • Flags: /m (multiline) ≈ Pattern.MULTILINE, /i ≈ Pattern.CASE_INSENSITIVE.
  • Validar e-mail: em PHP o recomendado é filter_var($email, FILTER_VALIDATE_EMAIL), e no Laravel a regra 'email' => 'email:rfc,dns' (que até consulta o DNS). A regex da aula é didática e não cobre todos os e-mails válidos. Em Java real, costuma-se usar a anotação @Email do Bean Validation.

package academy.devdojo.maratonajava.javacore.Uregex.test;

import java.util.Arrays;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class RegexTest01 {
    static void procurar(String regex, String texto) {
        Matcher matcher = Pattern.compile(regex).matcher(texto);
        StringBuilder sb = new StringBuilder(regex + " →");
        while (matcher.find()) {
            sb.append(" ").append(matcher.start()).append("[").append(matcher.group()).append("]");
        }
        System.out.println(sb);
    }

    public static void main(String[] args) {
        procurar("aba", "abababa");                                  // ?
        procurar("\\d", "@#hh_j2 12gvh21");                          // ?
        procurar("\\W", "@#hh_j2 12gvh21");                          // ?
        procurar("[a-cA-C]", "cafeBABE");                            // ?
        procurar("0[xX][0-9a-fA-F]", "12 0x 0X 0xFFABC 0x109 0x1"); // ?
        procurar("0[xX]([0-9a-fA-F])+(\\s|$)", "12 0x 0X 0xFFABC 0x10G 0x1"); // ?

        String email = "([a-zA-Z0-9\\._-])+@([a-zA-Z])+(\\.([a-zA-Z])+)+";
        String texto = "luffy@hotmail.com, 123jotaro@gmail.com, #@!zoro@mail.br, teste@gmail.com.br, sakura@mail";
        procurar(email, texto);                                      // ?
        System.out.println("#@!zoro@mail.br".matches(email));       // ?
        System.out.println("teste@gmail.com.br".matches(email));    // ?
        System.out.println(texto.split(",")[1].trim());             // ?

        Matcher m = Pattern.compile("^\\w+", Pattern.MULTILINE).matcher("Levi soldado\nEren titan\nMikasa");
        while (m.find()) System.out.print(m.group() + " ");         // ?
        System.out.println();
        System.out.println("(11) 98765-4321".replaceAll("\\D", ""));  // ? (extra)
        System.out.println(Arrays.toString("a.b.c".split(".")));      // ? (extra)
        System.out.println(Arrays.toString("a.b.c".split("\\.")));    // ? (extra)
    }
}

Glossário

  • Expressão regular (regex): padrão escrito com metacaracteres para achar ou validar trechos de texto.
  • Metacaractere: símbolo com significado especial na regex (\d, ., +, ^...).
  • Pattern: a regex compilada; imutável e reutilizável.
  • Matcher: aplica o Pattern a um texto (find, start, group, matches).
  • Range / classe de caracteres: [ ], um caractere dentre os listados ou intervalos.
  • Quantificador: quantas vezes o item anterior pode aparecer (? * + {n,m}).
  • Grupo: ( ), que junta partes para quantificar ou usar |.
  • Âncora: posição, e não caractere: ^ começo e $ fim da linha.
  • Escape: \ para usar um metacaractere como literal; em Java, \\.
  • Multiline: flag que faz ^ e $ valerem para cada linha.
