Resumo

Métodos também podem receber arrays. O varargs (variable arguments) é uma sintaxe mais recente e "mais bonitinha" para isso: com int... numeros, quem chama passa quantos valores quiser, separados por vírgula, e o Java monta o array sozinho. A aula 53 é um exercício que junta tudo desde a 39 (classe, atributos, arrays e métodos) e termina com a primeira NullPointerException "de verdade" do curso e como se proteger dela.

52 · Array como parâmetro

// Calculadora
public void somaArray(int[] numeros) {
    int soma = 0;
    for (int num : numeros) {
        soma += num;
    }
    System.out.println(soma);
}

// CalculadoraTest05
int[] numeros = {1, 2, 3, 4, 5};
calculadora.somaArray(numeros);                      // 15
calculadora.somaArray(new int[]{1, 2, 3, 4, 5});     // também funciona
  • O parâmetro declara o array igual a uma variável: int[] numeros.
  • Dá para criar o array direto na chamada, mas o William prefere separar a inicialização numa variável antes de passar, porque fica mais legível.

52 · Varargs

public void somaVarArgs(int... numeros) {       // tipo + ... + nome
    int soma = 0;
    for (int num : numeros) {
        soma += num;
    }
    System.out.println(soma);
}

calculadora.somaVarArgs(1, 2, 3, 4, 5, 6, 7);   // 28 — valores soltos
calculadora.somaVarArgs(numeros);               // também aceita um array pronto
  • A sintaxe é tipo... nome, com três pontos.
  • Por baixo dos panos é um array. A JVM transforma os argumentos num int[], e o debug mostra um array de 7 posições. O corpo do método é idêntico ao da versão com array.
  • A vantagem está só na chamada: você não precisa criar o array, basta passar os valores separados por vírgula. Continua aceitando um array pronto.
  • Regra: o varargs tem que ser o último parâmetro. (double valor, int... numeros) compila: o primeiro argumento vai para valor e o resto vira o array. Com 1 a 7, a soma dá 27 (o 1 foi para valor).
  • (int... numeros, double valor) não compila, porque o Java não saberia onde o array termina. Pelo mesmo motivo, só pode haver um varargs por método.
  • Até o main pode ser escrito assim: public static void main(String... args).

53 · Exercício: funcionário com média salarial

Crie uma classe Funcionario com nome, idade e salários (3 salários guardados num array). Crie dois métodos: um para imprimir os dados e outro para calcular e imprimir a média dos salários.

// dominio/Funcionario.java
public class Funcionario {
    public String nome;
    public int idade;
    public double[] salarios;

    public void imprime() {
        System.out.println(this.nome);
        System.out.println(this.idade);
        if (salarios == null) {
            return;                      // guard clause: sem salários, para aqui
        }
        for (double salario : salarios) {
            System.out.print(salario + " ");
        }
        imprimeMediaSalario();           // um método chamando outro do mesmo objeto
    }

    public void imprimeMediaSalario() {
        if (salarios == null) {
            return;                      // o método é public: pode ser chamado sozinho
        }
        double media = 0;                // variável local: precisa inicializar
        for (double salario : salarios) {
            media += salario;
        }
        media /= salarios.length;
        System.out.println("\nMédia salarial: " + media);
    }
}

// test/FuncionarioTest01.java
Funcionario funcionario = new Funcionario();
funcionario.nome = "Sanji";
funcionario.idade = 23;
funcionario.salarios = new double[]{1200, 987.32, 2000};
funcionario.imprime();
  • Resolva aos pouquinhos: primeiro a classe, depois o imprime, testa, e só então a média. "Primeiro chegue no resultado, depois melhore."
  • Os salários variam por mês (pense num vendedor com comissão). Por isso o array faz sentido. A classe não tem como limitar o array a 3: quem cria o objeto é que passa 3 valores.
  • System.out.println(funcionario.salarios) mostra a referência do array. É preciso percorrê-lo.
  • Imprimir salarios[0], [1] e [2] na mão "funciona", mas não escala: um quarto salário obrigaria a mexer no método. Com o foreach o método se adapta sozinho.
  • media é variável local, então precisa começar com 0. A média é a soma dividida por salarios.length.
  • imprime() chama imprimeMediaSalario() direto, sem variável de referência: os dois estão no mesmo objeto.

53 · A NullPointerException e as proteções

  • Se ninguém atribuir salarios, o atributo fica com o valor padrão de referência, null. Percorrê-lo lança NullPointerException na execução: você tentou usar algo que não existe.
  • Aprenda a ler o stack trace: ele mostra a pilha de chamadas (FuncionarioTest01.main → imprime → imprimeMediaSalario). As linhas azuis são clicáveis e levam direto à linha do erro.
  • A primeira correção foi if (salarios != null) { ... } envolvendo o laço. A versão final é uma guard clause: if (salarios == null) return; no começo, que deixa o resto do método sem aninhamento.
  • A validação fica nos dois métodos. imprimeMediaSalario é public, então alguém pode chamá-lo sem passar pelo imprime. Com private (próxima aula) só a própria classe o chamaria, mas ainda valeria manter a checagem.
  • No mundo real, o cliente "por descuido" vai esquecer de informar o salário, e seu código precisa estar preparado. Mais à frente, o jeito certo é impedir o objeto de existir sem salário (construtores e exceções).
  • Detalhe de sintaxe que o William mostra: um if sem chaves contendo um for funciona, porque o laço inteiro conta como uma instrução só. Funciona, mas "é bem feinho". Use chaves.

Atenção

  • O varargs vai sempre por último e é só um. (int... a, String b) e (int... a, int... b) não compilam.
  • Extra: varargs aceita zero argumentos. somaVarArgs() compila e recebe um array vazio (não null): a soma dá 0. Já o método com int[] exige que algo seja passado.
  • Extra: média com array vazio. new double[0] passa pelo if (salarios == null) e a divisão vira 0.0 / 0 = NaN. Uma validação mais completa: if (salarios == null || salarios.length == 0) return; (o curto-circuito do || evita a NPE).
  • Extra: você já usa varargs. System.out.printf("%s tem %d anos%n", nome, idade) e String.format(...) recebem Object... args. É por isso que aceitam quantos valores você quiser.
  • print não pula linha e println pula. Por isso o "\n" antes de "Média salarial".
  • O array é passado por referência (aulas 49–50): se o método alterar numeros[0], o array de quem chamou muda. Com varargs de valores soltos isso não importa, porque o array é criado na chamada.

Paralelo com PHP

  • Mesma ideia, sintaxe parecida: function soma(int ...$numeros) no PHP e void soma(int... numeros) em Java. Nos dois, o variádico é o último parâmetro e chega como array.
  • Passar um array pronto: o PHP exige o spread, soma(...$lista). O Java aceita o array direto, soma(lista).
  • Somar: o PHP tem array_sum($numeros). Em Java, por enquanto, é o laço. Mais à frente, Arrays.stream(numeros).sum() (programação funcional).
  • null: foreach (null as $s) no PHP dá um warning e segue. Em Java, percorrer null derruba o programa com NullPointerException. O nullsafe do PHP (?->) não existe em Java: aqui a guarda é o if (x == null).
  • Guard clauses: o if (! $this->salarios) return; que você usa no Laravel é exatamente o padrão da versão final da aula.

        }

Glossário

  • Varargs: parâmetro de quantidade variável (tipo... nome), recebido como array.
  • Argumentos variáveis: valores soltos, separados por vírgula, que o Java junta num array.
  • NullPointerException (NPE): exceção ao usar uma referência null como se apontasse para um objeto.
  • Stack trace: a lista de métodos que estavam sendo executados quando a exceção aconteceu.
  • Guard clause: validação no início do método que sai cedo com return.
  • NaN: "not a number", resultado de 0.0 / 0 com double.
  • printf: impressão formatada (%s, %d, %n), que usa varargs.
