Resumo

O ResultSet "é bem mais poderoso" do que só trazer dados de volta. Ele informa metadados da consulta (quantas colunas, nomes, tipos, tamanhos), pode andar para frente e para trás e ir direto a uma linha, e pode até atualizar, inserir e apagar registros sem escrever outro SQL. O que ele consegue fazer depende do driver, e para saber isso existe o DatabaseMetaData.

ResultSetMetaData md = rs.getMetaData();              // 263 · colunas da consulta
DatabaseMetaData dbmd = conn.getMetaData();           // 264 · o que o driver suporta
conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE); // 265–267

rs.updateString("name", ...); rs.updateRow();          // 266
rs.moveToInsertRow(); rs.updateString(...); rs.insertRow(); rs.deleteRow();         // 267

263 · ResultSetMetaData

public static void showProducerMetaData() {
    log.info("Showing Producer Metadata");
    String sql = "SELECT * FROM anime_store.producer";        // "não sei quais colunas vêm"
    try (Connection conn = ConnectionFactory.getConnection();
         Statement stmt = conn.createStatement();
         ResultSet rs = stmt.executeQuery(sql)) {
        ResultSetMetaData rsMetaData = rs.getMetaData();
        int columnCount = rsMetaData.getColumnCount();
        log.info("Columns count '{}'", columnCount);               // 2
        for (int i = 1; i <= columnCount; i++) {                  // colunas começam em 1
            log.info("Table name '{}'", rsMetaData.getTableName(i));        // producer
            log.info("Column name '{}'", rsMetaData.getColumnName(i));      // id / name
            log.info("Column size '{}'", rsMetaData.getColumnDisplaySize(i)); // 10 / 255
            log.info("Column type '{}'", rsMetaData.getColumnTypeName(i));  // INT / VARCHAR
        }
    } catch (SQLException e) {
        log.error("Error while trying to find all producers", e);
    }
}
  • rs.getMetaData() descreve as colunas do resultado: quantidade, nome da tabela, nome da coluna, tamanho de exibição e tipo.
  • getColumnType(i) devolve um código numérico (o 4 que confundiu o professor é java.sql.Types.INTEGER; VARCHAR é 12). O nome legível vem de getColumnTypeName(i).
  • Na primeira versão havia um rs.next() antes de ler os metadados, e na aula 264 o professor conta que testou e não precisa: os metadados existem mesmo sem ler nenhuma linha (e até com resultado vazio).
  • Para que serve: quando você não sabe exatamente quais colunas a consulta traz, por exemplo em relatórios gigantes com junção de várias tabelas vindos de outro sistema. Dá para descobrir as colunas em tempo de execução.

264 · DatabaseMetaData

Quem decide como o ResultSet se comporta é o driver (a implementação do JDBC). O conn.getMetaData() pergunta a ele o que é suportado.

public static void showDriverMetaData() {
    log.info("Showing Driver Metadata");
    try (Connection conn = ConnectionFactory.getConnection()) {
        DatabaseMetaData dbMetaData = conn.getMetaData();
        if (dbMetaData.supportsResultSetType(ResultSet.TYPE_FORWARD_ONLY)) {
            log.info("Supports TYPE_FORWARD_ONLY");
            if (dbMetaData.supportsResultSetConcurrency(ResultSet.TYPE_FORWARD_ONLY, ResultSet.CONCUR_UPDATABLE)) {
                log.info("And Supports CONCUR_UPDATABLE");
            }
        }
        // ... o mesmo para TYPE_SCROLL_INSENSITIVE e TYPE_SCROLL_SENSITIVE
    } catch (SQLException e) { ... }
}
// Supports TYPE_FORWARD_ONLY
// And Supports CONCUR_UPDATABLE
// Supports TYPE_SCROLL_INSENSITIVE
// And Supports CONCUR_UPDATABLE
// (TYPE_SCROLL_SENSITIVE: não suportado pelo driver do MySQL)

Tipo (como o cursor anda e se vê mudanças):

  • TYPE_FORWARD_ONLY (padrão): só para frente, uma linha por vez, com next().
  • TYPE_SCROLL_INSENSITIVE: navega para frente, para trás e para uma posição específica, mas é insensível a mudanças: é "como uma foto" guardada na memória. Se outra conexão alterar o banco enquanto você navega, você não vê.
  • TYPE_SCROLL_SENSITIVE: navega livremente e enxerga as alterações feitas por outros enquanto o ResultSet está aberto. É muito difícil de implementar, e pouquíssimos drivers suportam; o do MySQL não.

Concorrência (se dá para alterar pelo ResultSet): CONCUR_READ_ONLY (padrão, só leitura) ou CONCUR_UPDATABLE (dá para atualizar, inserir e deletar enquanto navega). O nome das constantes é esse mesmo, embora não tenha nada a ver com concorrência de threads.

265 · Navegando com TYPE_SCROLL_INSENSITIVE

try (Connection conn = ConnectionFactory.getConnection();
     Statement stmt = conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE);
     ResultSet rs = stmt.executeQuery("SELECT * FROM anime_store.producer;")) {
    log.info("Last row? '{}'", rs.last());              // true: foi para a última linha
    log.info("Row number '{}'", rs.getRow());            // 3
    log.info(Producer.builder().id(rs.getInt("id")).name(rs.getString("name")).build());

    log.info("First row? '{}'", rs.first());             // vai para a primeira · getRow() = 1
    log.info("Row Absolute? '{}'", rs.absolute(2));      // pula para a linha 2
    log.info("Row relative ? '{}'", rs.relative(-1));    // volta uma, relativo à atual · linha 1
    log.info("is last? '{}'", rs.isLast());              // false (só consulta, não move)
    log.info("is first? '{}'", rs.isFirst());            // true

    log.info("Last row? '{}'", rs.last());
    rs.next();                                           // passa da última
    log.info("After last row? '{}'", rs.isAfterLast());  // true
    while (rs.previous()) {                              // de baixo para cima
        log.info(Producer.builder().id(rs.getInt("id")).name(rs.getString("name")).build());
    }
}
  • Mover: next(), previous(), first(), last(), absolute(n) (linha n; aceita negativo, a partir do fim), relative(n) (n linhas a partir da atual; negativo volta), beforeFirst(), afterLast(). Todos devolvem boolean (se caiu numa linha válida).
  • Consultar sem mover: getRow() (número da linha atual), isFirst(), isLast(), isBeforeFirst(), isAfterLast().
  • "Última" é da consulta, não da tabela: com ORDER BY name DESC, a última linha passa a ser outra. O cursor anda sobre o resultado.
  • A pegadinha do previous(): se o cursor está na última linha, while (rs.previous()) começa pela penúltima e pula a última. Para percorrer tudo de baixo para cima, vá depois da última (rs.afterLast(), ou last() e depois next(), como no vídeo) e aí use previous().

266 · Atualizando registros com o ResultSet

public static List<Producer> findByNameAndUpdateToUpperCase(String name) {
    String sql = "SELECT * FROM anime_store.producer where name like '%%%s%%';".formatted(name);
    List<Producer> producers = new ArrayList<>();
    try (Connection conn = ConnectionFactory.getConnection();
         Statement stmt = conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE);
         ResultSet rs = stmt.executeQuery(sql)) {
        while (rs.next()) {
            rs.updateString("name", rs.getString("name").toUpperCase());  // altera na memória
//          rs.cancelRowUpdates();                                        // desfaria a alteração
            rs.updateRow();                                               // grava no banco
            producers.add(Producer.builder().id(rs.getInt("id")).name(rs.getString("name")).build());
        }
    } catch (SQLException e) { ... }
    return producers;
}

ProducerService.findByNameAndUpdateToUpperCase("Deen");   // Studio Deen → STUDIO DEEN
  • Caso de uso: você já está percorrendo os registros e quer aproveitar para alterá-los, sem escrever um UPDATE à parte.
  • rs.updateString("coluna", valor) (e updateInt, updateDouble...) muda o valor só no ResultSet, e o getString em seguida já devolve o novo valor. Sem rs.updateRow() nada vai para o banco, e foi exatamente o que aconteceu na primeira execução do professor.
  • rs.cancelRowUpdates() desfaz as alterações da linha antes do updateRow(). Use-o em vez de tentar "voltar" o valor à mão com outro updateString. Depois do updateRow(), não dá mais para cancelar.
  • O driver gera o UPDATE por baixo; você não escreve SQL de atualização.

267 · Inserindo e deletando registros com o ResultSet

public static List<Producer> findByNameAndInsertWhenNotFound(String name) {
    String sql = "SELECT * FROM anime_store.producer where name like '%%%s%%';".formatted(name);
    List<Producer> producers = new ArrayList<>();
    try (Connection conn = ConnectionFactory.getConnection();
         Statement stmt = conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE);
         ResultSet rs = stmt.executeQuery(sql)) {
        if (rs.next()) return producers;          // já existe: não insere
        insertNewProducer(name, rs);
        producers.add(getProducer(rs));
    } catch (SQLException e) { ... }
    return producers;
}

private static void insertNewProducer(String name, ResultSet rs) throws SQLException {
    rs.moveToInsertRow();                          // linha temporária especial
    rs.updateString("name", name);                 // preenche as colunas
    rs.insertRow();                                // INSERT no banco
}

private static Producer getProducer(ResultSet rs) throws SQLException {
    rs.beforeFirst();                              // volta ao início
    rs.next();                                     // a linha inserida, já com o id gerado
    return Producer.builder().id(rs.getInt("id")).name(rs.getString("name")).build();
}

public static void findByNameAndDelete(String name) {
    ... // mesmo Statement atualizável
    while (rs.next()) {
        log.info("Deleting '{}'", rs.getString("name"));
        rs.deleteRow();                            // DELETE direto, sem "confirmar"
    }
}

ProducerService.findByNameAndInsertWhenNotFound("A-1 pictures");  // Producer(id=13, name=A-1 pictures)
ProducerService.findByNameAndDelete("A-1 pictures");
  • Inserir: moveToInsertRow() leva o cursor para uma linha temporária, os updateXxx preenchem as colunas e insertRow() grava. Depois, moveToCurrentRow() (extra) volta à posição de antes.
  • Para devolver o registro com o id gerado sem fazer outra consulta, o professor volta com beforeFirst() e lê a linha (o driver do MySQL acrescenta a linha inserida ao resultado).
  • Refatoração ao vivo: o método ficou grande, então ele trocou o if/else por um retorno antecipado (if (rs.next()) return producers;) e extraiu insertNewProducer e getProducer com o IntelliJ (Refactor, Extract Method). "É assim que funciona refatoração."
  • Deletar: rs.deleteRow() apaga a linha atual direto no banco.
  • Com isso, "fizemos praticamente tudo com o ResultSet, sem escrever outra linha de SQL".

Atenção

  • Colunas de metadados começam em 1, como no getInt(1).
  • ResultSet padrão é FORWARD_ONLY e READ_ONLY. Para previous()/absolute()/updateRow(), crie o Statement com createStatement(TYPE_SCROLL_INSENSITIVE, CONCUR_UPDATABLE). Se não, vem SQLException.
  • updateXxx sem updateRow() não grava. cancelRowUpdates() só funciona antes do updateRow().
  • previous() a partir da última linha pula a última. Comece de afterLast().
  • findByNameAndDelete("") apaga todos: LIKE '%%' casa com tudo. O professor avisa: "se passar vazio, deleta todo mundo". Valide a entrada.
  • O findByNameAndInsertWhenNotFound devolve lista vazia quando o nome já existe: o return producers; sai antes de ler as linhas. Se a intenção é "buscar ou criar", o certo seria devolver os encontrados (como o firstOrCreate do Laravel).
  • Extra: ResultSet atualizável tem requisitos: a consulta deve vir de uma única tabela e incluir a chave primária (sem JOIN, sem colunas calculadas). É por isso que os exemplos usam SELECT * de producer.
  • Extra: cuidado com o "insensível": o TYPE_SCROLL_INSENSITIVE do MySQL carrega o resultado inteiro na memória. Com milhões de linhas, isso pesa.
  • SQL injection continua: estes métodos ainda montam o WHERE com formatted, e o PreparedStatement vem na aula 268.

Paralelo com PHP

  • Metadados: no PDO, $stmt->columnCount() e $stmt->getColumnMeta($i) (que começa em 0) devolvem nome, tabela, tipo e tamanho, o ResultSetMetaData. Do servidor e do driver: $pdo->getAttribute(PDO::ATTR_SERVER_VERSION) e ATTR_DRIVER_NAME. No Laravel, Schema::getColumnListing('producer') e Schema::getColumns('producer') descrevem a tabela.
  • Cursor rolável: o PDO tem PDO::ATTR_CURSOR => PDO::CURSOR_SCROLL e fetch(PDO::FETCH_ASSOC, PDO::FETCH_ORI_LAST)/FETCH_ORI_ABS, mas o pdo_mysql não suporta. Na prática, no PHP você faz fetchAll() e navega no array (end($rows), $rows[1], array_reverse), que é o equivalente ao "insensível": uma foto na memória.
  • Alterar pelo resultado ≈ Eloquent: foreach (Producer::where('name', 'like', '%Deen%')->get() as $p) { $p->name = strtoupper($p->name); $p->save(); } é o updateString + updateRow. O $p->refresh() (ou simplesmente não chamar save()) ≈ cancelRowUpdates. Producer::firstOrCreate(['name' => 'A-1 Pictures']) é o "busca e insere se não achar" feito do jeito certo, e Producer::where('name', 'like', '%A-1%')->delete() ≈ o deleteRow em loop.

package academy.devdojo.maratonajava.javacore.ZZIjdbc.test;

import academy.devdojo.maratonajava.javacore.ZZIjdbc.conn.ConnectionFactory;
import academy.devdojo.maratonajava.javacore.ZZIjdbc.dominio.Producer;

import java.sql.*;
import java.util.ArrayList;
import java.util.List;

public class ResultSetPraticaTest01 {
    static final String SELECT = "SELECT * FROM anime_store.producer ORDER BY id";

    static Producer producer(ResultSet rs) throws SQLException {
        return Producer.builder().id(rs.getInt("id")).name(rs.getString("name")).build();
    }

    static List<Producer> findAll(Connection conn) throws SQLException {
        List<Producer> list = new ArrayList<>();
        try (Statement stmt = conn.createStatement(); ResultSet rs = stmt.executeQuery(SELECT)) {
            while (rs.next()) list.add(producer(rs));
        }
        return list;
    }

    public static void main(String[] args) throws SQLException {
        try (Connection conn = ConnectionFactory.getConnection()) {
            // 263 · ResultSetMetaData (sem ler nenhuma linha)
            try (Statement stmt = conn.createStatement(); ResultSet rs = stmt.executeQuery(SELECT)) {
                ResultSetMetaData md = rs.getMetaData();
                System.out.println("colunas: " + md.getColumnCount());                          // ?
                for (int i = 1; i <= md.getColumnCount(); i++) {
                    System.out.println(md.getTableName(i) + "." + md.getColumnName(i) + " "
                            + md.getColumnTypeName(i) + " (Types=" + md.getColumnType(i) + ")"); // ?
                }
                System.out.println("tamanho de name: " + md.getColumnDisplaySize(2));           // ?
            }

            // 264 · DatabaseMetaData
            DatabaseMetaData db = conn.getMetaData();
            System.out.println(db.getDatabaseProductName() + " / " + db.getDriverName());       // ?
            System.out.println("FORWARD_ONLY? " + db.supportsResultSetType(ResultSet.TYPE_FORWARD_ONLY)
                    + " | SCROLL_INSENSITIVE? " + db.supportsResultSetType(ResultSet.TYPE_SCROLL_INSENSITIVE)
                    + " | SCROLL_SENSITIVE? " + db.supportsResultSetType(ResultSet.TYPE_SCROLL_SENSITIVE)); // ?

            try (Statement stmt = conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE);
                 ResultSet rs = stmt.executeQuery(SELECT)) {
                // 265 · navegando
                rs.last();        System.out.println(rs.getRow() + " " + producer(rs));        // ?
                rs.first();       System.out.println(rs.getRow() + " " + producer(rs));        // ?
                rs.absolute(2);   System.out.println(rs.getRow() + " " + producer(rs));        // ?
                rs.relative(-1);  System.out.println(rs.getRow() + " isFirst=" + rs.isFirst() + " isLast=" + rs.isLast()); // ?
                rs.afterLast();
                StringBuilder reverso = new StringBuilder();
                while (rs.previous()) reverso.append(rs.getString("name")).append(" | ");
                System.out.println("de baixo para cima: " + reverso);                          // ?

                // 266 · update pelo ResultSet
                rs.absolute(1);
                rs.updateString("name", "NHK ALTERADO");
                System.out.println("antes de cancelar: " + rs.getString("name"));              // ?
                rs.cancelRowUpdates();
                System.out.println("depois de cancelar: " + rs.getString("name"));             // ?
                rs.absolute(2);
                rs.updateString("name", rs.getString("name").toUpperCase());
                rs.updateRow();                                                                // grava

                // 267 · insert e delete pelo ResultSet
                rs.moveToInsertRow();
                rs.updateString("name", "A-1 Pictures");
                rs.insertRow();
                rs.moveToCurrentRow();
            }
            System.out.println("depois do insert: " + findAll(conn));                          // ?

            try (Statement stmt = conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE);
                 ResultSet rs = stmt.executeQuery("SELECT * FROM anime_store.producer WHERE name LIKE '%A-1%'")) {
                while (rs.next()) {
                    System.out.println("deletando " + rs.getString("name"));                    // ?
                    rs.deleteRow();
                }
            }
            System.out.println("final: " + findAll(conn));                                     // ?
        }
    }
}

Glossário

  • Metadados: dados sobre os dados (colunas, tipos, tamanhos, recursos do driver).
  • ResultSetMetaData: descrição das colunas de um resultado.
  • DatabaseMetaData: informações e recursos do banco/driver da conexão.
  • java.sql.Types: constantes numéricas dos tipos SQL (INTEGER = 4, VARCHAR = 12...).
  • TYPE_FORWARD_ONLY: cursor que só anda para frente (padrão).
  • TYPE_SCROLL_INSENSITIVE: cursor livre que não vê alterações feitas depois da consulta.
  • TYPE_SCROLL_SENSITIVE: cursor livre que vê as alterações (raro nos drivers).
  • CONCUR_READ_ONLY / CONCUR_UPDATABLE: resultado só de leitura / alterável.
  • absolute(n) × relative(n): ir à linha n × andar n linhas a partir da atual.
  • Linha de inserção: linha temporária (moveToInsertRow) usada para montar um INSERT.
  • Refatoração: melhorar a estrutura do código sem mudar o comportamento (ex.: extrair método).
