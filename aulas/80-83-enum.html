Resumo

Muitos atributos só podem assumir poucas opções fixas: tipo de cliente (pessoa física ou jurídica), dia da semana, período do dia, forma de pagamento. Guardar isso numa String deixa a porta aberta para "Pessoa_juridica", "pessoa fisica" e outras variações. Uma enumeração (enum) é um tipo especial de classe que lista as únicas opções válidas, e o compilador não aceita outra coisa. E, por ser uma classe, o enum pode ter atributos, construtor e métodos.

80 · O problema e o enum

// Com String: cada um escreve de um jeito
new Cliente("Tsubasa", "PESSOA_FISICA");
new Cliente("Tsubasa", "Pessoa_juridica");   // compila... e suja o banco de dados

// Com enum
public enum TipoCliente {
    PESSOA_FISICA,
    PESSOA_JURIDICA
}

public class Cliente {
    private String nome;
    private TipoCliente tipoCliente;          // Cliente TEM UM TipoCliente
    public Cliente(String nome, TipoCliente tipoCliente) { ... }
}

new Cliente("Tsubasa", TipoCliente.PESSOA_FISICA);
// new Cliente("Tsubasa", "PESSOA_FISICA");   // NÃO compila: o tipo é TipoCliente
  • A inconsistência de dados: com String, outra pessoa da equipe escreve "Pessoa_juridica" e o código aceita. Com 15 milhões de registros no banco, corrigir isso depois "dá um trabalhão".
  • Validar a String (if (!tipo.equals("PESSOA_FISICA") && ...)) até funciona, mas é feio e fácil de esquecer. Detalhe da aula: Strings se comparam com equals (ou equalsIgnoreCase), não com ==. Isso volta mais à frente.
  • enum se cria como uma classe (public enum TipoCliente, com as mesmas regras de nome). Os valores listados são como constantes public static final do tipo TipoCliente, e por isso usam MAIÚSCULAS e se acessam por TipoCliente.PESSOA_FISICA.
  • Qual o tipo de PESSOA_FISICA? É TipoCliente. Não é String nem int.
  • O enum força quem cria o objeto a escolher uma das opções. Para aceitar uma nova, é preciso acrescentá-la ao enum. O William: "gosto muito disso no Java, que é fortemente tipado e evita erros".
  • O toString() padrão de uma constante é o nome exatamente como está escrito: PESSOA_FISICA.
  • Quando usar: uma quantidade limitada de opções. A velocidade limite da aula 77, por exemplo, é um valor só, e continua sendo uma constante.

81 · Enum dentro de classe, atributos e construtor

public enum TipoCliente {
    PESSOA_FISICA(1, "Pessoa Física"),       // chama o construtor
    PESSOA_JURIDICA(2, "Pessoa Jurídica");   // ← ponto e vírgula antes dos atributos

    private int valor;                        // atributos vêm DEPOIS das constantes
    private String nomeRelatorio;

    TipoCliente(int valor, String nomeRelatorio) {   // construtor (sempre private)
        this.valor = valor;
        this.nomeRelatorio = nomeRelatorio;
    }

    public int getValor() { return valor; }
    public String getNomeRelatorio() { return nomeRelatorio; }
}

Cliente cliente1 = new Cliente("Tsubasa", TipoCliente.PESSOA_FISICA, TipoPagamento.DEBITO);
Cliente cliente2 = new Cliente("Akira", TipoCliente.PESSOA_JURIDICA, TipoPagamento.CREDITO);
// Cliente{nome='Tsubasa', tipoCliente=Pessoa Física, tipoClienteInt=1, tipoPagamento=DEBITO}
  • Enum dentro de classe: dá para declarar public enum TipoPagamento { DEBITO, CREDITO } dentro de Cliente, com uso Cliente.TipoPagamento.DEBITO ou importando Cliente.TipoPagamento. É possível, mas o William prefere um arquivo separado, e na aula 82 ele move o enum para fora.
  • O caso real: o banco já guarda o tipo como número (1 = pessoa física, 2 = jurídica). O enum mantém esse número e um nome legível, e quem usa só precisa lembrar de PESSOA_FISICA.
  • PESSOA_FISICA(1, "Pessoa Física") chama o construtor do enum. Sem um construtor com esses parâmetros, não compila.
  • O construtor de um enum é sempre privado: ninguém de fora cria uma constante nova com new. O Java cria cada constante uma vez.
  • Os atributos ficam depois da lista de constantes, e a lista termina com ;. Mover um atributo para antes não compila.
  • Sem setters: o valor de uma constante não deve mudar. O William sugere até private final int valor. static não serve aqui, porque cada constante tem o seu valor, atribuído no construtor.
  • Detalhe da aula: um atributo sem modificador de acesso tem visibilidade de pacote ("default"). Qualquer classe do mesmo pacote o acessa direto.

82 · Um comportamento por constante

public enum TipoPagamento {
    DEBITO {
        @Override
        public double calcularDesconto(double valor) {
            return valor * 0.1;     // 10%
        }
    }, CREDITO {
        @Override
        public double calcularDesconto(double valor) {
            return valor * 0.05;    // 5%
        }
    };

    public abstract double calcularDesconto(double valor);   // sem corpo: cada constante implementa
}

System.out.println(TipoPagamento.DEBITO.calcularDesconto(100));    // 10.0
System.out.println(TipoPagamento.CREDITO.calcularDesconto(100));   // 5.0
  • O problema: o desconto depende da forma de pagamento. O jeito ingênuo é espalhar if (tipo == DEBITO) ... else ... pelo código.
  • Cada constante pode ter um corpo próprio entre chaves, "como se fosse uma classe", e sobrescrever um método do enum (Ctrl+O mostra o que dá para sobrescrever).
  • Começando com um método comum que retorna 0, a versão certa é torná-lo abstract: sem corpo, terminado em ;. Assim, toda constante é obrigada a implementá-lo. Esquecer em uma dá erro de compilação. Métodos abstratos voltam nas aulas 84–86.
  • O resultado é zero if: tipoPagamento.calcularDesconto(valor) já executa a regra certa. O William adianta que isso é a base do padrão de projeto Strategy.

83 · Buscar a constante por um atributo

// valueOf: pelo NOME da constante
TipoCliente tipoCliente = TipoCliente.valueOf("PESSOA_FISICA");
System.out.println(tipoCliente.getNomeRelatorio());          // Pessoa Física

// Busca por outro atributo: você mesmo escreve
public static TipoCliente tipoClientePorNomeRelatorio(String nomeRelatorio) {
    for (TipoCliente tipoCliente : values()) {                // values(): todas as constantes
        if (tipoCliente.getNomeRelatorio().equals(nomeRelatorio)) {
            return tipoCliente;
        }
    }
    return null;                                              // não achou
}

TipoCliente.tipoClientePorNomeRelatorio("Pessoa Física");     // PESSOA_FISICA
TipoCliente.tipoClientePorNomeRelatorio("Pessoa Física221");  // null
  • Todo enum ganha dois métodos estáticos prontos: values(), que devolve um array com todas as constantes na ordem declarada, e valueOf(String), que busca pelo nome da constante.
  • valueOf("Pessoa Física") não funciona, porque o nome da constante é PESSOA_FISICA. Para buscar por um atributo (o nome do relatório, o valor 1/2 do banco), escreva um método static que percorre values().
  • É um static porque você ainda não tem uma constante: é justamente ela que está procurando.

Atenção

  • A lista de constantes vem primeiro e termina com ; quando há algo depois (atributos, construtor, métodos).
  • Não existe new TipoCliente(...). O construtor é privado e as constantes são criadas pelo próprio Java.
  • Extra: valueOf com nome inexistente não retorna null: lança IllegalArgumentException. Já o método da aula retorna null, então quem chama precisa checar. Mais à frente, Optional é a alternativa ao null.
  • Extra: comparar enum com == é seguro, porque cada constante existe uma vez só. tipo == TipoCliente.PESSOA_FISICA funciona, diferente de String.
  • Extra: enum no switch (aulas 25–26): case PESSOA_FISICA:, sem o prefixo TipoCliente..
  • Extra: não salve o ordinal() no banco. ordinal() é a posição da constante (0, 1, ...), e muda se alguém reordenar ou inserir constantes. Por isso a aula usa um atributo valor explícito. name() devolve o nome, mesmo que o toString() seja sobrescrito.
  • Extra: um enum não pode estender outra classe (ele já estende java.lang.Enum), mas pode implementar interfaces (aulas 87–89).

Paralelo com PHP

  • O PHP 8.1 também tem enums: enum TipoCliente: int { case PESSOA_FISICA = 1; case PESSOA_JURIDICA = 2; }. Acesso: TipoCliente::PESSOA_FISICA.
  • Métodos prontos: cases() ≈ values(). TipoCliente::from(1) busca pelo valor e tryFrom(9) devolve null se não achar, como o método da aula 83. Em Java, a busca por atributo você escreve.
  • Mais dados por constante em Java: o backed enum do PHP tem um valor escalar (int ou string). Em Java, cada constante pode ter vários atributos (valor e nomeRelatorio) via construtor.
  • Comportamento por constante: no PHP você faria match($this) { self::DEBITO => $v * 0.1, ... } dentro do método. Em Java, cada constante pode ter o próprio corpo sobrescrevendo um método abstract, como na aula 82.
  • Laravel: o $casts = ['tipo' => TipoCliente::class] converte a coluna do banco no enum. É o mesmo papel do valor 1/2 da aula 81, e em Java o JPA faz isso com @Enumerated ou conversores.

Glossário

  • Enumeração (enum): tipo especial de classe com um conjunto fixo de instâncias (as constantes).
  • Constante de enum: cada valor listado (PESSOA_FISICA), com o tipo do próprio enum.
  • Inconsistência de dados: o mesmo conceito gravado de formas diferentes ("PF", "pessoa física"...).
  • Corpo específico de constante: bloco { } após uma constante para sobrescrever métodos só para ela.
  • Método abstrato: método sem corpo que obriga a implementação (aulas 84–86).
  • values() / valueOf(): todas as constantes / constante pelo nome.
  • Fortemente tipado: o compilador verifica os tipos e impede valores fora do esperado.
