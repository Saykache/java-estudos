Resumo

Com atributos public, qualquer classe lê e grava o que quiser, e nada impede um pessoa.idade = -1. A partir daqui os atributos ficam private, e o acesso passa por métodos públicos, os getters e setters. É uma camada no meio que permite validar e mudar a implementação sem quebrar quem usa a classe. A aula 57 traz a sobrecarga: vários métodos com o mesmo nome e parâmetros diferentes, para evoluir a classe sem quebrar quem já a usa.

54 · Acoplamento e o modificador private

  • Coesão (aula 41): quanto uma classe se limita a um propósito. Alta é bom.
  • Acoplamento: quanto uma classe conhece e depende de outra. Baixo é bom. Se PessoaTest01 mexe direto em pessoa.idade, qualquer mudança em Pessoa (como bloquear idade negativa) afeta o teste. As duas estão fortemente acopladas.
  • private: o atributo só pode ser acessado de dentro do próprio objeto. Para as outras classes, "é como se não existisse". É a analogia da carteira: você não deveria nem saber que existe uma nota de 100 reais na carteira de outra pessoa.
  • Com o atributo private, pessoa.nome = "Jiraya" no teste não compila. Dentro da classe (this.nome no imprime) continua funcionando.

54 · Setters e getters

public class Pessoa {
    private String nome;
    private int idade;

    public void setNome(String nome) {
        this.nome = nome;            // sem this, "nome = nome" não altera nada
    }

    public void setIdade(int idade) {
        if (idade < 0) {
            System.out.println("Idade inválida");
            return;                  // a validação fica num lugar só
        }
        this.idade = idade;
    }

    public String getNome() {
        return nome;                 // this é opcional aqui: não há outro "nome"
    }

    public int getIdade() {
        return idade;
    }
}

// PessoaTest01
Pessoa pessoa = new Pessoa();
pessoa.setNome("Jiraya");
pessoa.setIdade(-1);                 // "Idade inválida": o valor não entra
System.out.println(pessoa.getNome());
  • Setter: public void set + nome do atributo em camelCase (setNome), recebendo um parâmetro do mesmo tipo. Não retorna nada.
  • Getter: public Tipo get + nome (getNome), sem parâmetros, retornando o valor em memória com o mesmo tipo do atributo.
  • O parâmetro costuma ter o mesmo nome do atributo, e aí o this é obrigatório: nome = nome só atribui o parâmetro a ele mesmo e, ao final do método, nada mudou. Com um nome diferente (setNome(String x) → nome = x), o this seria dispensável.
  • Os nomes get e set não são obrigatórios para o compilador, mas é uma convenção extremamente forte: qualquer dev Java entende na hora o que o método faz.
  • A vitória: a validação de idade entrou dentro de setIdade e o teste continuou compilando. Enquanto a assinatura (o contrato) se mantém, o que acontece dentro do método não afeta quem chama. Isso é baixo acoplamento.
  • Com um setter void, System.out.println(pessoa.setNome(...)) não compila. Para ler, use o getter.

55 · O que a variável de referência enxerga

  • De fora do objeto, a variável de referência (o "controle remoto") só tem botões para o que é public: setNome, getNome, imprime... Os atributos private não aparecem.
  • Dentro do objeto, tudo é acessível, inclusive os próprios getters. Dá para escrever getNome() dentro do imprime, mas o William não aconselha: dentro da classe, use o atributo direto (this.nome).
  • Acoplamento mora na assinatura. Mudar a assinatura de um método público (parâmetros, retorno ou torná-lo private) quebra todas as classes que o chamam. Mudar só o corpo não quebra.

56 · Todos private, geração automática e atributo só leitura

public class Funcionario {
    private String nome;
    private int idade;
    private double[] salarios;
    private double media;            // calculada pela própria classe

    public void imprimeMediaSalario() {
        if (salarios == null) return;
        for (double salario : salarios) {
            media += salario;
        }
        media /= salarios.length;
        System.out.println("Média salarial: " + media);
    }

    public double getMedia() {       // tem get...
        return media;
    }
    // ...mas NÃO tem setMedia: ninguém de fora altera a média
}
  • Na classe Funcionario, todos os atributos viram private, e o teste passa a usar setNome, setIdade e setSalarios.
  • Getters e setters são trabalho repetitivo, e a IDE gera: Alt+Insert → Getter and Setter (ou só Getter / só Setter), selecionando os atributos.
  • Nem todo atributo deve ter set. A media é calculada pela própria classe. Com um setMedia, qualquer um poderia gravar uma média falsa. Removendo o setter, ela fica somente leitura: só a classe grava e todos podem ler pelo getMedia(). Alguns atributos nem getter terão, porque são de uso interno.
  • O atributo de classe já nasce com 0, então a média não precisa ser inicializada. Só que getMedia() devolve 0 até alguém chamar a impressão, o que é uma questão de regra de negócio para pensar depois.

57 · Sobrecarga de métodos

// javacore.Csobrecargametodos.dominio.Anime
public void init(String nome, String tipo, int episodios) {
    this.nome = nome;
    this.tipo = tipo;
    this.episodios = episodios;
}

public void init(String nome, String tipo, int episodios, String genero) {
    this.init(nome, tipo, episodios);   // reaproveita o init de 3 parâmetros
    this.genero = genero;
}

// AnimeTest01
anime.init("Akudama Drive", "TV", 12);            // continua funcionando
anime.init("Akudama Drive", "TV", 12, "Ação");    // versão nova
  • O cenário: uma classe Anime (tipo, episódios) começa com setters, um por linha. Vem uma "mudança de requisito": acrescentar o nome. Para não precisar de três linhas de set, surge um método init que inicializa tudo de uma vez.
  • Depois chega outro requisito: o genero. Mudar o init para 4 parâmetros alteraria o contrato e quebraria todo mundo que chama com 3. Numa equipe espalhada por fusos horários, você quebra o código no fim do seu dia e os colegas que ainda estão trabalhando ficam parados.
  • Criar um init2 "funciona", mas é feio: dois nomes para a mesma ideia.
  • Sobrecarga: métodos com o mesmo nome e quantidade ou tipos de parâmetros diferentes. O Java escolhe qual executar pelos argumentos da chamada.
  • O modificador de acesso e o tipo de retorno não contam para a sobrecarga. Só contam o nome e a lista de parâmetros.
  • Evite repetir código: o init de 4 parâmetros delega para o de 3 (this.init(nome, tipo, episodios)) e só acrescenta o gênero. No debug (Shift+F9, F8) dá para ver a execução entrar num e depois no outro. Ctrl+P mostra as duas opções.
  • Sem ambiguidade: se duas versões ficassem indistinguíveis numa chamada, o compilador não saberia qual escolher e dá erro.
  • Costume do William: getters e setters no fim da classe, depois dos atributos e dos métodos com lógica, que "são mais importantes".

Atenção

  • Esquecer o this no setter é o erro clássico: compila, roda, e o atributo continua null ou 0.
  • Só o tipo de retorno diferente não é sobrecarga: int calcula() e double calcula() na mesma classe não compilam. Nomes de parâmetros diferentes com os mesmos tipos também não: m(int a) e m(int b) são o mesmo método.
  • Extra: getter de boolean usa is: isAtivo() no lugar de getAtivo(). A IDE já gera assim.
  • Extra: getter de array vaza o objeto. getSalarios() devolve a referência do array, e quem recebe pode alterar salarios[0] por fora, contornando o private (aulas 49–50). Quando isso importa, devolva uma cópia: return salarios.clone();.
  • Extra: sobrecarga com promoção de tipo. Com m(long x) e m(double x), a chamada m(5) escolhe long, a conversão "mais próxima" do int.
  • Extra: this.init(...) é uma chamada de método comum. Não confunda com this(...), que chama outro construtor (aulas 58–59) e é o jeito mais comum de fazer essa mesma delegação.
  • private é por classe, não por objeto: um método de Pessoa pode ler o nome privado de outra Pessoa recebida por parâmetro.

Paralelo com PHP

  • Visibilidade igual: public, private e protected funcionam do mesmo jeito. O protected vem com herança.
  • PHP não tem sobrecarga. Declarar dois métodos com o mesmo nome dá fatal error. No PHP você usa parâmetro opcional ($genero = null), argumentos nomeados ou __call. Em Java, que não tem parâmetros opcionais, a sobrecarga cumpre esse papel.
  • Getters e setters × Eloquent: no Laravel você raramente escreve getters, porque o Model expõe os atributos "por mágica", e os accessors/mutators (Attribute::make(get: ..., set: ...)) fazem o papel do get/set com lógica, como a validação de idade.
  • Só leitura: o readonly do PHP 8.1 e a visibilidade assimétrica do PHP 8.4 (public private(set)) equivalem ao "tem getter, não tem setter" da aula 56.
  • Menos código repetido: o PHP tem constructor property promotion. Em Java o equivalente moderno são os record (Java 16+), e muitos projetos usam o Lombok (@Getter @Setter) para gerar getters e setters.

package academy.devdojo.maratonajava.javacore.Csobrecargametodos.dominio;

public class Anime {
    private String nome;
    private String tipo;
    private int episodios;
    private String genero;

    public void init(String nome, String tipo, int episodios) {
        this.nome = nome;
        this.tipo = tipo;
        setEpisodios(episodios);
    }

    public void init(String nome, String tipo, int episodios, String genero) {
        this.init(nome, tipo, episodios);
        this.genero = genero;
    }

    public void imprime() {
        System.out.println(nome + " | " + tipo + " | " + episodios + " | " + genero);
    }

    public void setEpisodios(int episodios) {
        if (episodios < 0) {
            System.out.println("Episódios inválidos");
            return;
        }
        this.episodios = episodios;
    }

    public int getEpisodios() {
        return episodios;
    }
}
EOF

Glossário

  • Acoplamento: grau de dependência entre classes. Baixo acoplamento é o desejável.
  • Encapsulamento: esconder o estado interno (private) e expor só uma interface pública controlada.
  • Modificador de acesso: public, private (e protected/padrão, mais à frente).
  • Getter: método que devolve o valor de um atributo (getNome(), isAtivo()).
  • Setter: método que altera o valor de um atributo, podendo validar (setIdade(int)).
  • Somente leitura: atributo com getter e sem setter.
  • Sobrecarga (overloading): métodos com o mesmo nome e listas de parâmetros diferentes.
  • Assinatura: nome mais os tipos dos parâmetros. O retorno não faz parte.
