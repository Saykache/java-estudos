Resumo

Fechamento do java.time. O ChronoUnit mede intervalos em qualquer unidade (resolve o "58 semanas são quantos meses?"). Os TemporalAdjusters "pulam" para uma data (próxima quinta, último dia do mês), e dá para criar o seu (próximo dia útil). ZoneId/ZonedDateTime/OffsetDateTime tratam fusos. O DateTimeFormatter formata e faz parse. O bloco termina com o ResourceBundle, que traduz as mensagens do sistema conforme o Locale.

125 · ChronoUnit

LocalDateTime aniversario = LocalDateTime.of(1988, Month.AUGUST, 6, 12, 0, 0);
LocalDateTime now = LocalDateTime.now();
System.out.println(ChronoUnit.DAYS.between(aniversario, now));    // 11884 (em 18/02/2021 18h)
System.out.println(ChronoUnit.WEEKS.between(aniversario, now));   // 1697
System.out.println(ChronoUnit.MONTHS.between(aniversario, now));  // 390
System.out.println(ChronoUnit.YEARS.between(aniversario, now));   // 32

// De volta ao problema da aula 124: 58 semanas (406 dias) são quantos meses?
LocalDate hoje = LocalDate.now();
hoje.until(hoje.plusDays(406), ChronoUnit.MONTHS);   // 13 (o total, não o componente)
hoje.until(hoje.plusDays(406), ChronoUnit.DAYS);     // 406
  • ChronoUnit é um enum com todas as unidades de tempo: NANOS, MICROS, MILLIS, SECONDS... DAYS, WEEKS, MONTHS, YEARS, DECADES, CENTURIES...
  • UNIDADE.between(inicio, fim) devolve um long com o total de unidades completas. "Seu filho tem quantas semanas?": agora o sistema responde.
  • data.until(outra, unidade) faz o mesmo a partir do objeto. É a resposta para o Period.getMonths() que não normalizava (aula 124).
  • O William resume o pacote: Instant para a máquina, LocalDate/LocalDateTime/LocalTime para humanos, Duration/Period para quantidades e ChronoUnit para intervalos.

126 · with e TemporalAdjusters

LocalDate now = LocalDate.now();                              // quinta, 18/02/2021
now = now.with(ChronoField.DAY_OF_MONTH, 18);                 // troca só o dia (= withDayOfMonth(18))
now = LocalDate.now().with(TemporalAdjusters.nextOrSame(DayOfWeek.THURSDAY));  // 2021-02-18 (hoje é quinta)
now = LocalDate.now().with(TemporalAdjusters.next(DayOfWeek.THURSDAY));        // 2021-02-25
now = LocalDate.now().with(TemporalAdjusters.previous(DayOfWeek.THURSDAY));    // 2021-02-11
now = LocalDate.now().with(TemporalAdjusters.firstDayOfMonth());               // 2021-02-01 MONDAY
now = LocalDate.now().with(TemporalAdjusters.lastDayOfMonth());                // 2021-02-28 SUNDAY
now = LocalDate.now().with(TemporalAdjusters.firstDayOfNextYear());            // 2022-01-01 SATURDAY
now = LocalDate.now().with(TemporalAdjusters.firstDayOfNextMonth());           // 2021-03-01 MONDAY
  • plus × with: plusDays(20) anda no calendário e pode virar o mês. with substitui um campo e deixa o resto igual: withDayOfMonth(20), withMonth(1), with(ChronoField.DAY_OF_MONTH, 20).
  • TemporalAdjuster (singular) é uma interface com um único método. TemporalAdjusters (plural) é uma classe utilitária com métodos static que devolvem ajustadores prontos.
  • nextOrSame devolve hoje se hoje já for o dia pedido. next sempre avança. previous/previousOrSame voltam.
  • lastDayOfMonth() poupa a conta "28, 29, 30 ou 31?". Também existem firstDayOfYear, lastDayOfYear, firstInMonth(DayOfWeek)...
  • Como tudo é imutável, cada linha começa de LocalDate.now() e reatribui.

127 · TemporalAdjuster próprio: próximo dia útil

// Regra do exercício: sexta, sábado e domingo NÃO são dias úteis.
class ObterProximoDiaUtil implements TemporalAdjuster {      // não pública: pode ficar no mesmo arquivo
    @Override
    public Temporal adjustInto(Temporal temporal) {
        DayOfWeek dayOfWeek = DayOfWeek.of(temporal.get(ChronoField.DAY_OF_WEEK));
        int addDays;
        switch (dayOfWeek) {
            case THURSDAY: addDays = 4; break;   // quinta → segunda
            case FRIDAY:   addDays = 3; break;
            case SATURDAY: addDays = 2; break;
            default:       addDays = 1;          // domingo → segunda; seg/ter/qua → dia seguinte
        }
        return temporal.plus(addDays, ChronoUnit.DAYS);
    }
}

LocalDate.now().with(new ObterProximoDiaUtil());                    // qui 18/02 → 2021-02-22 MONDAY
LocalDate.now().withDayOfMonth(15).with(new ObterProximoDiaUtil()); // seg 15/02 → 2021-02-16 TUESDAY
// 19 (sex), 20 (sáb) e 21 (dom) → 2021-02-22 MONDAY
  • Quando nenhum ajustador pronto resolve, implemente a interface TemporalAdjuster e escreva a regra de negócio em adjustInto.
  • Regra do arquivo: um .java pode ter várias classes, mas só uma pública, com o mesmo nome do arquivo. Por isso ObterProximoDiaUtil fica sem public.
  • DayOfWeek.of(temporal.get(ChronoField.DAY_OF_WEEK)) transforma o número (1 = segunda ... 7 = domingo) no enum. O switch com enum usa case THURSDAY, sem prefixo (aulas 80–83).
  • temporal.plus(n, ChronoUnit.DAYS) devolve a data ajustada. O William ajustou a regra ao testar: faltava o caso da quinta.
  • Polimorfismo de novo: with aceita qualquer TemporalAdjuster e chama adjustInto. Ele não sabe qual implementação recebeu (aulas 90–94).

128 · ZoneId, ZonedDateTime e OffsetDateTime

Map<String, String> shortIds = ZoneId.SHORT_IDS;     // ex.: BET=America/Sao_Paulo (Map = chave → valor)
System.out.println(ZoneId.systemDefault());           // Europe/Berlin na máquina do William
ZoneId tokyoZone = ZoneId.of("Asia/Tokyo");            // id inválido ("Asia/Pequim") → exceção

LocalDateTime now = LocalDateTime.now();              // 2021-02-19T18:03 (sem zona)
ZonedDateTime zonedDateTime = now.atZone(tokyoZone);   // 2021-02-19T18:03+09:00[Asia/Tokyo]  ← só "cola" a zona

Instant nowInstant = Instant.now();                   // 2021-02-19T17:03:00Z (UTC)
ZonedDateTime zonedDateTime2 = nowInstant.atZone(tokyoZone);   // 2021-02-20T02:03+09:00[Asia/Tokyo] ← converte

System.out.println(ZoneOffset.MIN);                   // -18:00
System.out.println(ZoneOffset.MAX);                   // +18:00
ZoneOffset offsetManaus = ZoneOffset.of("-04:00");    // "-400" → exceção em tempo de execução
OffsetDateTime o1 = now.atOffset(offsetManaus);        // 2021-02-19T18:03-04:00
OffsetDateTime o2 = OffsetDateTime.of(now, offsetManaus);   // o mesmo
OffsetDateTime o3 = nowInstant.atOffset(offsetManaus);      // 2021-02-19T13:03-04:00 (hora de Manaus)

JapaneseDate.from(LocalDate.of(2021, 2, 19));          // Japanese Reiwa 3-02-19
JapaneseDate.from(LocalDate.of(1900, 2, 1));           // Japanese Meiji 33-02-01
  • ZoneId identifica a zona pelo nome da região (America/Sao_Paulo, Asia/Tokyo). Os nomes não batem com os do Windows ("Brasília"): use os do Java. ZoneId.SHORT_IDS é um Map (coleção chave → valor, assunto futuro) com apelidos.
  • ZonedDateTime é data, hora e zona. A diferença importa:
    • localDateTime.atZone(zona) mantém a hora e só diz "isso é em Tóquio".
    • instant.atZone(zona) converte o momento UTC para a hora de Tóquio (+9h).
  • ZoneOffset é o deslocamento fixo em relação ao UTC, de −18:00 a +18:00. Serve quando você sabe a diferença (Manaus = −4) mas não o nome da zona. O formato tem que ser exato: "-04:00".
  • OffsetDateTime é data, hora e offset, sem regras de zona. ZonedDateTime carrega a zona (com horário de verão). OffsetDateTime só o número.
  • Outros calendários: JapaneseDate mostra as eras japonesas (Meiji em 1900, Reiwa hoje). Também existem ThaiBuddhistDate, HijrahDate e MinguoDate.

129 · DateTimeFormatter

LocalDate date = LocalDate.now();                            // 2021-02-19
date.format(DateTimeFormatter.BASIC_ISO_DATE);               // 20210219
date.format(DateTimeFormatter.ISO_DATE);                     // 2021-02-19 (aceita offset: 2021-02-19+05:00)
date.format(DateTimeFormatter.ISO_LOCAL_DATE);               // 2021-02-19 (o padrão do toString)
LocalDate.parse("20210219", DateTimeFormatter.BASIC_ISO_DATE);        // 2021-02-19
LocalDate.parse("2021-02-19+05:00", DateTimeFormatter.ISO_DATE);      // 2021-02-19
// LocalDate.parse("2021-02-19+05:00", DateTimeFormatter.ISO_LOCAL_DATE) → DateTimeParseException

LocalDateTime.now().format(DateTimeFormatter.ISO_DATE_TIME);          // 2021-02-19T18:46:04.1121294
LocalDateTime.parse("2021-02-19T18:46:04.1121294", DateTimeFormatter.ISO_DATE_TIME);

DateTimeFormatter formatterBR = DateTimeFormatter.ofPattern("dd/MM/yyyy");   // EUA: MM/dd/yyyy · Japão: yyyy/MM/dd
LocalDate.now().format(formatterBR);                          // 19/02/2021
LocalDate.parse("19/02/2021", formatterBR);                   // 2021-02-19

DateTimeFormatter formatterGR = DateTimeFormatter.ofPattern("dd.MMMM.yyyy", Locale.GERMAN);
LocalDate.now().format(formatterGR);                          // 19.Februar.2021
LocalDate.parse("19.Februar.2021", formatterGR);              // 2021-02-19
  • Format = objeto → String. Parse = String → objeto. No parse, use o mesmo formato em que o texto foi gerado.
  • Formatos prontos (constantes): BASIC_ISO_DATE, ISO_DATE, ISO_LOCAL_DATE, ISO_DATE_TIME... O Ctrl+Q na IDE mostra um exemplo de cada.
  • ofPattern("dd/MM/yyyy") usa as mesmas letras do SimpleDateFormat (aula 118). Com um Locale, o mês por extenso sai no idioma (MMMM → "Februar" em alemão).
  • O formato do texto tem que bater com o formatter. Um offset (+05:00) passado para um formatter que não o aceita dá DateTimeParseException (unchecked).
  • Extra: o DateTimeFormatter é imutável e thread-safe. Pode ser uma constante static final, ao contrário do SimpleDateFormat.

130 · ResourceBundle: mensagens internacionalizadas

# src/messages_en_US.properties       (# e ! são comentários)
hello = Hello
good.morning = Good Morning

# src/messages_pt_BR.properties
hello = Olá
good.morning = Bom dia!

# src/messages.properties              (sem locale: o último fallback)
hi = Hi
ResourceBundle bundle = ResourceBundle.getBundle("messages", new Locale("en", "US"));
System.out.println(bundle.getString("hello"));          // Hello
System.out.println(bundle.getString("good.morning"));   // Good Morning
System.out.println(bundle.getString("hi"));             // Hi (veio do messages.properties)
bundle = ResourceBundle.getBundle("messages", new Locale("pt", "BR"));
System.out.println(bundle.getString("hello"));          // Olá
System.out.println(bundle.getString("good.morning"));   // Bom dia!
System.out.println(bundle.getString("hi"));             // Hi
// bundle.getString("tchau") → MissingResourceException · bundle.containsKey("tchau") → false
  • É o recurso por trás do "trocar o idioma do site" (a Amazon da Holanda em inglês). As mensagens ficam em arquivos .properties, um por idioma, no formato chave = valor. O código só pede a chave.
  • Nome do arquivo: nomeBase_língua_PAÍS.properties (messages_pt_BR.properties). O nome base é livre (messages, labels...), mas o sufixo tem que ser exato. Os arquivos ficam na raiz do classpath (no projeto da aula, direto em src, fora de pacotes).
  • getBundle(nomeBase, locale) carrega o arquivo certo, e getString(chave) busca o texto. A mesma chave precisa existir nos arquivos de cada idioma. Chave inexistente dá exceção. containsKey verifica antes.
  • Fallback (ordem de busca, pedindo fr_CA com o sistema em en_US): messages_fr_CA → messages_fr → messages_en_US (Locale padrão) → messages_en → messages. Se nenhum tiver a chave: exceção.
  • Dica: mensagens iguais em todos os idiomas (o "Hi") vão só no arquivo base, sem locale. Não dependa de um idioma específico existir: se o Locale do servidor mudar, a busca pode se perder.

Atenção

  • TemporalAdjuster (interface, 1 método) × TemporalAdjusters (classe utilitária com os prontos).
  • ChronoUnit.X.between conta unidades completas: de 06/08/1988 12h a 06/08/2020 11h ainda são 31 anos.
  • atZone num LocalDateTime não converte a hora, só associa a zona. Para converter um momento, parta de um Instant ou use zoned.withZoneSameInstant(outraZona) (extra).
  • Extra: prefira ZonedDateTime com ZoneId a um offset fixo para regiões com horário de verão: a zona sabe quando o offset muda, o ZoneOffset não.
  • Extra: DayOfWeek.from(temporal) é um jeito mais curto de obter o dia da semana dentro do adjustInto.
  • Extra: encoding dos .properties. Até o Java 8 eles eram lidos em ISO-8859-1 (acentos exigiam á). Do Java 9 em diante, o ResourceBundle lê em UTF-8. É por isso que o "Olá" aparece quebrado no repositório do professor.

Paralelo com PHP

  • ChronoUnit ↔ Carbon: ChronoUnit.DAYS.between(a, b) ≈ $a->diffInDays($b) (também diffInWeeks, diffInMonths, diffInYears).
  • Adjusters ↔ Carbon: next(THURSDAY) ≈ ->next(Carbon::THURSDAY), previous ≈ ->previous(), firstDayOfMonth/lastDayOfMonth ≈ ->startOfMonth()/->endOfMonth(), withDayOfMonth(20) ≈ ->day(20). O PHP puro aceita textos como modify('next thursday') e 'last day of this month'. O "próximo dia útil" no Carbon seria ->nextWeekday(), ou uma macro sua.
  • Zonas: ZoneId.of("Asia/Tokyo") ≈ new DateTimeZone('Asia/Tokyo'), com os mesmos nomes da base IANA. instant.atZone(z) ≈ $carbon->setTimezone('Asia/Tokyo') (converte). Para só "colar" a zona sem converter: ->shiftTimezone().
  • Formatter: DateTimeFormatter.ofPattern("dd/MM/yyyy") ≈ ->format('d/m/Y') e Carbon::createFromFormat('d/m/Y', ...) (as letras diferem). O ISO: ->toIso8601String(). O mês em alemão: ->locale('de')->translatedFormat('d.F.Y').
  • ResourceBundle ↔ lang/ do Laravel: lang/pt_BR/messages.php (ou lang/pt_BR.json) + __('messages.hello') ≈ bundle.getString("hello"). O fallback_locale do config/app.php faz o papel do fallback. A diferença: o Laravel devolve a própria chave quando falta a tradução, e o Java lança exceção.

Glossário

  • ChronoUnit: enum das unidades de tempo, com between para contar intervalos.
  • TemporalAdjuster: interface funcional com adjustInto, que devolve uma data ajustada.
  • TemporalAdjusters: classe utilitária com ajustadores prontos (next, lastDayOfMonth...).
  • ZoneId: identificador de fuso por região (base IANA: America/Sao_Paulo).
  • ZoneOffset: diferença fixa para o UTC (-04:00).
  • ZonedDateTime / OffsetDateTime: data e hora com zona / com offset.
  • DateTimeFormatter: formata e faz parse de datas do java.time; imutável e thread-safe.
  • ResourceBundle: conjunto de mensagens por Locale, lidas de .properties.
  • Fallback: a busca em arquivos cada vez mais genéricos quando o específico não existe.
  • Classpath: as pastas e JARs onde a JVM procura classes e recursos.
