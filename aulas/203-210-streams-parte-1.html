Resumo

Streams (Java 8, "uma das melhores coisas que adicionaram", segundo o professor) são uma forma declarativa de processar os dados de uma coleção, parecida com uma consulta num banco de dados: você diz o que quer (ordene, filtre, limite, pegue o título) em vez de como fazer (for, if, break). Uma frase do professor resume a diferença: coleções guardam dados no espaço (na memória), streams são uma sequência de elementos no tempo: não guardam nada, só fazem os dados passarem pelas operações.

List<String> titles = lightNovels.stream()         // fonte: coleção → Stream<LightNovel>
        .sorted(Comparator.comparing(LightNovel::getTitle)) // intermediária
        .filter(ln -> ln.getPrice() <= 4)                  // intermediária
        .limit(3)                                           // intermediária
        .map(LightNovel::getTitle)                          // intermediária: Stream<String>
        .collect(Collectors.toList());                      // terminal: volta para uma coleção
  • Operação intermediária: retorna outro Stream, então dá para encadear (sorted, filter, limit, map, distinct, flatMap).
  • Operação terminal: fecha o stream e produz um resultado que não é stream: uma coleção (collect), um número (count), um boolean (anyMatch), um Optional (findFirst, max, reduce) ou nada (forEach).

203 · Introdução pt 01: o jeito antigo

O domínio é uma LightNovel (os livros que geralmente dão origem aos animes) com title e price. Os requisitos:

//1. Order LightNovel by title
//2. Retrieve the first 3 titles light novels with price less than 4
public class StreamTest01 {
    private static List<LightNovel> lightNovels = new ArrayList<>(List.of(
            new LightNovel("Tensei Shittara", 8.99),
            new LightNovel("Overlord", 3.99),
            new LightNovel("Violet Evergarden", 5.99),
            new LightNovel("No Game no life", 2.99),
            new LightNovel("Fullmetal Alchemist", 5.99),
            new LightNovel("Kumo desuga", 1.99),
            new LightNovel("Monogatari", 4.00)
    ));
    public static void main(String[] args) {
        lightNovels.sort(Comparator.comparing(LightNovel::getTitle));
        List<String> titles = new ArrayList<>();
        for (LightNovel lightNovel : lightNovels) {
            if (lightNovel.getPrice() <= 4) {
                titles.add(lightNovel.getTitle());
            }
            if (titles.size() >= 3) {
                break;
            }
        }
        System.out.println(lightNovels);
        System.out.println(titles); // [Kumo desuga, Monogatari, No Game no life]
    }
}

Comparator.comparing(LightNovel::getTitle) é novidade: recebe uma Function que extrai a chave e monta o Comparator sozinho, sem escrever (l1, l2) -> l1.getTitle().compareTo(l2.getTitle()). O código funciona, mas é cheio de blocos: for, dois if, break e uma lista auxiliar.

204 · Introdução pt 02: o mesmo com stream

List<String> titles = lightNovels.stream()
        .sorted(Comparator.comparing(LightNovel::getTitle))
        .filter(ln -> ln.getPrice() <= 4)
        .limit(3)
        .map(LightNovel::getTitle)
        .collect(Collectors.toList());
System.out.println(titles); // [Kumo desuga, Monogatari, No Game no life]
  • coleção.stream() devolve um Stream<LightNovel>.
  • sorted(Comparator) ordena. Se o tipo já implementa Comparable, dá para chamar sorted() sem argumento.
  • filter(Predicate) mantém só quem passa no teste (a aula 194 de novo).
  • limit(3) para depois de 3 elementos, o break do código antigo.
  • map(Function) transforma cada elemento: LightNovel → String. "Quando você precisa de um atributo específico, você usa o map."
  • collect(Collectors.toList()) é a terminal: agrupa a sequência "do tempo de volta para o espaço", numa lista (poderia ser um Set, um Map...).

O resultado é o mesmo, mas lido de cima para baixo como uma frase: ordena, filtra, limita a três, pega o título, junta numa lista. Uma pessoa nova no código entende isso mais fácil do que o for com if e break.

205 · Introdução pt 03: forEach, count, distinct e o stream fechado

// LightNovel ganhou equals e hashCode pelo title
private static List<LightNovel> lightNovels = new ArrayList<>(List.of(
        /* ...as mesmas... */
        new LightNovel("Kumo desuga", 1.99),
        new LightNovel("Kumo desuga", 1.99),   // repetido de propósito
        new LightNovel("Monogatari", 4.00)));

Stream<LightNovel> stream = lightNovels.stream();
lightNovels.forEach(System.out::println);        // forEach da coleção (Iterable)

long count = stream
        .distinct()                              // remove repetidos (usa equals/hashCode)
        .filter(ln -> ln.getPrice() <= 4)
        .count();                                // terminal: long
System.out.println(count);                       // 4 (sem o distinct, 5)
  • forEach existe em dois lugares: stream().forEach(...) é uma operação terminal do stream; lista.forEach(...) é só um método default da interface Iterable. Os dois recebem um Consumer. Não abra um stream só para imprimir (lista.stream().forEach(...)): é desperdício, use lista.forEach(...) direto.
  • count() é terminal e devolve long. É o SELECT COUNT(*) ... WHERE do banco.
  • distinct() é intermediária e compara com equals/hashCode. Na gravação o distinct não funcionou de primeira porque a LightNovel ainda não tinha equals e hashCode. O professor gerou os dois pelo title, e aí a contagem caiu de 5 para 4.
  • Stream fechado não reabre: depois de uma operação terminal, usar o mesmo objeto Stream de novo lança IllegalStateException ("stream has already been operated upon or closed"). Para processar de novo, chame lightNovels.stream() outra vez. O professor conta que um candidato numa entrevista de emprego foi reprovado, entre outras coisas, por abrir streams sem necessidade.

206 · FlatMap pt 01: listas dentro de lista

Esta aula não tem legenda no YouTube; o texto vem do código do professor e do resumo do vídeo. O flatMap é uma operação intermediária para "achatar" estruturas aninhadas: coleções dentro de coleções. A DevDojo é uma lista de equipes, e cada equipe é uma lista de pessoas:

public class StreamTest04 {
    public static void main(String[] args) {
        List<List<String>> devdojo = new ArrayList<>();
        List<String> graphicDesigners = List.of("Wildnei Suane", "Catarina Santos", "Sandy Carolina");
        List<String> developers = List.of("William", "David", "Harisson");
        List<String> students = List.of("Édipo", "Gustavo Lima", "Gustavo Mendes", "Guilherme");
        devdojo.add(graphicDesigners);
        devdojo.add(developers);
        devdojo.add(students);

        for (List<String> people : devdojo) {      // o jeito antigo: for dentro de for
            for (String person : people) {
                System.out.println(person);
            }
        }
        System.out.println("----");
        devdojo.stream().flatMap(Collection::stream).forEach(System.out::println);
    }
}
  • devdojo.stream() é um Stream<List<String>>: cada elemento é uma lista inteira.
  • map transforma cada elemento em um outro objeto. Com map(Collection::stream), você teria um Stream<Stream<String>>: streams dentro de stream.
  • flatMap transforma cada elemento em um stream e concatena todos esses streams num único Stream<String> plano, com os 10 nomes. O resultado impresso é o mesmo do for duplo.
  • Com o stream plano dá para filtrar ou contar os elementos que estavam "aninhados": devdojo.stream().flatMap(Collection::stream).filter(p -> p.startsWith("G")).count() → 3.

207 · FlatMap pt 02: palavras em letras

List<String> words = List.of("Gomu", "Gomu", "No", "Mi");
String[] letters = words.get(0).split("");               // split("") separa letra por letra
System.out.println(Arrays.toString(letters));             // [G, o, m, u]

List<String[]> collect = words.stream().map(w -> w.split("")).collect(Collectors.toList());
Stream<String> stream = Arrays.stream(letters);          // array → stream
List<String> letters2 = words.stream()
        .map(w -> w.split(""))   //Stream<String[]>
        .flatMap(Arrays::stream) // Stream<String>
        .collect(Collectors.toList());
System.out.println(letters2); // [G, o, m, u, G, o, m, u, N, o, M, i]

Só com map, o resultado é uma List<String[]>: uma lista de arrays, uma estrutura interna que precisa ser extraída. O truque é Arrays.stream(array), que transforma um array em stream. O flatMap(Arrays::stream) faz isso para cada array e junta tudo. A dica do professor: quando vir algo aninhado, muito provavelmente você precisa de flatMap.

208 · Finding and matching

// Overlord agora custa 10.99
System.out.println(lightNovels.stream().anyMatch(ln -> ln.getPrice() > 9));  // true
System.out.println(lightNovels.stream().allMatch(ln -> ln.getPrice() > 0));  // true
System.out.println(lightNovels.stream().noneMatch(ln -> ln.getPrice() < 0)); // true

lightNovels.stream()
        .filter(ln -> ln.getPrice() > 3)
        .findAny()                                  // qualquer um: Optional
        .ifPresent(System.out::println);

lightNovels.stream()
        .filter(ln -> ln.getPrice() > 3)
        .sorted(Comparator.comparing(LightNovel::getPrice).reversed())
        .findFirst()                                // o primeiro, respeitando a ordem
        .ifPresent(System.out::println);            // Overlord 10.99

lightNovels.stream()
        .filter(ln -> ln.getPrice() > 3)
        .max(Comparator.comparing(LightNovel::getPrice))
        .ifPresent(System.out::println);            // Overlord 10.99
  • anyMatch: existe algum que satisfaz? allMatch: todos satisfazem? noneMatch: nenhum satisfaz? Todos recebem um Predicate e devolvem boolean (terminais). Com > 10 no lugar de > 9, o anyMatch dá false.
  • O noneMatch embaralha a cabeça (o professor admite que também se confunde): noneMatch(p < 0) é true porque nenhum preço é negativo; noneMatch(p > 0) é false porque todos são positivos.
  • findAny: devolve qualquer elemento, sem garantia de qual. Use quando não se importa com a ordem. Num stream sequencial costuma vir sempre o primeiro, mas isso não é garantido.
  • findFirst: o primeiro, respeitando a ordem da fonte (ou a do sorted). Sem ordenar, dá o primeiro da lista com preço > 3 (Tensei Shittara). Ordenando por preço dá Monogatari (4.00). Com .reversed(), dá Overlord.
  • Como pode não haver resultado, findAny, findFirst e max devolvem Optional. Daí o ifPresent (aulas 201–202).
  • max(Comparator) faz o mesmo que ordenar ao contrário e pegar o primeiro, sem precisar ordenar tudo. Existe também min.

209 · Reduce pt 01

reduce é uma operação terminal que aplica repetidamente uma operação aos elementos até sobrar um resultado único: soma, produto, maior... Ela recebe um BinaryOperator<T> (dois T entram, um T sai).

List<Integer> integers = List.of(1, 2, 3, 4, 5, 6);

integers.stream().reduce((x, y) -> x + y).ifPresent(System.out::println); // 21 (Optional)
System.out.println(integers.stream().reduce(0, (x, y) -> x + y));         // 21 (valor inicial 0)

integers.stream().reduce(Integer::sum).ifPresent(System.out::println);      // 21
System.out.println(integers.stream().reduce(0, Integer::sum));              // 21

integers.stream().reduce((x, y) -> x * y).ifPresent(System.out::println);  // 720
System.out.println(integers.stream().reduce(1, (x, y) -> x * y));          // 720 (com 0 daria 0!)

integers.stream().reduce((x, y) -> x > y ? x : y).ifPresent(System.out::println); // 6
System.out.println(integers.stream().reduce(0, Integer::max));                    // 6
  • Sem valor inicial, retorna Optional, porque a lista pode estar vazia.
  • Com valor inicial (a identidade), retorna o valor direto: se a lista estiver vazia, devolve a própria identidade. Na soma a identidade é 0; na multiplicação é 1. Na gravação o professor pôs 0 na multiplicação e o resultado deu 0 ("passar vergonha"). Colocando 1 na soma, o resultado vira 22.
  • Integer::sum e Integer::max são method references que já são BinaryOperator. O Integer não tem um método de multiplicar, por isso a multiplicação fica na lambda.
  • reduce(10, Integer::max) devolve 10 se nenhum elemento for maior: o valor inicial entra na conta, então só use se fizer sentido na regra de negócio.

210 · Reduce pt 02: objetos e streams de primitivos

// soma dos preços acima de 3 (lista da aula 208)
lightNovels.stream()
        .map(LightNovel::getPrice)          // Stream<Double> (autoboxing)
        .filter(price -> price > 3)
        .reduce(Double::sum)
        .ifPresent(System.out::println);    // 35.96

double sum = lightNovels.stream()           // Stream<LightNovel>
        .mapToDouble(LightNovel::getPrice)  // DoubleStream (primitivo)
        .filter(price -> price > 3)
        .sum();                             // double direto, sem Optional
  • Com objetos, primeiro use o map para extrair o atributo que você quer reduzir. Dá para filtrar antes ou depois do map, e o IntelliJ sugere trocar a ordem.
  • map(LightNovel::getPrice) gera Stream<Double>: cada double vira um Double (boxing) e volta na soma (unboxing). É permitido, mas numa aplicação de alta performance esse vai e volta custa.
  • Streams de primitivos: IntStream, LongStream e DoubleStream (não existe FloatStream, CharStream etc.). Você chega neles com mapToInt, mapToLong e mapToDouble, e eles já têm operações numéricas prontas, como sum(), que devolve o primitivo direto.

Atenção

  • Nada acontece sem uma operação terminal. As intermediárias são lazy: só montam o pipeline. Um lista.stream().filter(...) sozinho não filtra nada.
  • Stream não é reutilizável: depois da terminal, usar o mesmo objeto dá IllegalStateException. Crie outro com lista.stream().
  • Stream não altera a coleção de origem. stream().sorted() não ordena a lista; lista.sort(...) ordena (aula 203).
  • A ordem das operações importa: limit(3) antes do filter pega os 3 primeiros e depois filtra (pode sobrar menos de 3), e sorted depois do limit ordena só esses 3.
  • distinct depende de equals/hashCode (aulas 161–164): sem eles, dois objetos iguais continuam "diferentes".
  • findAny não garante qual elemento vem; findFirst garante o primeiro da ordem.
  • A identidade do reduce tem de ser neutra: 0 para soma, 1 para produto. Senão o resultado sai errado.
  • Extra: Collectors.toList() × .toList(): a partir do Java 16 existe stream.toList(), que devolve uma lista imutável. O Collectors.toList() da aula devolve (na prática) um ArrayList mutável.
  • Extra: limit e findFirst fazem curto-circuito: as operações seguintes param assim que o resultado é conhecido, assim como o break do código da aula 203. anyMatch, allMatch e noneMatch também param cedo.

Paralelo com PHP

  • Stream ≈ Collection do Laravel: collect($novels)->sortBy('title')->filter(fn($n) => $n->price <= 4)->take(3)->pluck('title')->values()->all() é a aula 204 em Laravel. O mapeamento: sorted ≈ sortBy, filter ≈ filter, limit ≈ take, map(getTitle) ≈ pluck/map, collect(toList()) ≈ all()/toArray(), count ≈ count, distinct ≈ unique.
  • A diferença importante: a Collection do Laravel executa cada passo na hora e cria uma coleção nova a cada método (eager). O stream do Java é lazy, só roda na terminal, e é de uso único. A LazyCollection do Laravel (cursor(), LazyCollection::make) é a mais parecida.
  • flatMap ≈ ->flatMap(fn($equipe) => $equipe) ou ->flatten(1) / ->collapse(). str_split("Gomu") ≈ "Gomu".split("").
  • anyMatch/allMatch/noneMatch ≈ ->contains(fn...) / ->every(fn...) / ! ->contains(fn...). findFirst ≈ ->first(fn...) (que devolve null, não Optional). max(Comparator) ≈ ->sortByDesc('price')->first(); o ->max('price') do Laravel devolve só o valor.
  • reduce ≈ array_reduce($ints, fn($x, $y) => $x + $y, 0) / ->reduce(...). O terceiro argumento é a identidade. mapToDouble(...).sum() ≈ ->sum('price') ou array_sum(array_column(...)).

Glossário

  • Stream: sequência de elementos de uma fonte que passa por um pipeline de operações; não armazena dados.
  • Pipeline: fonte + zero ou mais operações intermediárias + uma operação terminal.
  • Operação intermediária: devolve outro Stream e é lazy (filter, map, sorted...).
  • Operação terminal: dispara o processamento, fecha o stream e produz o resultado (collect, count, reduce...).
  • Declarativo: descrever o que se quer, não o passo a passo (imperativo).
  • Collectors: fábrica de coletores para o collect (toList, toSet, joining...).
  • flatMap: mapeia cada elemento para um stream e concatena todos num único stream.
  • Curto-circuito: operação que pode terminar sem percorrer tudo (limit, findFirst, anyMatch).
  • reduce: combina todos os elementos num único resultado com um BinaryOperator.
  • Identidade: valor inicial neutro do reduce (0 na soma, 1 no produto).
  • IntStream/LongStream/DoubleStream: streams de primitivos, sem boxing, com sum, average, max...
