Resumo

Com o Java 8 veio o pacote java.time, inspirado na biblioteca Joda-Time, que todo mundo usava por causa dos problemas de Date e Calendar. As classes novas são imutáveis, criadas por métodos de fábrica (now, of, parse, nunca new), têm meses de 1 a 12 e imprimem no formato ISO 8601, o mesmo do banco de dados. Conselho do William: do Java 8 em diante, use java.time. Date e Calendar só quando o sistema legado obrigar.

LocalDate       2022-01-27                 só data (aniversário)
LocalTime       23:32:12                   só hora
LocalDateTime   2022-08-06T23:45           data + hora, sem fuso
Instant         2021-02-16T13:30:00Z       ponto na linha do tempo, em UTC (Z = Zulu)
Duration        PT17520H8M                 quantidade de tempo em segundos/nanos (horas, minutos)
Period          P2Y7D                      quantidade de tempo em datas (anos, meses, dias)

119 · LocalDate

System.out.println(Month.JANUARY.getValue());                 // 1 (não é mais 0!)
LocalDate date = LocalDate.of(2022, Month.JANUARY, 27);
LocalDate agora = LocalDate.now();
agora = agora.plusWeeks(4);                   // imutável: sem atribuir, o resultado se perde
System.out.println(date.getYear());           // 2022
System.out.println(date.getMonth());          // JANUARY
System.out.println(date.getMonthValue());     // 1
System.out.println(date.getDayOfWeek());      // THURSDAY
System.out.println(date.getDayOfMonth());     // 27
System.out.println(date.lengthOfMonth());     // 31
System.out.println(date.isLeapYear());        // false (ano bissexto?)
System.out.println(date.get(ChronoField.YEAR));          // 2022
System.out.println(date.get(ChronoField.DAY_OF_MONTH));  // 27
System.out.println(date);                     // 2022-01-27 (ISO 8601, como no banco)
System.out.println(LocalDate.MAX);            // +999999999-12-31
System.out.println(LocalDate.MIN);            // -999999999-01-01
  • Só data, sem hora: para uma data de nascimento, a hora só traria dor de cabeça.
  • Criação: LocalDate.of(ano, mês, dia) ou LocalDate.now(). A classe é final e o construtor é private, então new LocalDate() não compila.
  • O mês agora começa em 1. Dá para passar 1, mas prefira Month.JANUARY (enum, aulas 80–83).
  • Métodos prontos: getYear, getMonth/getMonthValue, getDayOfWeek, getDayOfMonth, lengthOfMonth (útil em relatório: o mês tem 28, 29, 30 ou 31 dias?), isLeapYear. Para qualquer outro campo existe get(ChronoField.XXX).
  • Imutável: agora.plusWeeks(4) sozinho não muda agora (o IntelliJ avisa: "resultado ignorado"). É preciso agora = agora.plusWeeks(4). Existem plusDays, plusMonths, plusYears, minus.... A imutabilidade evita inconsistência quando várias threads acessam o mesmo objeto.
  • Não há mais o limite de 1970: vai de LocalDate.MIN a MAX, quase um bilhão de anos para cada lado.

120 · LocalTime

LocalTime time = LocalTime.of(23, 32, 12);    // LocalTime.of(24, ...) → DateTimeException
LocalTime timeNow = LocalTime.now();          // 18:07:23.123456789 (até nanossegundos)
System.out.println(time);                     // 23:32:12
System.out.println(time.getHour());           // 23
System.out.println(time.getMinute());         // 32
System.out.println(time.getSecond());         // 12
System.out.println(time.get(ChronoField.CLOCK_HOUR_OF_AMPM));   // 11 (11 da noite)
System.out.println(LocalTime.MIN);            // 00:00
System.out.println(LocalTime.MAX);            // 23:59:59.999999999
  • Segue o mesmo padrão do LocalDate: of, now, getters e ChronoField.
  • Hora vai de 0 a 23. Um valor inválido lança DateTimeException.
  • Ao testar ChronoField, confira o que cada campo significa: AMPM_OF_DAY dá 0/1 (AM/PM), CLOCK_HOUR_OF_AMPM dá a hora de 1 a 12.
  • MIN e MAX em relatórios: "todos os registros de 15/02/2022" vão de 00:00 (LocalTime.MIN) a 23:59:59.999999999 (LocalTime.MAX).

121 · LocalDateTime

LocalDateTime localDateTime = LocalDateTime.now();   // 2022-02-16T18:07:23.123456789
LocalDate date = LocalDate.parse("2022-08-06");      // String ISO → objeto
LocalTime time = LocalTime.parse("23:45:00");
System.out.println(time);                            // 23:45 (segundos zerados não aparecem)
LocalDateTime ldt1 = date.atTime(time);              // data + hora
LocalDateTime ldt2 = time.atDate(date);              // hora + data: mesmo resultado
System.out.println(ldt1);                            // 2022-08-06T23:45
System.out.println(ldt2);                            // 2022-08-06T23:45
  • É a junção de LocalDate e LocalTime, com os métodos de ambos. O T separa a data da hora (ISO 8601).
  • parse(String) lê o formato ISO ("2022-08-06", "23:45:00"). Formatos personalizados vêm com o DateTimeFormatter (aula 129).
  • O parse daqui lança DateTimeParseException, que é unchecked. É diferente do ParseException (checked) do DateFormat: não obriga try/catch, mas continua explodindo com texto inválido.
  • Combinar: date.atTime(time) ou time.atDate(date). O atTime também é sobrecarregado: atTime(9, 45), atTime(9, 45, 30).

122 · Instant

Instant now = Instant.now();
System.out.println(now);                        // 2022-02-16T13:30:00.123456Z  (Z = UTC)
System.out.println(LocalDateTime.now());        // 2022-02-16T14:30:00.123456   (sem fuso: hora local)
System.out.println(now.getEpochSecond());       // segundos desde 1970 (long)
System.out.println(now.getNano());              // nanos dentro do segundo: 0 a 999.999.999
System.out.println(Instant.ofEpochSecond(3));                    // 1970-01-01T00:00:03Z
System.out.println(Instant.ofEpochSecond(3, 0));                 // 1970-01-01T00:00:03Z
System.out.println(Instant.ofEpochSecond(3, 1_000_000_000));     // 1970-01-01T00:00:04Z
System.out.println(Instant.ofEpochSecond(3, -1_000_000_000));    // 1970-01-01T00:00:02Z
  • Um ponto instantâneo na linha do tempo, contado desde 1970 como o Date, mas com precisão de nanossegundos. Também é imutável.
  • O Z no fim é "Zulu time", o horário neutro do mundo (na prática, o mesmo que UTC). É o mesmo instante para qualquer pessoa em qualquer lugar.
  • Por que isso importa no banco: "14h" gravado sem fuso é ambíguo. Na Holanda são 14h, em São Paulo 10h, em Manaus 9h. Salve em UTC e converta para o fuso do usuário na hora de mostrar (São Paulo = UTC−3).
  • Nanossegundos desde 1970 não cabem num long. Por isso são dois campos: getEpochSecond() (long) e getNano() (int, até 999.999.999). Um bilhão de nanos "vira" um segundo, como mostram os ofEpochSecond(3, ±1_000_000_000).
  • Quando usar: para humanos (dia, mês, ano), LocalDate/LocalDateTime. Para a máquina (timestamp de evento, log, medir tempo), Instant.

123 · Duration: tempo em segundos e nanos

LocalDateTime now = LocalDateTime.now();
LocalDateTime nowAfterTwoYears = LocalDateTime.now().plusYears(2).plusMinutes(8);
LocalTime timeNow = LocalTime.now();
LocalTime timeMinus7Hours = LocalTime.now().minusHours(7);
Duration d1 = Duration.between(now, nowAfterTwoYears);   // PT17520H8M (aprox.)
Duration d2 = Duration.between(timeNow, timeMinus7Hours); // PT-7H (aprox.): negativa!
Duration d3 = Duration.between(Instant.now(), Instant.now().plusSeconds(1000)); // PT16M40S
Duration d4 = Duration.ofDays(20);                       // PT480H
Duration d5 = Duration.ofMinutes(3);                     // PT3M
Duration d6 = Duration.of(3, ChronoUnit.HOURS);          // PT3H
// Duration.between(LocalDate.now(), LocalDate.now().plusDays(2))  → UnsupportedTemporalTypeException: Seconds
  • Quantidade de tempo baseada em segundos e nanossegundos: quantas horas, minutos e segundos há entre dois momentos. Não tem now().
  • Duration.between(inicio, fim) aceita LocalDateTime, LocalTime e Instant. Com LocalDate dá erro em tempo de execução, porque ela não tem segundos. Para datas existe o Period.
  • O formato ISO 8601 da duração: P (period) abre, T (time) separa a parte de horas, e depois vêm H, M, S. PT17520H8M = 17.520 horas e 8 minutos (os 730 dias de dois anos).
  • Fábricas: ofDays, ofHours, ofMinutes, ofSeconds... Dias viram horas: ofDays(20) imprime PT480H.
  • Duration.of(qtd, ChronoUnit.X) tem que ser usado com cuidado: unidades de duração estimada (WEEKS, MONTHS, YEARS...) lançam UnsupportedTemporalTypeException. HOURS, MINUTES, SECONDS e DAYS funcionam.
  • Se o fim vier antes do início, a duração fica negativa (PT-7H).

124 · Period: tempo em anos, meses e dias

LocalDate now = LocalDate.now();
LocalDate nowAfterTwoYears = LocalDate.now().plusYears(2).plusDays(7);
Period p1 = Period.between(now, nowAfterTwoYears);   // P2Y7D  (só aceita LocalDate)
Period p2 = Period.ofDays(10);                       // P10D
Period p3 = Period.ofWeeks(58);                      // P406D  (semanas viram dias)
Period p4 = Period.ofMonths(3);                      // P3M
Period p5 = Period.ofYears(3);                       // P3Y
System.out.println(p3.getMonths());                  // 0  (não converte 406 dias em meses!)
System.out.println(Period.between(LocalDate.now(),
        LocalDate.now().plusDays(p3.getDays())).getMonths());   // 1  (de P1Y1M...D, e não 13)
  • Quantidade de tempo baseada em datas: anos, meses e dias. Period.between aceita só LocalDate.
  • Fábricas: ofDays, ofWeeks (vira dias: 58 semanas = P406D), ofMonths, ofYears.
  • A pegadinha: não há normalização automática. Period.ofWeeks(58) guarda 406 dias, 0 meses e 0 anos, então getMonths() dá 0. O Period.between dá P1Y1M...D, e o getMonths() devolve só o componente de meses (1), não o total (13). A documentação avisa: 15 meses ≠ 1 ano e 3 meses.
  • Para "quantos meses no total entre duas datas" existe o ChronoUnit, assunto da aula 125.

Atenção

  • Tudo em java.time é imutável: data.plusDays(1); sozinho não faz nada. Escreva data = data.plusDays(1);.
  • Sem new: use now(), of(...) e parse(...).
  • Duration × Period: Duration = horas, minutos e segundos (não aceita LocalDate). Period = anos, meses e dias (só aceita LocalDate).
  • LocalDateTime não tem fuso. "2022-08-06T23:45" não diz de onde é. Para gravar um momento absoluto, use Instant (UTC) ou ZonedDateTime (aula 128).
  • Extra: compare com isBefore, isAfter e isEqual (ou equals). == compara referências.
  • Extra: with troca um campo, como data.withDayOfMonth(1) (primeiro dia do mês). Também é imutável.
  • Extra: conversões úteis de Duration: toMinutes(), toHours(), toDays(), toMillis(). E para medir tempo de execução: Duration.between(inicio, Instant.now()).toMillis().

Paralelo com PHP

  • Joda-Time ↔ Carbon: o java.time está para o Java como o Carbon está para o Laravel. LocalDate.now().plusWeeks(4) ≈ now()->addWeeks(4).
  • Imutabilidade: Carbon/DateTime são mutáveis ($d->addDay() altera $d, uma fonte clássica de bugs). O equivalente ao java.time é CarbonImmutable/DateTimeImmutable. No Laravel dá para tornar esse o padrão com Date::use(CarbonImmutable::class).
  • O PHP não tem um tipo "só data" nem "só hora": tudo é data e hora (Carbon::today() é meia-noite). Em Java, LocalDate e LocalTime são tipos próprios.
  • Intervalos: o DateInterval do PHP junta Duration e Period num tipo só, e usa o mesmo ISO 8601: new DateInterval('P2Y7D'), 'PT3H'. $a->diff($b) ≈ Period.between e Duration.between. diffInDays() do Carbon ≈ ChronoUnit.DAYS.between (aula 125).
  • UTC no banco: é o mesmo conselho do Laravel: 'timezone' => 'UTC' em config/app.php e converter na exibição. O Instant é o "timestamp em UTC" do Java.

Glossário

  • java.time: a API de datas do Java 8, imutável e inspirada na Joda-Time.
  • ISO 8601: padrão internacional de datas (2022-01-27, 2022-08-06T23:45) e durações (P2Y7D, PT3H).
  • Método de fábrica: método estático que cria o objeto no lugar do new (of, now, parse).
  • ChronoField: enum com os campos de data e hora (YEAR, DAY_OF_MONTH...) para usar com get.
  • UTC / Zulu time: o horário de referência mundial, sem fuso; o Z do Instant.
  • Epoch second: segundos desde 01/01/1970 00:00 UTC.
  • Duration: quantidade de tempo em segundos e nanos (horas, minutos).
  • Period: quantidade de tempo em anos, meses e dias.
  • Normalização: converter unidades menores em maiores (12 meses → 1 ano); o Period não faz sozinho.
