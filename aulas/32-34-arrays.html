Resumo

Para guardar três idades, até agora seria preciso criar idade1, idade2 e idade3, e depois três println. Isso não escala. Um array (vetor) guarda vários valores do mesmo tipo sob um único nome, cada um numa posição numerada. O conselho do William vale para as três aulas: desenhe no papel o que acontece na memória. As classes do curso são Aula07Arrays01 e 02.

32 · Declarar, criar e acessar

int[] idades;              // variável do tipo referência (ainda não aponta para nada)
idades = new int[3];       // cria o objeto na memória: 3 posições, índices 0, 1 e 2
idades[0] = 21;
idades[1] = 15;
idades[2] = 11;
System.out.println(idades[0]); // 21
System.out.println(idades);    // algo como [I@1b6d3586 (a referência, não os valores)
  • int[] se lê "array de int". int idades[] também compila, mas o recomendado é o colchete junto do tipo: batendo o olho, você já sabe que é um array. Por ser uma coleção, use nome no plural.
  • Array é um objeto, e a variável é do tipo referência. Ela não guarda os valores: ela aponta para um objeto na memória, que tem as posições. Por isso o println(idades) mostra uma referência e não os números.
  • Sem new, a variável local não está inicializada e não compila. Ela pode receber null ("não aponta para nada"), mas só tipos de referência aceitam null. int x = null; não compila.
  • O tamanho é obrigatório no new: new int[3], porque o Java precisa saber quantas posições reservar.
  • O índice começa em 0. Com 3 posições, os índices vão de 0 a 2. É a piada dos três desenvolvedores no bar: o garçom pergunta quantos são, e um levanta 0, outro 1, outro 2.
  • Acessar uma posição que não existe (idades[3]), seja para ler ou para gravar, lança ArrayIndexOutOfBoundsException. O código compila, mas quebra na execução.

33 · Tipos e valores padrão

  • Cada posição segue as regras do tipo do array. Num int[], idades[0] = 10.5F; não compila, porque um float não entra num int sem cast.
  • new com tipo primitivo só aparece em array (new int[3]). O new em geral fica para a parte de orientação a objetos.
  • Toda posição de um array novo já nasce com um valor padrão:
Tipo do array                      Valor padrão
byte, short, int, long             0
float, double                      0.0
char                               '\u0000' (caractere nulo: imprime "em branco")
boolean                            false
String e outros tipos referência   null
  • Os valores padrão valem para arrays e para variáveis declaradas fora dos métodos (atributos, vistos em OO). Variáveis locais não têm valor padrão: precisam ser inicializadas antes do uso, como você viu no if.

34 · Percorrer com for, length e tamanho fixo

String[] nomes = new String[3];
nomes[0] = "Goku";
nomes[1] = "Kurosaki";
nomes[2] = "Luffy";

for (int i = 0; i < nomes.length; i++) {
    System.out.println(nomes[i]);
}
  • O for é o parceiro natural do array: o índice do laço é o índice das posições.
  • Com o número fixo (i < 3), aumentar o array obriga a lembrar de mudar o laço também. Se o laço for longe demais (i < 4 com 3 posições), imprime os três e depois quebra com ArrayIndexOutOfBoundsException.
  • A solução é nomes.length, uma propriedade que todo array tem e que dá o tamanho dele. O laço passa a se ajustar sozinho. Ela existe porque o array é um objeto: digite nomes. e a IDE mostra o que o objeto oferece.
  • O tamanho é fixo. Um array não cresce em tempo de execução. Para mudar o tamanho, só alterando o código e compilando de novo. No dia a dia você vai usar as coleções (como ArrayList), que crescem sozinhas. Elas vêm mais para frente no curso.
  • Posições não preenchidas continuam com o valor padrão. Um String[4] com 3 nomes imprime o quarto como null.
  • Reatribuir cria outro objeto: nomes = new String[5]; não "aumenta" o array antigo. Cria um array novo, vazio, e a variável passa a apontar para ele. O antigo perde a referência, não dá mais para recuperá-lo, e o garbage collector (coletor de lixo) do Java libera essa memória.
nomes ──X──▶ [Goku | Kurosaki | Luffy]      ← sem referência: o GC recolhe
   └───────▶ [null | null | null | null | null]

Atenção

  • O último índice é length - 1, não length. No laço, use i < nomes.length, nunca <=.
  • length sem parênteses no array. Na String é texto.length(), com parênteses, porque é um método. Nas coleções é lista.size(). Três jeitos diferentes, e é pegadinha de prova.
  • Índice fora do limite compila e só quebra ao rodar. O compilador não verifica.
  • Extra: para ver o conteúdo de um array, use System.out.println(Arrays.toString(idades));, que imprime [21, 15, 11]. Precisa de import java.util.Arrays; no topo do arquivo.
  • Extra: dá para criar e preencher de uma vez: int[] idades = {21, 15, 11};. O tamanho vem da lista. É o tema da aula 35.
  • Extra: int[] b = a; não copia o array. Copia a referência, e as duas variáveis passam a apontar para o mesmo objeto. b[0] = 99; muda também a[0]. Para copiar de verdade, use a.clone() ou Arrays.copyOf(a, a.length).
  • Extra: new int[0] é válido (array vazio). Tamanho negativo compila e lança NegativeArraySizeException ao rodar.

Paralelo com PHP

  • O array do PHP é outra coisa. No PHP ele é um mapa ordenado que cresce sozinho, aceita chaves string ($u['nome']) e mistura tipos. O array do Java tem tamanho fixo, um só tipo e índices inteiros de 0 a length-1. O equivalente do array PHP de lista é o ArrayList, e o do associativo é o HashMap (coleções, mais à frente).
  • Não existe $a[] = x: não há "append" em array Java. Todas as posições já existem desde o new.
  • Tamanho: count($a) no PHP e a.length no Java.
  • Índice inexistente: no PHP dá um warning e devolve null. No Java lança exceção e o programa para.
  • Cópia: no PHP, $b = $a copia o array (alterar $b não mexe em $a). No Java, b = a faz as duas variáveis apontarem para o mesmo array. O comportamento Java lembra os objetos do PHP, não os arrays.
  • Imprimir: o print_r($a) equivale a Arrays.toString(a). O println(a) sozinho mostra só a referência.

Glossário

  • Array (vetor): objeto de tamanho fixo que guarda vários valores do mesmo tipo.
  • Índice: número da posição, de 0 até length - 1.
  • Variável de referência: variável que aponta para um objeto na memória em vez de guardar o valor.
  • null: "não aponta para nenhum objeto". Só tipos de referência aceitam.
  • Valor padrão: valor inicial automático das posições de um array (0, 0.0, '\u0000', false, null).
  • length: propriedade com o tamanho do array.
  • ArrayIndexOutOfBoundsException: exceção ao acessar um índice que não existe.
  • Garbage collector: parte da JVM que libera a memória de objetos sem referência.
