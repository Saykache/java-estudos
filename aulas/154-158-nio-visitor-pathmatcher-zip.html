Resumo

O DirectoryStream (aula 153) só enxerga um nível. Para descer em todas as subpastas existe o Files.walkFileTree com um FileVisitor: o Java percorre a árvore e chama os seus métodos (polimorfismo) em cada pasta e arquivo. O PathMatcher filtra caminhos por padrão (glob, como *.java). O ZipOutputStream junta arquivos num .zip. Com isso termina a parte de IO.

154 · SimpleFileVisitor e walkFileTree

class ListJavaFiles extends SimpleFileVisitor<Path> {     // <Path>: generics (aulas 183+)
    @Override
    public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
        if (file.getFileName().toString().endsWith(".java")) {   // getFileName devolve Path → toString
            System.out.println(file.getFileName());
        }
        return FileVisitResult.CONTINUE;                     // o que o Java deve fazer em seguida
    }
}

public class SimpleFileVisitorTest01 {
    public static void main(String[] args) throws IOException {
        Path root = Paths.get(".");
        Files.walkFileTree(root, new ListJavaFiles());       // percorre TUDO a partir de "."
    }
}
// → todos os .java do projeto, desde a primeira aula
  • Files.walkFileTree(inicio, visitor): o primeiro argumento é de onde começar, e o segundo é o comportamento (o que fazer em cada item).
  • O visitor é uma classe que estende SimpleFileVisitor<Path>. Ela é uma classe (não interface), então você sobrescreve só o que precisa. Aqui, visitFile, chamado para cada arquivo.
  • Quem chama visitFile é o Java. Você só diz o que fazer, e pode ser imprimir, copiar ou mudar permissões.
  • A classe auxiliar fica no mesmo arquivo, sem public (só a classe com o nome do arquivo pode ser pública).
  • O desafio da aula (listar só os .java): file.getFileName().toString().endsWith(".java"). Sem o toString(), o endsWith do Path compara elementos do caminho, não texto, e não acha nada.

155 · Os quatro métodos e o FileVisitResult

class ListAllFiles extends SimpleFileVisitor<Path> {
    @Override
    public FileVisitResult preVisitDirectory(Path dir, BasicFileAttributes attrs) throws IOException {
        System.out.println("pre visit " + dir.getFileName());     // ao ENTRAR numa pasta
        return FileVisitResult.SKIP_SUBTREE;                        // na aula: pula o conteúdo dela
    }
    @Override
    public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
        System.out.println(file.getFileName());                     // cada arquivo
        return FileVisitResult.CONTINUE;
    }
    @Override
    public FileVisitResult visitFileFailed(Path file, IOException exc) throws IOException {
        return super.visitFileFailed(file, exc);                    // falhou ao ler (ex.: sem permissão)
    }
    @Override
    public FileVisitResult postVisitDirectory(Path dir, IOException exc) throws IOException {
        System.out.println("post visit " + dir.getFileName());    // ao SAIR da pasta (depois dos descendentes)
        return FileVisitResult.CONTINUE;
    }
}
Files.walkFileTree(Paths.get("pasta"), new ListAllFiles());
  • preVisitDirectory: antes de entrar numa pasta. postVisitDirectory: depois de visitar tudo dentro dela (a saída aparece "de baixo para cima"). visitFileFailed: quando um arquivo não pôde ser lido, bom lugar para um log.
  • FileVisitResult (enum), o que o Java faz em seguida:
    • CONTINUE: continua normalmente;
    • TERMINATE: para tudo;
    • SKIP_SUBTREE: não entra nesta pasta (faz sentido no preVisitDirectory);
    • SKIP_SIBLINGS: ignora os "irmãos" que ainda não foram visitados (o resto do mesmo nível).
  • No postVisitDirectory, SKIP_SUBTREE não tem efeito: a pasta já foi percorrida. A documentação diz que ele só é chamado depois de todos os descendentes. "Na dúvida, leia a documentação."
  • A ordem entre irmãos não é garantida: depende do sistema de arquivos.

156 · PathMatcher e glob

private static void matches(Path path, String glob) {
    PathMatcher matcher = FileSystems.getDefault().getPathMatcher(glob);
    System.out.println(glob + ": " + matcher.matches(path));
}

Path path1 = Paths.get("pasta/subpasta/file.bkp");
Path path2 = Paths.get("pasta/subpasta/file.txt");
Path path3 = Paths.get("pasta/subpasta/file.java");
matches(path1, "glob:*.bkp");                    // false: * não atravessa diretórios
matches(path1, "glob:**/*.bkp");                 // true:  ** atravessa
matches(path1, "glob:**/*.{bkp,txt,java}");      // true   { } = qualquer uma das opções
matches(path2, "glob:**/*.{bkp,txt,java}");      // true
matches(path3, "glob:**/*.{bkp,txt,java}");      // true
matches(path1, "glob:**/*.???");                 // true:  ? = exatamente 1 caractere (bkp)
matches(path2, "glob:**/*.???");                 // true   (txt)
matches(path3, "glob:**/*.???");                 // false  (java tem 4)
matches(path3, "glob:**/file.????");             // true
  • FileSystems.getDefault().getPathMatcher("sintaxe:padrão"). A sintaxe é glob: (curingas de arquivo) ou regex: (a regex das aulas 131–136).
  • Glob:
    • *: qualquer sequência de caracteres dentro de um nível (não passa de /);
    • **: qualquer sequência, atravessando diretórios;
    • ?: exatamente um caractere;
    • {a,b,c}: qualquer uma das alternativas.
  • matches olha o caminho inteiro. Por isso *.bkp falha em pasta/subpasta/file.bkp e **/*.bkp casa.

157 · Exercício: visitor + PathMatcher

class FindAllTestJavaOrClass extends SimpleFileVisitor<Path> {
    private PathMatcher matcher = FileSystems.getDefault().getPathMatcher("glob:**/*Test*.{java,class}");

    @Override
    public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) throws IOException {
        if (matcher.matches(file)) {
            System.out.println(file.getFileName());
        }
        return FileVisitResult.CONTINUE;
    }
}
Files.walkFileTree(Paths.get("."), new FindAllTestJavaOrClass());
// → todos os arquivos com "Test" no nome e extensão .java ou .class (fontes e compilados)
  • Pedido: percorrer o projeto e listar os arquivos que têm "Test" no nome e terminam em .java ou .class.
  • **/ ignora a pasta, *Test* pega qualquer coisa antes e depois de "Test" (inclusive o 01, 02), e {java,class} são as duas extensões.
  • O matcher vira um atributo da classe: é criado uma vez e reaproveitado em cada visitFile.
  • No meio da aula, um padrão mal escrito gerou IllegalArgumentException. O William testou partes do padrão até achar o erro. O conselho dele: "tem dúvida se funciona? Não pergunta, testa".

158 · ZipOutputStream

Path arquivoZip = Paths.get("pasta/arquivo.zip");
Path arquivosParaZipar = Paths.get("pasta/subpasta1/subsubpasta1");

try (ZipOutputStream zipStream = new ZipOutputStream(Files.newOutputStream(arquivoZip));
     DirectoryStream<Path> directoryStream = Files.newDirectoryStream(arquivosParaZipar)) {
    for (Path file : directoryStream) {
        ZipEntry zipEntry = new ZipEntry(file.getFileName().toString());   // 1. prepara a entrada (o nome no zip)
        zipStream.putNextEntry(zipEntry);                                  // 2. abre o "lugar" no zip
        Files.copy(file, zipStream);                                       // 3. copia o CONTEÚDO
        zipStream.closeEntry();                                            // 4. fecha a entrada
    }
    System.out.println("Arquivo criado com sucesso");
} catch (IOException e) {
    e.printStackTrace();
}
  • OutputStream é "saída" (manda dados para algum lugar) e InputStream é "entrada" (lê). Os streams trabalham em baixo nível, com bytes (dados binários), ao contrário de Reader/Writer, que trabalham com caracteres.
  • Files.newOutputStream(path) cria o arquivo e o OutputStream. O ZipOutputStream embrulha esse stream (encadeamento de novo) e compacta o que passa por ele.
  • Cada arquivo tem 3 etapas: new ZipEntry(nome) → putNextEntry → escrever o conteúdo (Files.copy(file, zipStream)) → closeEntry.
  • Sem o Files.copy, o zip sai com os arquivos vazios: você criou o "esqueleto" das entradas, mas não mandou o conteúdo. Foi o que o William mostrou antes de completar.
  • Os dois recursos (o zip e o DirectoryStream) ficam no mesmo try-with-resources.
  • Programe e teste em pedaços: primeiro ele só imprimiu os arquivos encontrados, depois zipou. Com cerca de 10 linhas o conteúdo de um diretório vira um zip. Subpastas e senha exigem mais trabalho.

Atenção

  • SimpleFileVisitor é classe: sobrescreva só o que precisa. Todo método retorna um FileVisitResult.
  • file.getFileName().toString().endsWith(".java"): o endsWith de Path (sem toString) compara elementos do caminho, não o texto.
  • No glob, * fica num nível e ** atravessa pastas. matches compara o caminho inteiro.
  • Zip: putNextEntry + conteúdo + closeEntry. Extra: se houver subpastas no diretório, o Files.copy(subpasta, zipStream) falha. Filtre com Files.isRegularFile(file) ou use o visitor.
  • Extra: Files.walk(path) e Files.find(path, profundidade, filtro) fazem o mesmo passeio com Streams (aulas 203+), e costumam ser mais curtos que o visitor.
  • Extra: o nome do ZipEntry pode ter pastas ("docs/a.txt"), e é assim que se preserva a estrutura. Para descompactar existe o ZipInputStream (ou FileSystems.newFileSystem(zip)).

Paralelo com PHP

  • Percorrer a árvore: new RecursiveIteratorIterator(new RecursiveDirectoryIterator($dir)) ≈ Files.walkFileTree/Files.walk. O modo SELF_FIRST/CHILD_FIRST lembra o preVisitDirectory/postVisitDirectory. No Laravel: File::allFiles($dir) ou Storage::allFiles(). O Symfony tem o Finder (->in($dir)->name('*Test*.php')), que é o "visitor + PathMatcher" dele.
  • Glob: glob('*.txt') e fnmatch('*.{txt,java}', $nome). A função glob do PHP só aceita {a,b} com a flag GLOB_BRACE e não tem ** nativo (use o iterador recursivo).
  • Zip: $zip = new ZipArchive; $zip->open('arquivo.zip', ZipArchive::CREATE); $zip->addFile($caminho, $nomeNoZip); $zip->close();. O addFile faz as três etapas do Java (entrada, conteúdo, fechar) de uma vez.
  • Streams de bytes: o fopen/fwrite em modo 'wb'/'rb' do PHP ≈ OutputStream/InputStream. O PHP não separa "caracteres" de "bytes" como o Java faz com Reader/Writer × Stream.

package academy.devdojo.maratonajava.javacore.Wnio.test;

import java.io.IOException;
import java.nio.file.*;
import java.nio.file.attribute.BasicFileAttributes;
import java.util.zip.ZipEntry;
import java.util.zip.ZipOutputStream;

class ImprimeArvore extends SimpleFileVisitor<Path> {
    private int nivel = 0;

    @Override
    public FileVisitResult preVisitDirectory(Path dir, BasicFileAttributes attrs) {
        System.out.println("  ".repeat(nivel) + "[" + dir.getFileName() + "]");
        nivel++;
        return FileVisitResult.CONTINUE;
    }

    @Override
    public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
        System.out.println("  ".repeat(nivel) + file.getFileName() + " (" + attrs.size() + " bytes)");
        return FileVisitResult.CONTINUE;
    }

    @Override
    public FileVisitResult postVisitDirectory(Path dir, IOException exc) {
        nivel--;
        return FileVisitResult.CONTINUE;
    }
}

public class VisitorZipTest01 {
    static void matches(Path path, String glob) {
        PathMatcher matcher = FileSystems.getDefault().getPathMatcher(glob);
        System.out.println(glob + ": " + matcher.matches(path));
    }

    public static void main(String[] args) throws IOException {
        Files.walkFileTree(Paths.get("lab-visit"), new ImprimeArvore());

        Path p1 = Paths.get("pasta/subpasta/file.bkp");
        Path p3 = Paths.get("pasta/subpasta/file.java");
        matches(p1, "glob:*.bkp");                 // ?
        matches(p1, "glob:**/*.bkp");              // ?
        matches(p3, "glob:**/*.???");              // ?
        matches(p3, "glob:**/file.????");          // ?
        matches(p3, "glob:**/*.{bkp,txt,java}");   // ?

        PathMatcher testes = FileSystems.getDefault().getPathMatcher("glob:**/*Test*.{java,class}");
        Files.walkFileTree(Paths.get("lab-visit"), new SimpleFileVisitor<Path>() {   // classe anônima (aula 191)
            @Override
            public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
                if (testes.matches(file)) System.out.println("teste: " + file.getFileName());
                return FileVisitResult.CONTINUE;
            }
        });

        Path zip = Paths.get("lab-visit/arquivo.zip");
        try (ZipOutputStream zipStream = new ZipOutputStream(Files.newOutputStream(zip));
             DirectoryStream<Path> ds = Files.newDirectoryStream(Paths.get("lab-visit/subpasta1/subsubpasta1"))) {
            for (Path file : ds) {
                zipStream.putNextEntry(new ZipEntry(file.getFileName().toString()));
                Files.copy(file, zipStream);
                zipStream.closeEntry();
            }
        }
        System.out.println("Arquivo criado com sucesso");
    }
}
EOF

Glossário

  • walkFileTree: percorre recursivamente uma árvore de diretórios chamando um FileVisitor.
  • SimpleFileVisitor: implementação base de FileVisitor; você sobrescreve só o que precisa.
  • FileVisitResult: enum que diz ao Java como continuar (CONTINUE, TERMINATE, SKIP_SUBTREE, SKIP_SIBLINGS).
  • Glob: padrão de nome de arquivo com *, **, ? e {a,b}.
  • PathMatcher: objeto que testa se um Path casa com um glob ou regex.
  • Stream (IO): fluxo de bytes; InputStream lê, OutputStream escreve. Não confundir com a Stream API (aulas 203+).
  • ZipEntry: uma entrada (arquivo) dentro do zip.
  • Irmãos (siblings): itens no mesmo nível do diretório.
