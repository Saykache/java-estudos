Resumo

A aula 137 fecha as classes de texto: tokens são os pedaços que sobram quando você quebra um texto pelos delimitadores, e o Scanner ainda converte cada pedaço para o tipo certo. Depois começa o IO (entrada e saída), "um dos assuntos mais legais, porque você vê o resultado quase de forma física". O pacote java.io tem uma classe para cada propósito, e elas são encadeadas:

File            → representa o arquivo/diretório (criar, apagar, renomear, consultar)
FileWriter      → escreve caracteres no arquivo (baixo nível)
FileReader      → lê caracteres do arquivo (baixo nível)
BufferedWriter  → embrulha um Writer e escreve via buffer em memória (mais rápido)
BufferedReader  → embrulha um Reader e lê linha a linha via buffer

new BufferedWriter(new FileWriter(new File("file.txt"), true))   ← encadeamento

137 · Tokens, delimitadores e Scanner

String texto = "Levi, Eren, Mikasa, true, 200";
String[] nomes = texto.split(",");          // delimitador: , → tokens: "Levi", " Eren", ...
for (String nome : nomes) {
    System.out.println(nome.trim());        // todos são String
}

String texto2 = "Levi,Eren,Mikasa,true,200";
Scanner scanner = new Scanner(texto2);      // Scanner lendo uma String (não o teclado)
scanner.useDelimiter(",");                  // o padrão é o espaço em branco
while (scanner.hasNext()) {                 // existe um próximo token?
    if (scanner.hasNextInt()) {
        int i = scanner.nextInt();
        System.out.println("Int " + i);
    } else if (scanner.hasNextBoolean()) {
        boolean b = scanner.nextBoolean();
        System.out.println("Boolean " + b);
    } else {
        System.out.println(scanner.next());
    }
}
// Levi · Eren · Mikasa · Boolean true · Int 200
  • Delimitador é o separador (a vírgula). Token é o resultado da quebra (os nomes). O delimitador é uma regex: pode ser " ", "\\d"...
  • split sempre devolve String. Para ter true como boolean e 200 como int, use o Scanner, a mesma classe de ler o teclado (aulas 68–69), aqui lendo uma String.
  • O Scanner funciona como dois ponteiros: hasNext...() espia se existe o próximo (e de que tipo), e next...() anda e devolve o valor.
  • hasNextInt/nextInt, hasNextBoolean/nextBoolean, hasNextDouble... Com eles você trata cada token pelo tipo.

138 · File

File file = new File("file.txt");     // só um objeto: NÃO cria nada no disco
try {
    boolean isCreated = file.createNewFile();                       // agora cria (false se já existia)
    System.out.println("Created " + isCreated);
    System.out.println("path " + file.getPath());                   // file.txt
    System.out.println("path absolute " + file.getAbsolutePath());  // /home/.../file.txt
    System.out.println("is directory " + file.isDirectory());       // false
    System.out.println("is file " + file.isFile());                 // true
    System.out.println("is hidden " + file.isHidden());             // false
    System.out.println("last modified " + Instant.ofEpochMilli(file.lastModified())
            .atZone(ZoneId.systemDefault()));                       // long de ms → data legível
    if (file.exists()) {
        System.out.println("Deleted " + file.delete());             // true
    }
} catch (IOException exception) {                                   // createNewFile lança IOException (checked)
    exception.printStackTrace();
}
  • Só o nome ("file.txt") cria o arquivo onde o programa roda (a raiz do projeto no IntelliJ). Um caminho absoluto no Windows precisa de \\ (a barra é escape).
  • new File(...) não toca no disco. Quem cria é createNewFile(), que não sobrescreve: se o arquivo existe, devolve false.
  • delete() num arquivo inexistente devolve false, sem exceção. A boa prática é checar exists() antes.
  • getPath() devolve o caminho como foi passado, e getAbsolutePath() o caminho completo. Existem ainda isDirectory, isFile, isHidden, canRead, canWrite...
  • lastModified() devolve os milissegundos desde 1970 (aula 112). O jeito moderno de ler é Instant.ofEpochMilli(...).atZone(ZoneId.systemDefault()) (aulas 122 e 128).

139 · FileWriter

File file = new File("file.txt");
try (FileWriter fw = new FileWriter(file, true)) {    // true = append (acrescenta no fim)
    fw.write("O DevDojo é lindo, é o melhor curso do brasillllllll\nContinuando a cantoria na próxima linha\n");
    fw.flush();                                       // descarrega o buffer antes de fechar
} catch (IOException ex) {
    ex.printStackTrace();
}
  • O construtor aceita o nome ou um File. O William passa o File para mostrar o encadeamento. Se o arquivo não existe, o FileWriter cria.
  • Recurso do sistema operacional precisa ser fechado, e o try-with-resources (aula 103) fecha sozinho. O FileWriter é Closeable.
  • flush(): o SO usa um buffer, como a barrinha de carregamento do YouTube. Antes de fechar, o flush "cospe" o que ficou no buffer para o arquivo.
  • Sobrescrever × acrescentar: new FileWriter(file) apaga o conteúdo e escreve de novo. new FileWriter(file, true) acrescenta no fim (append).
  • O \n quebra a linha, mas não é garantido em todo sistema operacional (o Windows usa \r\n). O BufferedWriter resolve isso na aula 141.

140 · FileReader

try (FileReader fr = new FileReader(file)) {
    // Opção 1: ler num array
    // char[] in = new char[1000];
    // int size = fr.read(in);          // devolve QUANTOS caracteres leu
    // for (char c : in) System.out.print(c);

    // Opção 2: caractere por caractere até o fim
    int i;
    while ((i = fr.read()) != -1) {     // read() devolve o código do caractere; -1 = fim do arquivo
        System.out.print((char) i);     // cast int → char
    }
} catch (IOException e) {
    e.printStackTrace();
}
  • É a classe mais baixo nível de leitura. O construtor recebe o File ou o nome.
  • read() lê um caractere e devolve um int com o código dele (65 = 'A', 79 = 'O'). No fim do arquivo devolve -1.
  • O laço while ((i = fr.read()) != -1) lê, guarda e compara ao mesmo tempo. Sem o (char), só aparecem números.
  • read(char[]) preenche o array e devolve quantos caracteres leu. Com um array pequeno (30), você lê só o começo do arquivo.

141 · BufferedWriter

try (FileWriter fw = new FileWriter(file, true);
     BufferedWriter bw = new BufferedWriter(fw)) {     // encapsula o FileWriter
    bw.write("O DevDojo é lindo, é o melhor curso do brasillllllll");
    bw.newLine();                                      // quebra de linha do SO
    bw.flush();
} catch (IOException ex) {
    ex.printStackTrace();
}
  • FileWriter e FileReader são low level e não foram feitos pensando em desempenho. Para arquivos grandes, use os Buffered.
  • O BufferedWriter encapsula um Writer: acumula os dados num buffer em memória e grava no disco em blocos, o que é bem mais rápido que ir ao disco a cada escrita. O construtor aceita o tamanho do buffer (new BufferedWriter(fw, 2048)), mas o padrão costuma bastar.
  • newLine() usa o separador de linha do sistema operacional (System.lineSeparator()): \n no Linux e no Mac, \r\n no Windows.
  • Continua precisando de flush() e de ser fechado (try-with-resources).
  • Dica do William: o nome da variável acompanha a classe (bw para BufferedWriter, br para BufferedReader). O plugin Rainbow Brackets colore parênteses aninhados.

142 · BufferedReader

try (FileReader fr = new FileReader(file);
     BufferedReader br = new BufferedReader(fr)) {
    String linha;
    while ((linha = br.readLine()) != null) {   // lê uma LINHA inteira; fim do arquivo = null
        System.out.println(linha);
    }
} catch (IOException e) {
    e.printStackTrace();
}
  • Mesmo padrão: o BufferedReader encapsula o FileReader.
  • readLine() lê a linha inteira, sem o \n, bem mais eficiente que caractere por caractere. No fim devolve null (e não -1).
  • O William resume assim: mais classes encadeadas dão um pouco mais de código, mas cada classe tem um propósito (coesão, aulas 39–43), e isso deixa o código mais fácil de manter.

143 · File para diretórios

File fileDiretorio = new File("pasta");
boolean isDiretorioCreated = fileDiretorio.mkdir();               // cria o diretório (false se já existe)
File fileArquivoDiretorio = new File(fileDiretorio, "arquivo.txt"); // (pai, nome) → pasta/arquivo.txt
boolean isFileCreated = fileArquivoDiretorio.createNewFile();

File fileRenamed = new File(fileDiretorio, "arquivo_renomeado.txt");
boolean isRenamed = fileArquivoDiretorio.renameTo(fileRenamed);   // renomeia (recebe um File!)

File diretorioRenamed = new File("pasta2");
boolean isDiretorioRenomeado = fileDiretorio.renameTo(diretorioRenamed);
  • O mesmo File representa arquivo ou diretório: depende do método chamado. mkdir() cria o diretório (o nome vem do Unix).
  • Arquivo dentro do diretório: dá para passar o caminho completo, mas é melhor o construtor new File(diretorio, "arquivo.txt"). Com só new File("arquivo.txt"), ele vai para a raiz do projeto.
  • renameTo(File destino) recebe um File, não uma String. O destino define nome e lugar: new File("arquivo_renomeado.txt") tira o arquivo da pasta (renomear é mover). Para manter na pasta, crie o destino com o mesmo pai.
  • Todos devolvem boolean e não lançam exceção quando não conseguem. Rodando de novo: mkdir dá false (a pasta existe), e renameTo dá false se o destino já existe. Use o debug passo a passo para acompanhar.

Atenção

  • new File() não cria nada, mas new FileWriter() cria o arquivo (e apaga o conteúdo, se não for append).
  • Fim do arquivo: FileReader.read() → -1 · BufferedReader.readLine() → null.
  • Sempre feche (try-with-resources). Ao escrever sem fechar nem dar flush, parte do texto pode não chegar ao arquivo.
  • Extra: fechar o de fora fecha o de dentro. bw.close() já fecha o FileWriter. Declarar os dois no try( ) (como na aula) também funciona.
  • Extra: encoding. FileReader/FileWriter usam o charset padrão da JVM (UTF-8 a partir do Java 18). Em versões antigas no Windows, os acentos podiam quebrar. Seja explícito: new FileWriter(file, StandardCharsets.UTF_8, true) (Java 11+).
  • Extra: mkdirs() cria as pastas intermediárias (a/b/c). listFiles() lista o conteúdo do diretório. delete() num diretório não vazio devolve false.
  • Extra: o NIO (Path/Files, aulas 144+) é a API mais nova e mais prática: Files.readAllLines(path) e Files.writeString(path, texto).

Paralelo com PHP

  • Tokens: split(",") ≈ explode(',', $s) (separador fixo) ou preg_split (regex). O PHP não tem um Scanner tipado: você converte à mão ((int), filter_var), ou usa str_getcsv para CSV.
  • File ↔ funções do PHP:
    • exists ≈ file_exists, isDirectory/isFile ≈ is_dir/is_file.
    • lastModified ≈ filemtime (em segundos, não ms).
    • delete ≈ unlink, mkdir ≈ mkdir, renameTo ≈ rename, getAbsolutePath ≈ realpath.
    • createNewFile ≈ touch (que, diferente do Java, não falha se o arquivo existe).
  • Escrever: new FileWriter(file, true) ≈ file_put_contents($f, $s, FILE_APPEND). newLine() ≈ PHP_EOL.
  • Ler linha a linha: while ((linha = br.readLine()) != null) ≈ while (($linha = fgets($h)) !== false) (no PHP o fim é false, e a linha vem com o \n). Ler tudo: file_get_contents ≈ Files.readString, e file() ≈ Files.readAllLines.
  • Fechar: no PHP o fclose costuma ficar implícito no fim do script. Em Java, um servidor roda por meses, então vazar recurso derruba a aplicação. Daí o try-with-resources.
  • Laravel: Storage::put, append, get, exists, delete, makeDirectory, move. É uma camada acima, como o NIO.

Glossário

  • Token: cada pedaço resultante da quebra de um texto.
  • Delimitador: o separador (regex) usado para quebrar o texto.
  • IO (entrada e saída): ler e escrever dados fora do programa (arquivos, rede, console).
  • Buffer: área de memória que acumula dados antes de gravar ou depois de ler, para reduzir o acesso ao disco.
  • flush: forçar a gravação do que está no buffer.
  • Append: acrescentar no fim do arquivo em vez de sobrescrever.
  • Encadeamento (decorator): uma classe embrulha a outra para acrescentar comportamento (BufferedReader(FileReader(File))).
  • Separador de linha: \n (Linux/Mac) ou \r\n (Windows); newLine() e System.lineSeparator() escolhem o certo.
  • Caminho relativo / absoluto: a partir de onde o programa roda / a partir da raiz do sistema.
