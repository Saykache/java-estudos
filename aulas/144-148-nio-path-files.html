Resumo

O pacote java.nio.file (Java 7, "NIO.2") trouxe métodos mais efetivos para arquivos e diretórios, e deve substituir o File com o tempo. A funcionalidade do File foi dividida em três:

Path   (interface)  → o caminho em si (substitui o objeto File); implementação depende do SO
Paths  (classe)     → fábrica: Paths.get(...) devolve um Path
Files  (classe final, métodos static) → as operações: criar, copiar, apagar, existe?...
       (ex-métodos do File, agora como "caixa utilitária")

File ↔ Path:  file.toPath()  ·  path.toFile()      (interoperabilidade com código legado)

144 · Path e Paths.get

Path p1 = Paths.get("C:\\Users\\William\\Documents\\devdojo\\maratona-java\\file.txt");
Path p2 = Paths.get("C:\\Users\\William\\Documents\\devdojo\\maratona-java", "file.txt");
Path p3 = Paths.get("C:", "Users\\William\\Documents\\devdojo\\maratona-java", "file.txt");
Path p4 = Paths.get("C:", "Users", "William", "Documents", "devdojo", "maratona-java", "file.txt");
System.out.println(p1.getFileName());   // file.txt (nos quatro casos)
  • Path é uma interface. Quem cria a implementação certa para o sistema operacional é Paths.get(...).
  • Paths.get recebe varargs (aulas 52–53): o caminho inteiro de uma vez ou em pedaços. Ele monta o caminho com o separador do SO.
  • getFileName() devolve só o último elemento (file.txt). Também existem getParent(), getRoot() e getNameCount().
  • No Windows a barra invertida precisa de escape (\\). No Linux e no WSL: Paths.get("/home/marcos/file.txt").

145 · Files: criar diretórios, arquivos e copiar

Path pastaPath = Paths.get("pasta");                  // relativo: onde o programa roda
if (Files.notExists(pastaPath)) {
    Path pastaDirectory = Files.createDirectory(pastaPath);   // já existe → FileAlreadyExistsException
}
Path subPastaPath = Paths.get("pasta/subpasta/subsubpasta");
Path subPastaDirectory = Files.createDirectories(subPastaPath);   // cria os pais; não reclama se existir
Path filePath = Paths.get(subPastaPath.toString(), "file.txt");

if (Files.notExists(filePath)) {
    Path filePathCreated = Files.createFile(filePath);            // já existe → exceção
}

Path source = filePath;
Path target = Paths.get(filePath.getParent().toString(), "file_renamed.txt");   // mesma pasta
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);   // sem a opção → exceção se existir
  • Diferença de comportamento em relação ao File: os métodos de Files devolvem o Path criado, e não um boolean. Quando algo dá errado, lançam exceção (IOException e filhas, checked). O File só devolvia false.
  • Por isso a programação defensiva: Files.exists/Files.notExists antes de criar.
  • createDirectory cria um nível e lança exceção se o pai não existir. createDirectories cria toda a árvore e não lança exceção se ela já existir (é o mkdirs do NIO).
  • createFile(path) cria o arquivo e também lança exceção se ele já existir.
  • Files.copy(origem, destino, opções): o destino é um Path completo, com nome. O William errou ao montar o destino a partir do caminho do arquivo (.../file.txt/file_renamed.txt) e corrigiu com getParent(). Com StandardCopyOption.REPLACE_EXISTING, o destino é sobrescrito. Sem a opção, dá exceção se ele já existir.

146 · normalize: tirar . e ..

String diretorioProjeto = "home/william/dev";
String arquivoTxt = "../../arquivo.txt";            // "volta dois diretórios"
Path path1 = Paths.get(diretorioProjeto, arquivoTxt);
System.out.println(path1);               // home/william/dev/../../arquivo.txt
System.out.println(path1.normalize());   // home/arquivo.txt

Path path2 = Paths.get("/home/./william/./dev/");
System.out.println(path2);               // /home/./william/./dev
System.out.println(path2.normalize());   // /home/william/dev
  • No terminal: .. = diretório pai (cd ..) e . = diretório atual (./arquivo.txt). O William mostra isso no Ubuntu com cd, pwd e o vim.
  • Um caminho montado a partir de pedaços (de um script ou de uma configuração) pode vir cheio de .. e .. Ele funciona, mas é confuso. normalize() remove essas partes "redundantes" e devolve o caminho limpo.
  • normalize é só manipulação de texto: não verifica se o arquivo existe (para isso existe Files.exists).

147 · resolve: juntar caminhos

Path dir = Paths.get("home/william");
Path arquivo = Paths.get("dev/arquivo.txt");
System.out.println(dir.resolve(arquivo));       // home/william/dev/arquivo.txt

Path absoluto = Paths.get("/home/william");     // começa com / → absoluto (a partir da raiz)
Path relativo = Paths.get("dev");               // sem / → relativo (a partir de onde o programa roda)
Path file = Paths.get("file.txt");
System.out.println("1 " + absoluto.resolve(relativo));   // 1 /home/william/dev
System.out.println("2 " + absoluto.resolve(file));       // 2 /home/william/file.txt
System.out.println("3 " + relativo.resolve(absoluto));   // 3 /home/william       ← absoluto "vence"
System.out.println("4 " + relativo.resolve(file));       // 4 dev/file.txt
System.out.println("5 " + file.resolve(absoluto));       // 5 /home/william
System.out.println("6 " + file.resolve(relativo));       // 6 file.txt/dev        ← não é inteligente!
  • Absoluto × relativo: com / no começo, o caminho parte da raiz. Sem ela, parte do diretório atual. No terminal: cd home/william falha dentro de /home, e cd /home/william funciona de qualquer lugar.
  • a.resolve(b) junta b ao final de a. Regras:
    • se b é absoluto, devolve o próprio b (casos 3 e 5);
    • se b é relativo, cola no fim de a (1, 2, 4).
  • O resolve não é inteligente: ele não sabe que file.txt é um arquivo e cola dev depois dele (caso 6). Quem garante que a combinação faz sentido é você.
  • Na prática, o William costuma já ter o caminho inteiro, mas é bom conhecer as ferramentas.

148 · relativize: o caminho de A até B

Path dir = Paths.get("/home/william");
Path clazz = Paths.get("/home/william/devdojofoda/OlaMundo.java");
System.out.println(dir.relativize(clazz));      // devdojofoda/OlaMundo.java

Path absoluto1 = Paths.get("/home/william");
Path absoluto2 = Paths.get("/usr/local");
Path absoluto3 = Paths.get("/home/william/devdojofoda/OlaMundo.java");
Path relativo1 = Paths.get("temp");
Path relativo2 = Paths.get("temp/temp.2021921");
System.out.println("1 " + absoluto1.relativize(absoluto3));   // 1 devdojofoda/OlaMundo.java
System.out.println("2 " + absoluto3.relativize(absoluto1));   // 2 ../..
System.out.println("3 " + absoluto1.relativize(absoluto2));   // 3 ../../usr/local
System.out.println("4 " + relativo1.relativize(relativo2));   // 4 temp.2021921
System.out.println("5 " + absoluto1.relativize(relativo1));   // IllegalArgumentException
  • a.relativize(b) responde: estando em a, qual caminho leva até b? É o inverso do resolve: a.resolve(a.relativize(b)) volta a b.
  • Para subir, ele usa ... De /home/william até /usr/local: volta dois níveis (até a raiz) e desce para usr/local (cd ../../usr/local no terminal).
  • Os dois precisam ser do mesmo tipo: absoluto com absoluto, ou relativo com relativo. Misturar lança IllegalArgumentException, porque o Java não sabe onde o relativo está.

Atenção

  • Files lança exceção onde o File devolvia false: createDirectory, createFile e copy (sem REPLACE_EXISTING) lançam FileAlreadyExistsException. Um pai inexistente dá NoSuchFileException.
  • Files.exists e Files.notExists não são opostos exatos: sem permissão para verificar, os dois dão false (extra).
  • normalize, resolve e relativize só mexem no texto do caminho: não acessam o disco nem verificam se algo existe.
  • resolve com absoluto devolve o absoluto. relativize exige os dois do mesmo tipo.
  • Extra: prefira resolve a concatenar Strings: subPastaPath.resolve("file.txt") em vez de Paths.get(subPastaPath.toString(), "file.txt"). E filePath.resolveSibling("file_renamed.txt") troca só o nome, na mesma pasta.
  • Extra: Path.of(...) (Java 11+) é o substituto recomendado de Paths.get(...).
  • Extra: o Files também lê e escreve: Files.writeString(path, texto), Files.readString(path), Files.readAllLines(path), Files.move, Files.delete/deleteIfExists. Path é imutável, então os métodos devolvem um novo.

Paralelo com PHP

  • Estilo: o PHP usa funções soltas com string (mkdir, copy, file_exists), mais perto do Files (métodos estáticos) do que do File. O que o Java acrescenta é o tipo Path no lugar da string.
  • Equivalências:
    • Files.createDirectories ≈ mkdir($dir, 0777, true) (o true é o "recursivo").
    • Files.createFile ≈ touch, e Files.copy(..., REPLACE_EXISTING) ≈ copy(), que no PHP sobrescreve por padrão.
    • Files.exists ≈ file_exists, getFileName ≈ basename, getParent ≈ dirname.
  • Erros: as funções do PHP devolvem false e emitem um warning, como o File antigo. O Files lança exceção. No Laravel, o Storage/File facade tem makeDirectory($path, recursive: true), copy, move e exists.
  • normalize: o realpath() do PHP também resolve . e .., mas acessa o disco (devolve false se o arquivo não existe). O normalize do Java só mexe no texto. Em Java, o equivalente ao realpath é path.toRealPath() (extra).
  • resolve/relativize: no PHP você concatena com DIRECTORY_SEPARATOR ou usa um pacote como o symfony/filesystem (Path::join, makeRelative). O Java traz isso pronto.

Glossário

  • NIO.2: a API java.nio.file (Java 7) para caminhos e arquivos.
  • Path: interface que representa um caminho; imutável.
  • Paths: classe fábrica de Path (Paths.get).
  • Files: classe final com métodos estáticos que operam sobre Paths.
  • Caminho absoluto: começa na raiz (/); vale de qualquer lugar.
  • Caminho relativo: parte do diretório atual.
  • . / ..: diretório atual / diretório pai.
  • Normalizar: remover . e .. redundantes do caminho.
  • Resolver: juntar um caminho a outro (a.resolve(b)).
  • Relativizar: calcular o caminho que leva de a até b.
