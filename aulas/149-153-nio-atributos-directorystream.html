Resumo

Arquivos têm atributos: datas de criação, modificação e acesso, oculto, somente leitura, permissões... Cada sistema operacional tem os seus, e o NIO resolve isso com interfaces e polimorfismo: você pede o tipo de atributo e a JVM entrega a implementação do SO onde o programa roda. A regra de ouro das aulas:

XxxFileAttributes      → só LEITURA   (Files.readAttributes(path, Xxx.class))
XxxFileAttributeView   → ALTERAÇÃO    (Files.getFileAttributeView(path, XxxView.class))

BasicFileAttributes   (qualquer SO: datas, tamanho, é diretório?...)
 ├── DosFileAttributes   (Windows: hidden, readOnly, archive, system)
 └── PosixFileAttributes (Unix/Linux/Mac: dono, grupo, permissões rwx)

149 · Alterar a data de modificação: jeito antigo × NIO

LocalDateTime date = LocalDateTime.now().minusDays(10);

// Jeito antigo (java.io.File): milissegundos
File file = new File("pasta2/novo.txt");
boolean isCreated = file.createNewFile();
boolean isModified = file.setLastModified(date.toInstant(ZoneOffset.UTC).toEpochMilli());

// NIO: FileTime
Path path = Paths.get("pasta2/novo_path.txt");
Files.createFile(path);
FileTime fileTime = FileTime.from(date.toInstant(ZoneOffset.UTC));
Files.setLastModifiedTime(path, fileTime);
System.out.println(Files.isWritable(path));     // true
System.out.println(Files.isReadable(path));     // true
System.out.println(Files.isExecutable(path));   // true no Windows · false no Linux (sem x)
  • No Explorer, o arquivo mostra "modificado há 10 dias" mas "criado hoje". Moral do William: não confie cegamente na data de modificação, porque qualquer programa pode alterá-la.
  • O NIO usa o tipo FileTime, e não um long. Ele é criado com FileTime.from(instant) ou FileTime.fromMillis(ms).
  • Files.isWritable, isReadable, isExecutable e isHidden fazem as verificações rápidas.
  • Extra: date.toInstant(ZoneOffset.UTC) trata a hora local como se fosse UTC, o que dá uma diferença de 3h no Brasil. O correto é date.atZone(ZoneId.systemDefault()).toInstant() (aula 128).

150 · BasicFileAttributes e BasicFileAttributeView

Path path = Paths.get("pasta2/new.txt");
BasicFileAttributes basicFileAttributes = Files.readAttributes(path, BasicFileAttributes.class);  // leitura
FileTime creationTime = basicFileAttributes.creationTime();
FileTime lastModifiedTime = basicFileAttributes.lastModifiedTime();
FileTime lastAccessTime = basicFileAttributes.lastAccessTime();
System.out.println("creationTime " + creationTime);   // sempre em UTC: 2021-03-05T15:28:00.12Z

BasicFileAttributeView fileAttributeView = Files.getFileAttributeView(path, BasicFileAttributeView.class);  // alteração
FileTime newCreationTime = FileTime.fromMillis(System.currentTimeMillis());
fileAttributeView.setTimes(lastModifiedTime, newCreationTime, creationTime);
//                         (lastModified,     lastAccess,      creation) ← a ordem dos parâmetros!

lastAccessTime = fileAttributeView.readAttributes().lastAccessTime();   // relê pela View: valor novo
  • Files.readAttributes(path, BasicFileAttributes.class): você diz qual interface quer, e o Java devolve a implementação do SO (no Windows, um WindowsFileAttributes, que aparece no debug). Você programa para a interface (aula 94).
  • Além das datas, há size(), isDirectory(), isRegularFile() e isSymbolicLink().
  • Os FileTime são impressos em UTC (o Z no fim): o William vê 15:28 quando o relógio dele marca 16:28.
  • Os atributos lidos são um retrato do momento da leitura. Depois de alterar, leia de novo (view.readAttributes()), senão você vê os valores antigos.
  • setTimes(lastModifiedTime, lastAccessTime, createTime): cuidado com a ordem. Na aula, o newCreationTime entra na 2ª posição, então quem muda é o último acesso. Passe null no que não quiser alterar (extra).

151 · DosFileAttributes (Windows)

Path path = Paths.get("pasta/teste.txt");
if (Files.notExists(path)) Files.createFile(path);

// Jeito 1: Files.setAttribute com o nome em texto
Files.setAttribute(path, "dos:hidden", true);      // tem que ser exatamente "dos:hidden"
Files.setAttribute(path, "dos:readonly", true);    // tudo minúsculo; "dos:readOnly" dá exceção

// Jeito 2: as interfaces
DosFileAttributes dosFileAttributes = Files.readAttributes(path, DosFileAttributes.class);
System.out.println(dosFileAttributes.isHidden());      // false
System.out.println(dosFileAttributes.isReadOnly());    // false

DosFileAttributeView fileAttributeView = Files.getFileAttributeView(path, DosFileAttributeView.class);
fileAttributeView.setHidden(true);
fileAttributeView.setReadOnly(true);
System.out.println(fileAttributeView.readAttributes().isHidden());     // true
System.out.println(fileAttributeView.readAttributes().isReadOnly());   // true
  • São os atributos do Windows (herança do DOS): oculto, somente leitura, arquivo e sistema. No Explorer, o arquivo some (oculto) e ganha um cadeado (somente leitura).
  • Files.setAttribute(path, "view:nome", valor) funciona, mas é frágil: o nome é uma String e precisa ser escrito exatamente ("dos:readonly"). Um erro de digitação só aparece em execução.
  • O jeito tipado é DosFileAttributeView: setHidden, setReadOnly, setArchive, setSystem.
  • Um arquivo somente leitura não pode ser apagado nem alterado até você tirar o atributo (setReadOnly(false)).

152 · PosixFileAttributes (Linux / WSL)

$ ls -l        (o William usa o alias ll)
-rw-r--r-- 1 william william 6 mar  5 17:10 file.txt
│└┬┘└┬┘└┬┘
│ │  │  └── outros (others):  r--  só leitura
│ │  └───── grupo  (group):   r--  só leitura
│ └──────── dono   (owner):   rw-  leitura e escrita
└────────── tipo: - arquivo · d diretório
Path path = Paths.get("/home/william/dev/file.txt");
PosixFileAttributes posixFileAttributes = Files.readAttributes(path, PosixFileAttributes.class);
System.out.println(posixFileAttributes.permissions());
// [OWNER_WRITE, OWNER_READ, GROUP_READ, OTHERS_READ]

PosixFileAttributeView fileAttributeView = Files.getFileAttributeView(path, PosixFileAttributeView.class);
Set<PosixFilePermission> posixFilePermissions = PosixFilePermissions.fromString("rw-rw-rw-");
fileAttributeView.setPermissions(posixFilePermissions);
System.out.println(fileAttributeView.readAttributes().permissions());
// [OWNER_WRITE, OWNER_READ, GROUP_WRITE, GROUP_READ, OTHERS_WRITE, OTHERS_READ]  → ls -l: -rw-rw-rw-
  • POSIX é o padrão dos sistemas Unix (Linux, Mac). No Windows, pedir PosixFileAttributes lança UnsupportedOperationException. Por isso o William copiou a classe para o Ubuntu e rodou pelo terminal: sudo apt install default-jdk, depois javac e java, editando no vi.
  • As permissões do ls -l: 1 caractere de tipo e três trios rwx (read, write, execute): dono, grupo e outros. Um - significa "sem essa permissão".
  • permissions() devolve um Set<PosixFilePermission> (coleção sem repetição, aula 175+) de valores do enum PosixFilePermission (OWNER_READ, GROUP_WRITE...).
  • Você não precisa montar o Set à mão: PosixFilePermissions.fromString("rw-rw-rw-") converte a notação do ls. Repare: PosixFilePermissions (com s, a utilitária) × PosixFilePermission (o enum).
  • A PosixFileAttributeView também altera o dono e o grupo (setOwner, setGroup).

153 · DirectoryStream: listar um diretório

Path dir = Paths.get(".");                       // "." = diretório atual (onde o programa roda)
try (DirectoryStream<Path> stream = Files.newDirectoryStream(dir)) {   // é Closeable
    for (Path path : stream) {                   // itera como um array
        System.out.println(path.getFileName());
    }
} catch (IOException e) {
    e.printStackTrace();
}
// .idea · src · pasta · pasta2 · file.txt ... (inclui os ocultos; ordem não garantida)
  • É um dos jeitos mais simples de pegar todos os itens de um diretório, como o dir/ls: só o primeiro nível, sem entrar nas subpastas. Para percorrer a árvore inteira vem o SimpleFileVisitor (aulas 154–155).
  • DirectoryStream<Path> usa generics (aulas 183+): o <Path> diz que cada elemento é um Path.
  • É um recurso do SO (tem close()), então vai no try-with-resources.
  • O caminho absoluto do projeto não funcionou na aula (ele copiou só parte). O caminho "." resolve: o diretório atual.
  • Lista também os ocultos (.idea, .git), como o ls -a.

Atenção

  • Attributes = ler, AttributeView = alterar. Obtém-se com Files.readAttributes(path, X.class) e Files.getFileAttributeView(path, XView.class).
  • Depois de alterar, releia: o objeto de atributos é um retrato do momento em que foi lido.
  • Depende do SO: PosixFileAttributes no Windows → UnsupportedOperationException. getFileAttributeView devolve null se a view não for suportada (extra). Teste antes de usar.
  • A ordem do setTimes é (modificação, acesso, criação). No Linux, muitos sistemas de arquivos não guardam a data de criação, e o creationTime() pode devolver a de modificação (extra).
  • Extra: filtro no DirectoryStream. Files.newDirectoryStream(dir, "*.txt") lista só os .txt (glob, parente do PathMatcher das aulas 156–157). Files.list(dir) faz o mesmo com Streams (aulas 203+).

Paralelo com PHP

  • Datas: touch($f, $timestamp) ≈ Files.setLastModifiedTime. filemtime/fileatime/filectime ≈ lastModifiedTime/lastAccessTime/creationTime. Atenção: no Linux, o filectime é a data de mudança de status, não de criação. Todos devolvem segundos (Unix timestamp).
  • stat: stat($f) devolve tudo num array, parecido com readAttributes. No Java, cada SO tem sua interface.
  • Permissões: chmod($f, 0666) ≈ setPermissions(fromString("rw-rw-rw-")). fileperms ≈ permissions(). chown/chgrp ≈ setOwner/setGroup. É o mesmo mundo POSIX que você já usa em deploy (chmod -R 775 storage no Laravel).
  • Checagens: is_writable, is_readable, is_executable ≈ Files.isWritable...
  • Listar diretório: scandir($dir) ≈ newDirectoryStream (mas o scandir inclui . e .., que você filtra). glob('*.txt') ≈ o filtro com glob. new DirectoryIterator($dir) é o parente orientado a objetos. No Laravel: File::files($dir) e Storage::files().

package academy.devdojo.maratonajava.javacore.Wnio.test;

import java.io.IOException;
import java.nio.file.*;
import java.nio.file.attribute.*;
import java.time.LocalDateTime;
import java.time.ZoneId;

public class AtributosTest01 {
    public static void main(String[] args) throws IOException {
        Path pasta = Files.createDirectories(Paths.get("lab-attr"));
        Path path = pasta.resolve("novo.txt");
        if (Files.notExists(path)) Files.createFile(path);
        Files.createDirectories(pasta.resolve("subpasta"));
        if (Files.notExists(pasta.resolve("outro.txt"))) Files.createFile(pasta.resolve("outro.txt"));

        // 149 · data de modificação fixa (23/02/2021 12h em São Paulo)
        LocalDateTime date = LocalDateTime.of(2021, 2, 23, 12, 0);
        Files.setLastModifiedTime(path, FileTime.from(date.atZone(ZoneId.of("America/Sao_Paulo")).toInstant()));
        System.out.println(Files.isWritable(path) + " " + Files.isReadable(path) + " " + Files.isExecutable(path)); // ?

        // 150 · Basic
        BasicFileAttributes basic = Files.readAttributes(path, BasicFileAttributes.class);
        System.out.println("lastModifiedTime " + basic.lastModifiedTime());   // ? (em UTC)
        System.out.println("size " + basic.size() + " dir? " + basic.isDirectory());   // ?

        // 151 · Dos no Linux: a view existe?
        System.out.println("dos view: " + Files.getFileAttributeView(path, DosFileAttributeView.class));

        // 152 · Posix
        PosixFileAttributes posix = Files.readAttributes(path, PosixFileAttributes.class);
        System.out.println(PosixFilePermissions.toString(posix.permissions()));   // ?
        PosixFileAttributeView view = Files.getFileAttributeView(path, PosixFileAttributeView.class);
        view.setPermissions(PosixFilePermissions.fromString("rw-rw-rw-"));
        System.out.println(PosixFilePermissions.toString(posix.permissions()));   // ? (retrato antigo!)
        System.out.println(PosixFilePermissions.toString(view.readAttributes().permissions()));   // ?
        System.out.println("dono: " + view.readAttributes().owner().getName());

        // 153 · DirectoryStream
        try (DirectoryStream<Path> stream = Files.newDirectoryStream(pasta)) {
            for (Path p : stream) System.out.println("- " + p.getFileName());
        }
        try (DirectoryStream<Path> stream = Files.newDirectoryStream(pasta, "*.txt")) {   // extra: glob
            for (Path p : stream) System.out.println("txt: " + p.getFileName());
        }
    }
}
EOF

Glossário

  • Atributo de arquivo: metadado (datas, tamanho, oculto, permissões) que não faz parte do conteúdo.
  • FileTime: tipo do NIO para datas de arquivo.
  • XxxFileAttributes: interface de leitura dos atributos.
  • XxxFileAttributeView: interface que permite alterar os atributos.
  • DOS: atributos herdados do MS-DOS no Windows (hidden, readonly, archive, system).
  • POSIX: padrão dos sistemas Unix; permissões rwx para dono, grupo e outros.
  • rwx: read (ler), write (escrever), execute (executar/entrar no diretório).
  • DirectoryStream: iteração sobre os itens do primeiro nível de um diretório.
  • Glob: padrão curinga de nomes de arquivo (*.txt).
