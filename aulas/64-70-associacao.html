Resumo

Associação é o relacionamento entre objetos: um time tem jogadores, uma escola tem professores, um seminário acontece num local. Quem conhece banco de dados reconhece na hora, porque é o mesmo conceito dos relacionamentos entre tabelas, só que feito com atributos que guardam referências para outros objetos (ou arrays delas). No meio do bloco, as aulas 68–69 ensinam a ler dados do teclado com Scanner. Tudo fica no pacote novo javacore.Gassociacao.

64 · Array de objetos

Jogador jogador1 = new Jogador("Pelé");
Jogador jogador2 = new Jogador("Romário");
Jogador jogador3 = new Jogador("Cafu");

Jogador[] jogadores = {jogador1, jogador2, jogador3};   // ou new Jogador[3] e preencher

for (Jogador jogador : jogadores) {
    jogador.imprime();
}
jogadores ─▶ [ ref | ref | ref ]
               │     │     └──▶ [Cafu]    ◀── jogador3
               │     └────────▶ [Romário] ◀── jogador2
               └──────────────▶ [Pelé]    ◀── jogador1
  • Um array de objetos guarda referências, não cópias. jogadores[0] e jogador1 apontam para o mesmo objeto Pelé, que agora tem duas referências.
  • O foreach declara o tipo do objeto: for (Jogador jogador : jogadores). Com isso dá para chamar métodos em cada um.
  • Segundo o William, esse conceito é a base das coleções (listas e mapas), que vêm mais à frente.
  • Detalhe da aula: o pacote tinha sido criado com o nome errado. Shift+F6 renomeia e o IntelliJ corrige os import sozinho.

65 · Associação unidirecional: jogador → time

public class Jogador {
    private String nome;
    private Time time;          // o jogador conhece o time (um)

    public Jogador(String nome) { this.nome = nome; }   // time opcional: fica fora do construtor

    public void imprime() {
        System.out.println(this.nome);
        if (time != null) {                             // sem isso: NullPointerException
            System.out.println(time.getNome());
        }
    }
    // getters e setters...
}

Jogador jogador1 = new Jogador("Pelé");
Time time = new Time("Seleção Brasileira");
jogador1.setTime(time);         // É AQUI que a relação é criada
jogador1.imprime();
  • Os tipos de relação: um para um (jogador e personagem num jogo), um para muitos (um time tem vários jogadores), muitos para um (vários jogadores, um time) e muitos para muitos (estudante e cursos).
  • Unidirecional: só um lado conhece o outro. Aqui o Jogador tem um Time, mas o Time não sabe quais jogadores tem.
  • Obrigatório ou opcional se decide no construtor: se o jogador precisa de um time para existir, o time vai no construtor. Se ele pode se cadastrar e escolher depois, fica só o setter.
  • Criar os dois objetos não cria a relação. Ela só existe depois de jogador1.setTime(time).
  • Como o time é opcional, time.getNome() sem a checagem time != null lança NullPointerException quando o jogador ainda não tem time.

66 · Um lado com muitos: escola → professores

public class Escola {
    private String nome;
    private Professor[] professores;       // "muitos" = array

    public Escola(String nome) { this.nome = nome; }
    public Escola(String nome, Professor[] professores) {   // sobrecarga
        this.nome = nome;
        this.professores = professores;
    }

    public void imprime() {
        System.out.println(this.nome);
        if (professores == null) return;
        for (Professor professor : professores) {
            System.out.println(professor.getNome());
        }
    }
}

Professor professor1 = new Professor("Jiraiya Sensei");
Professor professor2 = new Professor("Kakashi");
Professor[] professores = {professor1, professor2};
Escola escola = new Escola("Konoha", professores);
  • Uma escola tem vários professores, e cada professor trabalha em uma escola. O relacionamento é unidirecional, da escola para os professores. O lado "muitos" vira um array.
  • A ordem de criação: comece pelos objetos que não dependem de ninguém (professor) e deixe por último os que os usam (escola).
  • Alt+Insert → Constructor gera o construtor sobrecarregado com os dois atributos (segure Shift e use as setas para selecionar vários).
  • Muitos para muitos seria a mesma ideia com array dos dois lados.

67 · Associação bidirecional: jogador ↔ time

public class Time {
    private String nome;
    private Jogador[] jogadores;   // agora o time também conhece os jogadores
    // construtores sobrecarregados, imprime com null check, get/set
}

Jogador jogador = new Jogador("Cafu");
Time time = new Time("Brasil");
jogador.setTime(time);                        // lado 1
Jogador[] jogadores = {jogador};
time.setJogadores(jogadores);                 // lado 2
jogador ──▶ [Cafu | time ─┐]
                          ▼
time ─────▶ [Brasil | jogadores ─┐]
                                 ▼
               [ ref ] ──▶ (o mesmo objeto Cafu)
  • Bidirecional: os dois lados guardam referência um para o outro. O jogador sabe seu time, e o time sabe seus jogadores.
  • Nada garante a integridade. A aula mostra o Pelé colocado no array do Brasil sem jogador2.setTime(time): o time diz que ele é jogador, mas o jogador não sabe que tem time. Num banco de dados, as chaves estrangeiras cuidam disso. Com objetos na memória, quem mantém os dois lados coerentes é você.
  • O conselho do William: desenhe as referências. "Se você é capaz de desenhar, é capaz de explicar. E se é capaz de explicar, entendeu."
  • No IntelliJ, Ctrl+Shift+↑/↓ move a linha atual para cima ou para baixo.

68 · Leitura de dados pelo teclado (Scanner)

import java.util.Scanner;

Scanner entrada = new Scanner(System.in);

System.out.println("Digite seu nome abaixo");
String nome = entrada.nextLine();          // a linha inteira
System.out.println("Digite sua idade");
int idade = entrada.nextInt();             // já converte para int
System.out.println("Digite M ou F para o seu sexo");
char sexo = entrada.next().charAt(0);      // Scanner não tem nextChar

System.out.println(nome + " " + idade + " " + sexo);
  • Scanner (do pacote java.util) lê o que é digitado. O System.in é a "entrada padrão", o teclado. Streams e System.in voltam mais à frente.
  • next() lê só a primeira palavra: "Olá mundo" vira "Olá". nextLine() lê a linha inteira.
  • Há um next para cada tipo (nextInt, nextDouble, nextBoolean, nextBigDecimal...), que já devolve o valor convertido. Digitar texto onde se espera número dá erro.
  • Para um char: next().charAt(0), o caractere da posição 0 da String. Digitando "masculino", fica só o 'm'.
  • Enquanto espera a digitação, o programa fica parado. O William avisa que não vai usar muito o teclado no curso: para testar, é mais rápido deixar os valores no código. Mas é ótimo para praticar e "mostrar para a família".

69 · Exercício: o "oráculo" que responde sim ou não

Scanner entrada = new Scanner(System.in);
System.out.println("Sou o grande oráculo. Digite sua pergunta e eu responderei SIM ou NÃO");
String pergunta = entrada.nextLine();
if (pergunta.charAt(0) == ' ') {           // char se compara com aspas simples
    System.out.println("SIM");
} else {
    System.out.println("NÃO");
}
  • A "pegadinha" para brincar com os amigos: se você começar a pergunta com um espaço, digitado rápido sem ninguém ver, a resposta é SIM. Sem o espaço, é NÃO.
  • charAt devolve um char, que se compara com ' ' (aspas simples). Com " " (String) não compila.

70 · Exercício: sistema de seminários

Cadastrar seminários, alunos, professores e o local de cada seminário. Um aluno pode estar em apenas um seminário. Um seminário pode ter nenhum ou vários alunos. Um professor pode ministrar vários seminários. Um seminário deve ter obrigatoriamente um local. Campos: Seminário (título), Aluno (nome, idade), Professor (nome, especialidade), Local (endereço).

Local           endereco
Aluno           nome, idade, Seminario seminario           (aluno → 1 seminário)
Seminario       titulo, Aluno[] alunos, Local local        (seminário → N alunos, 1 local)
Professor       nome, especialidade, Seminario[] seminarios (professor → N seminários)

Aluno ↔ Seminario: bidirecional · Professor → Seminario: unidirecional (é o que o requisito pede)
// Professor.imprime()
public void imprime() {
    System.out.println("Professor: " + this.nome);
    if (seminarios == null) return;
    System.out.println("----- Seminários cadastrados -----");
    for (Seminario seminario : seminarios) {
        System.out.println(seminario.getTitulo() + " — " + seminario.getLocal().getEndereco());
        if (seminario.getAlunos() == null || seminario.getAlunos().length == 0) {
            continue;   // sem alunos: pula SÓ este seminário (break pararia todos)
        }
        for (Aluno aluno : seminario.getAlunos()) {
            System.out.println("  " + aluno.getNome() + ", " + aluno.getIdade());
        }
    }
}
  • Comece pelas classes básicas, só com os atributos obrigatórios e seus construtores. Depois acrescente os relacionamentos, um requisito por vez.
  • O Professor já existia com um construtor. Para acrescentar especialidade sem quebrar quem já usava a classe, sobrecarregue o construtor.
  • Siga o requisito: o professor conhece os seminários, mas o seminário não precisa conhecer o professor. Poderia ser bidirecional, mas "provavelmente quem escreveu entende do negócio".
  • Ordem de cadastro no teste: primeiro o que não depende de nada (Local), depois Aluno e Professor, e por último o Seminario, que usa os outros. É como um sistema real, com "pré-cadastros" antes do principal.
  • null × vazio (o papel higiênico): um array null é não ter nem o rolo. Um array de tamanho 0 é ter o rolo vazio. O new Aluno[0] passou pelo == null, e por isso a checagem completa é == null || length == 0.
  • continue, não break: se um seminário não tem alunos, o laço precisa seguir para o próximo seminário.
  • Uma máxima citada: um método com mais de ~20 linhas provavelmente pode ser quebrado em métodos menores. Refatorar vem com a prática.

Atenção

  • Criar os objetos não os relaciona. A relação só existe depois de setTime, setJogadores etc.
  • Relação opcional exige null check antes de navegar (time.getNome(), seminario.getLocal().getEndereco()).
  • Extra: a armadilha do nextInt() + nextLine(). nextInt() lê o número e deixa o Enter no buffer. O nextLine() seguinte lê esse "resto de linha" vazio e parece que "pulou" a pergunta. Solução: chame um entrada.nextLine(); extra depois do nextInt(), ou leia tudo com nextLine() e converta (Integer.parseInt(...)).
  • Extra: digitar "abc" num nextInt() lança InputMismatchException, e uma pergunta vazia no oráculo faz o charAt(0) lançar StringIndexOutOfBoundsException. Tratamento de exceções vem nas aulas 95+.
  • Extra: um método que liga os dois lados evita a inconsistência da aula 67. Por exemplo, time.adicionaJogador(jogador), que coloca o jogador no time e chama jogador.setTime(this).
  • Extra: cuidado com impressão recursiva. Numa relação bidirecional, se Jogador.imprime() chamar time.imprime() e Time.imprime() chamar jogador.imprime(), um chama o outro sem parar até StackOverflowError. Imprima só os dados simples do outro lado (o nome).
  • Extra: array tem tamanho fixo, então "adicionar um jogador" exige criar outro array. É justamente o que as coleções (List) resolvem.

Paralelo com PHP

  • Eloquent, na mesma língua: Jogador com um atributo Time é o belongsTo. Time com Jogador[] é o hasMany. Array nos dois lados é o belongsToMany (com tabela pivot no banco).
  • A diferença de integridade: no Laravel a relação vive no banco (chave estrangeira), e $time->jogadores consulta o que está gravado, então os dois lados sempre batem. Em Java puro, sem banco, as referências vivem na memória, e nada sincroniza os dois lados sozinho (aula 67). Com JPA/Hibernate, mais à frente, a situação volta a parecer a do Eloquent.
  • Serializar relação bidirecional dá o mesmo problema nas duas linguagens: toArray()/JSON de um time que tem jogadores que têm o time entra em loop. O Laravel resolve com $hidden ou Resources, e o Java com @JsonIgnore e afins.
  • Ler do teclado: no PHP CLI é readline("Nome: ") ou fgets(STDIN). Num comando Artisan, $this->ask(). Em Java, Scanner. O nextInt() já converte, enquanto no PHP tudo chega como string.

    private Jogador[] jogadores = new Jogador[0];

    public Time(String nome) { this.nome = nome; }

    }

    public void imprime() {
        System.out.println("Time: " + nome);
        for (Jogador jogador : jogadores) System.out.println("  " + jogador.getNome());
    }

    public String getNome() { return nome; }
}

Glossário

  • Associação: relacionamento entre objetos, representado por atributos que referenciam outros objetos.
  • Cardinalidade: 1:1, 1:N, N:1, N:N, ou seja, quantos de um lado se relacionam com quantos do outro.
  • Unidirecional: só um dos lados tem a referência para o outro.
  • Bidirecional: os dois lados se referenciam. Manter a coerência é responsabilidade do código.
  • Integridade referencial: garantia de que as relações são coerentes. No banco, chaves estrangeiras. Na memória, o seu código.
  • Scanner: classe de java.util que lê dados de uma fonte, como o teclado (System.in).
  • next() / nextLine(): próxima palavra / linha inteira.
  • charAt(i): o caractere da posição i de uma String.
